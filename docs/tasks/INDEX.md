# 任务索引

每个任务是一个独立文件，执行者一次只读一个任务文件与它列出的源码，按 [FLASH_AGENT_PROMPT.md](../FLASH_AGENT_PROMPT.md) 执行，完成后停止。设计依据：[ADR-0005](../adr/0005-m2-data-architecture.md)、[ADR-0006](../adr/0006-first-playable-slice.md)。

## 状态说明

`未开始` → `进行中` → `待审查`（任务分支已推送/CI 通过，或维护者本地审查）→ `已合并`；或 `阻塞`（附阻塞报告链接）。**状态只由维护者更新**；执行者在报告里写结果，不改本表。

例外：M2 的 23 个任务在 2026-10-20 由执行 Agent 按维护者指令**核对代码与提交记录后**修正为 `已合并`（见下节「M2 状态核对」）。里程碑是否验收仍然只由维护者决定。

风险为「高」的任务需要维护者做架构审查：走 PR 时在 PR 上加 `arch-approved` 标签；用本地 Git 时在 `task/` 分支上本地提交并在报告中列出高风险点，由维护者审查后合并。**Agent 的每一次远程推送都必须先获得人类操作员当次批准**（AGENTS.md「分支、工作树与推送」）。执行者不得自己加标签或声称已完成审查。

## 编写新任务的模板

维护者为后续里程碑拆任务时，每个任务文件包含：风险、前置依赖、涉及模块、预计改动、特殊要求；目标；背景（只写执行者必须知道的事实与已定的决定）；必读文件；允许修改；禁止修改；实现要求（接口、字段、规则写到不需要再做设计决定的程度）；验收测试（逐条列出，关键计算给出输入输出示例与边界）；验收命令；完成定义；可能的阻塞。
