# 任务索引

每个任务是一个独立文件，执行者一次只读一个任务文件与它列出的源码，按 [FLASH_AGENT_PROMPT.md](../FLASH_AGENT_PROMPT.md) 执行，完成后停止。设计依据：[ADR-0005](../adr/0005-m2-data-architecture.md)。

## 状态说明

`未开始` → `进行中` → `待审查`（任务分支已推送/CI 通过，或维护者本地审查）→ `已合并`；或 `阻塞`（附阻塞报告链接）。**状态只由维护者更新**；执行者在报告里写结果，不改本表。只有前置依赖全部 `已合并` 的任务才能开始。

风险为「高」的任务需要维护者做架构审查：走 PR 时在 PR 上加 `arch-approved` 标签；用本地 Git 推送时先推 `task/` 分支并在报告中列出高风险点，由维护者本地审查后合并。执行者不得自己加标签或声称已完成审查。

## 第一个任务

**[M2-001 统计序列契约](M2-001.md)**：没有前置依赖；只新增一个 schema 文件与它的测试，`content-schema/src/index.ts` 加一行导出；schema 的全部字段与 8 条规则已在任务文件中逐条给出，执行者不需要做任何设计决定。成功标准是任务文件「验收测试」中的 5 组测试全部通过、`pnpm verify` 通过、没有改动范围外的文件。它解锁 DataRegistry（M2-006）与全部数据转换任务。

（M2-002 至 M2-005 同样没有依赖，可以与 M2-001 并行交给不同的执行者。）

## 编写新任务的模板

维护者为后续里程碑拆任务时，每个任务文件包含：风险、前置依赖、涉及模块、预计改动、特殊要求；目标；背景（只写执行者必须知道的事实与已定的决定）；必读文件；允许修改；禁止修改；实现要求（接口、字段、规则写到不需要再做设计决定的程度）；验收测试（逐条列出，关键计算给出输入输出示例与边界）；验收命令；完成定义；可能的阻塞。
