## 背景

维护者允许复用 1injp 的代码，但要求符合 MIT。原有流程（[REFERENCE_REUSE](../REFERENCE_REUSE.md) §8）要求在 `THIRD_PARTY_NOTICES.md` 登记，但该文件由 `pnpm notices` 生成并逐字比对，手写条目会让 `pnpm check:licenses` 失败；另外实测发现**构建产物里没有任何许可声明**——压缩器去掉了源码注释，`dist/` 里也没有声明文件，连 React、i18next、zod 等 npm 依赖的 MIT 声明都没有随产物分发。

## 实现

1. `third_party/ported-code.json`：移植登记表（上游仓库、40 位 commit、上游文件与行号及其 SHA-256、许可证、原版权行、许可证原文路径、本仓库文件、改动摘要、任务、访问日期）。
2. `third_party/1injp/LICENSE`：从 commit `5f19a0e7…` 逐字节复制的 MIT 原文（含 `Copyright (c) 2026 satoru.net`）。
3. `scripts/check-licenses.mjs`：检查登记完整；许可证在允许名单内；原文含原版权行；每个移植文件以 `/*!` 许可注释开头并写明原版权行、`SPDX-License-Identifier` 与登记 ID；仓库里任何带 SPDX 标记的源文件都必须已登记。`pnpm notices` 把登记表与许可证原文写进 `THIRD_PARTY_NOTICES.md`（npm 部分逐字节不变，只在末尾追加）。新增 13 项测试。
4. `apps/web/vite.config.ts`：构建时随产物输出 `LICENSE.txt` 与 `THIRD_PARTY_NOTICES.txt`；页脚「关于」增加中英链接。新增 E2E：产物中确实有这两个文件、内容含 React 与 1injp 的声明、页脚链接指向它们。
5. 第一处移植：`apps/web/src/game/year-pacing.ts`（1injp `app.js` 576—577、677、680—688、705—708、731 行）——1× 一年 48 秒与 1/2/4/16 倍速、每帧最多计 250 ms、年初先显示一条再按进度逐条揭示、日期按进度逐日推进。改写为纯函数，日期用规范日历并且不超过这一年的终点（权威时钟）。7 项测试（含 fast-check）。**尚未接入界面**，由 M4-017 接入。
6. `third_party/` 加入高风险路径（`check-guardrails.mjs` 与 `CODEOWNERS`），并加测试。

## 验收（实测）

- `pnpm verify`：58 个文件、469 项测试通过；`pnpm check:licenses`：10 个生产依赖与 1 处移植代码，NOTICES 已同步。
- `PW_CHANNEL=chrome pnpm test:e2e`：40 项通过（含新增的许可声明测试，桌面与手机）。
- 黄金指纹与基准工作量指纹不变（未改任何规则）。
