## 目标

实现收养、监护与育儿：收养有国家与年代的资格限制；孩子是独立的 Tier1 NPC；育儿消耗金钱与时间并影响关系；孩子长大后走自己的生命周期（已由 M3-011 提供）。**本任务不含生育**（生育在 M3-019，依赖 Q1/Q7）。

## 背景

- GDD §8.4：亲生、收养与抚养责任分离；收养与婚姻政策按历史日期与地区包适用；不把婚育当作单一成功指标。
- 收养法的年代差异（需核实来源）：中国大陆 1992 年《收养法》（此前也有收养实践）、日本 1947 年民法与 1987 年特别收养、韩国民法收养条款、俄罗斯 1995 年家庭法典、朝鲜资料有限。
- 金额：育儿支出走 M3-014 的家庭经济口径；本任务不得另造一套金额规则。
- 性别未决：不使用性别；育儿责任不按性别分配。

## 实现要求

1. **收养资格**：按（国家, 年份）决定最低收养年龄、是否允许单身收养、是否需要配偶同意、年龄差要求；不满足时选项不可用并给出原因。
2. **创建孩子**：收养成功时创建 Tier1 NPC（ID `char:<主角>:child-1` 递增），带出生日期（按收养时年龄推算）、出生地、健康与教育起点；建立 `adoptive-parent-child` 关系（`biological: false`、`legal: true`、`coResident: true`）；不得重抽既有事实。
3. **育儿**：年度育儿支出（食品、教育、医疗）进入家庭结算；孩子的教育路径使用 M3-012 的规则；孩子与主角的 `bonds` 随事件变化；孩子成年后独立（`coResident` 可变为 false）。
4. **监护**：配偶死亡或离婚后，孩子的监护关系保持；不得出现「孩子没有监护人」的未处理状态（至少一条 `adoptive-parent-child` 或 `parent-child` 有效）。
5. **独立性**：孩子有自己的生命事件（M3-011），主角不能替孩子做重大决定；玩家只能通过 M3-020 的干预机制影响。
6. **不重复**：育儿支出只在一处入账；同一孩子不会同时有两条有效收养关系。

## 验收测试

1. 资格：未达最低年龄或不允许单身收养时，选项 `eligible: false` 且原因正确；满足时成功并产生事实。
2. 关系与不变量：孩子有且仅有一条有效收养/亲子关系；孩子有账户、有生命周期事件；死者不能被收养。
3. 支出：一个孩子带来的年度支出可在结算事实里看到具体金额；没有孩子的角色不产生该项。
4. 成年独立：孩子到成年后 `coResident` 变为 false（或按规则保持），并有事实记录。
5. 确定性：同 seed 两次运行一致；快照往返一致。
6. 双语：新增事实全部有 zh/en 模板。
