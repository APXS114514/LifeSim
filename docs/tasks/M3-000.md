# M3-000：旧存档非破坏性保护（前置修复）

| 项       | 内容                                                                                                                  |
| -------- | --------------------------------------------------------------------------------------------------------------------- |
| 风险     | 低（只改 `apps/web` 的存档读取与提示；不改规则、数据、内核、公共契约）                                                |
| 前置依赖 | 无。**必须在 M3-001 之前完成**：M3-001 会把 `SYSTEMS_VERSION` 从 `0.1.0` 升到 `0.2.0`，旧存档会因版本不匹配而恢复失败 |
| 涉及模块 | `apps/web`                                                                                                            |
| 预计改动 | 修改 2 个文件，新增 1 个组件与 1 个单元测试；追加 1 组 Playwright 用例                                                |

## 目标

恢复失败（版本不兼容或数据损坏）时**绝不删除**玩家已有的存档：保留原始内容、给出明确提示、允许下载备份、允许玩家手动清除后再开新局。这是 M3-001 的前置保护，也是 Q9 的落地。

## 背景

- 现状：`apps/web/src/game/storage.ts` 的 `loadGame()` 捕获所有异常后调用 `clearGame()`，然后返回 `null`。只要 `SYSTEMS_VERSION` 或数据版本变化，旧存档就会在下一次打开页面时被静默删除。
- 内核在版本不匹配时抛出 `SimulationError`，`code === 'incompatible-snapshot'`（见 `packages/simulation-core/src/engine.ts:202-218`）；`parseGameSave` 对存档格式版本不匹配抛出 `Unsupported save version`。
- 维护者已确认 Q9：**非破坏性兼容策略**——旧存档不能恢复时保留原始内容，允许导出备份并提示不兼容；不要求在 M3 实现迁移。
- 本任务**不实现** IndexedDB、存档迁移、导入导出 UI、多局管理；这些属于 M4-001/002/003。

## 实现要求

### 1. `storage.ts` 的新接口

保持 localStorage 键名不变（E2E 与现有玩家数据依赖它）：

    export const SAVE_KEY = 'lifesim.save.v1';
    export const PRESERVED_KEY = 'lifesim.save.v1.preserved';

    export type SaveIssueReason = 'incompatible' | 'unreadable';

    export type SaveLoadResult =
      | { kind: 'none' }
      | { kind: 'loaded'; session: GameSession }
      | { kind: 'failed'; reason: SaveIssueReason; raw: string; detail: string };

    export function loadGame(): SaveLoadResult;
    /** 返回是否真的写入；有待处理的旧存档时拒绝覆盖并返回 false。 */
    export function saveGame(session: GameSession): boolean;
    /** 玩家明确选择清除时调用：主存档与保留副本一起删除。 */
    export function clearGame(): void;
    /** 浏览器下载原始存档备份；没有 DOM 时返回 false。 */
    export function downloadSaveBackup(raw: string): boolean;

### 2. 行为

1. **成功**：返回 `{ kind: 'loaded', session }`；不修改任何键。
2. **无存档**：主键为空时返回 `{ kind: 'none' }`；但若保留副本存在（例如主键被外部清掉），返回 `failed` 并带上该副本内容，避免留下无法处理的数据。
3. **失败**：
   - 把**原始字符串**写入 `PRESERVED_KEY`（写入失败也不影响主键保留）；
   - **不得删除或修改 `SAVE_KEY`**；
   - 返回 `{ kind: 'failed', reason, raw, detail }`，`detail` 只用于本地诊断，界面上不直接展示原始异常全文（避免把内部信息当玩家文案）。
4. **分类**：
   - `incompatible`：`parseGameSave` 的 `Unsupported save version`，或 `SimulationError` 且 `code === 'incompatible-snapshot'`；
   - `unreadable`：JSON 解析失败、schema 校验失败、其他恢复异常。
5. **防止覆盖**：`saveGame` 在 `PRESERVED_KEY` 存在时**不写入**并返回 `false`（多标签页或未处理旧存档时也不会覆盖）。成功写入返回 `true`；存储不可用或配额错误返回 `false`。
6. **清除**：`clearGame` 同时删除 `SAVE_KEY` 与 `PRESERVED_KEY`；只在玩家明确确认后调用。
7. **下载**：用 `Blob` + `URL.createObjectURL` 触发下载，文件名固定为 `lifesim-save-backup.json`；没有 `document`/`URL`/`Blob` 时返回 `false`。
8. **不写时间**：下载与保留逻辑不读取系统时间，文件名不含时间戳。

### 3. 界面（`App.tsx` + `SaveIssuePanel.tsx`）

1. 启动时调用一次 `loadGame()`；`failed` 时**阻塞**进入出生设置与游戏，先展示面板：
   - 标题（两种原因各一条文案）；
   - 说明「原始存档已保留，不会自动删除」；
   - 按钮：**下载原始存档**、**清除存档并开新局**（两步确认）、**重试读取**；
   - 语言切换按钮仍可用（面板文案跟随语言）。
2. 清除需要两步：第一次点击把按钮文案变为「再次点击以确认清除（不可恢复）」，第二次点击才调用 `clearGame()` 并进入出生设置。
3. 打开面板期间不得创建新会话，因此不会触发自动保存覆盖。
4. 成功恢复时保留现有「已恢复上次自动存档。」提示。
5. 面板使用 `role="alert"` 或同等级的可访问语义；按钮可键盘操作。

### 4. 文案（zh-Hans 与 en 同时提供）

至少包含：面板标题、两种原因说明、保留说明、下载、清除、确认清除、重试。占位符集合两语言一致（`locales.test.ts` 会检查）。

## 验收测试

### 单元（`storage.test.ts`，用内存 localStorage 夹具，注释写明是夹具）

1. 成功：创建会话 → `saveGame` 返回 true → `loadGame` 得到 `loaded`，事实一致。
2. 不兼容（格式版本）：主键写入 `{"version":999}` → `failed` 且 `reason === 'incompatible'`；主键原文未变；保留副本等于原文。
3. 不兼容（内核版本）：篡改真实快照的 `engineVersion` → `failed` 且 `incompatible`，主键与保留副本都在。
4. 损坏：主键写入 `'{not json'` → `unreadable`；主键未被删除。
5. 防覆盖：失败后调用 `saveGame` 返回 false，主键仍是原始损坏内容。
6. 清除：`clearGame` 后主键与保留副本都不存在；再次 `loadGame` 返回 `none`。
7. 仅保留副本：主键删除但保留副本存在时，`loadGame` 返回 `failed` 且 `raw` 是副本内容。
8. Node 环境：`downloadSaveBackup` 返回 `false`（不抛错）。

### E2E（追加到 `smoke.spec.ts`）

1. **旧版本存档被保留**：开一局 → 读取 localStorage → 把 `snapshot.engineVersion` 改成 `'0.0.0'` 写回 → 刷新页面 → 断言：
   - 存档问题面板可见；
   - `lifesim.save.v1` 与 `lifesim.save.v1.preserved` 都存在且内容相同；
   - 点击「下载原始存档」能收到文件（文件名 `lifesim-save-backup.json`）；
   - 两步确认清除后出现出生设置，两个键都被删除。
2. **损坏存档不被静默删除**：写入非 JSON 内容 → 刷新 → 面板显示「损坏/无法读取」文案 → 主键仍在。
