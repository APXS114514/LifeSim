| 项       | 内容                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 风险     | 高（数据登记 + 质量门禁脚本 + CI）：PR 需维护者审查并加 `arch-approved` 标签 |
| 前置依赖 | 无                                                                           |
| 涉及模块 | `data/`、`scripts/`、根 `package.json`、`.github/workflows/ci.yml`           |

## 目标

把来源登记从手写表格改成机器可读的 `data/sources.json`，由脚本校验并生成 `data/SOURCES.md`，并在 CI 中检查两者同步。**本任务不登记任何具体来源**：目前仓库没有外部数据，`sources.json` 就是空数组，这是真实状态。

## 背景（只需知道这些）

- 来源记录的结构已经有了：`SourceRecordSchema`（`packages/content-schema/src/evidence.ts`），其中「可再分发（`allowed`）必须有 `verifiedAt`」已由 schema 强制。
- 规则见 `docs/DATA_POLICY.md`「流程」第 1 步：`SOURCES.md` 由 `sources.json` 生成，不手改。
- 参考写法：`scripts/check-licenses.mjs` 也是「检查模式 / `--write` 生成模式」的结构。
- 根目录脚本是 `.mjs`，可以直接 `import` 仓库里的 `.ts` 源码（Node 24 类型剥离），例如 `../packages/content-schema/src/index.ts`。

## 必读文件

- `packages/content-schema/src/evidence.ts`
- `scripts/check-licenses.mjs`（结构参考）
- `data/SOURCES.md`（现有表头，生成的文件要保留这些说明文字）
- `package.json`（`scripts` 与 `verify`）
- `.github/workflows/ci.yml`（checks 任务）

## 允许修改

- 新增 `data/sources.json`（内容为 `[]` 加换行）
- 新增 `scripts/check-data.mjs`
- 新增 `scripts/check-data.test.ts`
- `data/SOURCES.md`（改为由脚本生成）

- `.github/workflows/ci.yml`：在 checks 任务的 `pnpm check:licenses` 之后加一步 `- run: pnpm check:data`

## 禁止修改

其他文件；不得向 `sources.json` 写入任何具体来源。

## 实现要求

### `scripts/check-data.mjs`

导出两个纯函数（供测试），并在 `import.meta.main` 时执行命令行逻辑：

```js
/**
 * @param {unknown} records  sources.json 的解析结果
 * @returns {string[]}       问题列表；空数组表示通过
 */
export function validateSources(records);

/**
 * @param {import('../packages/content-schema/src/index.ts').SourceRecord[]} records
 * @returns {string}         完整的 SOURCES.md 文本
 */
export function renderSourcesMarkdown(records);
```

`validateSources` 的规则：

1. 必须是数组，否则返回 `['data/sources.json 必须是数组']`。
2. 每一项都要通过 `SourceRecordSchema`；失败时问题文本包含下标与 zod 的错误信息。
3. `id` 不得重复（问题文本包含重复的 id）。
4. 按 `id` 字典序排列（不是则报告，避免合并冲突与无意义的顺序变化）。

`renderSourcesMarkdown` 的输出：

- 开头保留现有 `data/SOURCES.md` 的标题与说明段落，并在说明后加一行引用：

  ```markdown
  > 本文件由 `pnpm data:sources` 根据 `data/sources.json` 生成，请勿手改。
  ```

- 没有来源时，表格之前写 `**目前仓库里还没有任何外部数据。**`（与现有文字一致）。
- 表头列：`ID | 标题 | 发布者 | URL | 版本 | 许可证（SPDX） | 再分发 | 核验日期 | 备注`；每个来源一行，缺省字段写 `—`；表格单元格里的 `|` 转义为 `\|`。
- 文件以单个换行结尾。

命令行：

- `node scripts/check-data.mjs`：读取 `data/sources.json`，运行 `validateSources`；再把 `renderSourcesMarkdown` 的结果与 `data/SOURCES.md` 比较。有问题时逐条打印并以退出码 1 结束；不同步时提示运行 `pnpm data:sources`。全部通过时打印一行总结（来源条数）。
- `node scripts/check-data.mjs --write`：校验通过后重写 `data/SOURCES.md`；校验不通过时不写文件、退出码 1。

所有提示用中文。参数解析用 `node:util` 的 `parseArgs`。用 JSDoc 写类型（根目录 `tsconfig.json` 会做类型检查）。

### `package.json`

```json
"check:data": "node scripts/check-data.mjs",
"data:sources": "node scripts/check-data.mjs --write",
```

## 验收测试（必须新增，写在 `scripts/check-data.test.ts`）

用测试夹具（注释标明为夹具；URL 用 `https://example.org/...`）：

1. `validateSources([])` 返回 `[]`。
2. 非数组、缺字段、`redistribution: 'allowed'` 却没有 `verifiedAt`、重复 id、未按 id 排序，各返回包含相应信息的问题。
3. `renderSourcesMarkdown([])` 包含「目前仓库里还没有任何外部数据」与生成说明，以换行结尾。
4. 两条夹具来源渲染后各占一行，单元格里的 `|` 被转义，缺省字段为 `—`。
5. 对仓库里真实的 `data/sources.json` 运行两个函数：校验通过，渲染结果与 `data/SOURCES.md` 完全一致。
