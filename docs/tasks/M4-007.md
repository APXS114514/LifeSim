## 目标

让上万条人生事实的时间线保持流畅：按年分组、重大事件突出、普通事件折叠、虚拟滚动只渲染可见区域，并支持回顾过去的人生。GDD §10 要求「通过虚拟列表和分页读取千条以上人生记录」。

## 背景

- 现状：`components/Timeline.tsx` 直接把所有事实渲染成列表；M3 加入 NPC 与事件后事实数会显著上升（M3-lite 一局约 96 条；M3 预计数百到数千）。
- 事实是只追加日志（`sequence` 单调），适合按年分组 + 增量渲染。
- 界面不得改写事实；渲染由 `narrator` 负责（语言切换只重绘）。
- 不引入重量级虚拟列表依赖（许可证与体积成本）；可以用自研窗口化或已审计的小库（需 notices）。

## 实现要求

1. **分组**：按年份分组，组头显示年份与年龄；组内按 `sequence` 升序；同一天的事件保持事实顺序。
2. **折叠**：每组默认只显示「重大事件」（`decision.made`、`life.death`、`life.birth`、历史锚点、家庭重大事件）与最近 3 条普通事件；「展开这一年」显示全部；折叠状态是界面状态，不写入存档。
3. **虚拟化**：只渲染视口 ± 一屏的行；行高可变时用估算 + 测量缓存；滚动到任意年份；键盘可导航（Home/End/PageUp/PageDown）。
4. **增量**：新事实到达时只更新受影响的组，不重建整棵树。
5. **性能预算**：10,000 条事实的初始渲染与滚动帧时间目标（P75 ≤ 200 ms 首次渲染、滚动无明显掉帧）；用固定夹具测量并记录真实数字。
6. **语言切换**：切换后重绘文本，滚动位置与折叠状态保留。
7. **可访问性**：列表用 `role="log"` 或列表语义；每行有可读的日期/年龄文本。

## 验收测试

1. 分组/折叠纯函数：给定夹具事实，断言组数、每组可见条数、展开后的条数。
2. 虚拟化：10,000 条夹具下 DOM 节点数 < 200（渲染窗口），滚动到末尾后可见最后一条。
3. 增量：追加 10 条事实后只有最后一组更新（用渲染计数断言）。
4. 键盘：End 跳到最后，Home 回到开头。
5. 语言切换：滚动位置与折叠状态不变，文本改变。
6. E2E：长人生时间线可滚动、无控制台错误、无横向滚动。
