## 目标

现在最慢每年 2 秒，一生约 3 分钟，且一年的事件一次性出现。参考 1in8b 与 1injp 的节奏：开局可选「一生时长」（例如约 10、30、60 分钟），播放中可再调倍速；一年内的事件按年度进度条逐条出现。

## 已定的约束（骨架原文，不得改动）

1. **仍然每个 tick 只推进一个周年节点**（M3-034 的约束不变），绝不预先模拟后面的年份。
2. 年内逐条出现只是展示：这一年的事实已经由内核算出并保存，界面按进度依次显示。显示的日期**不得超过权威时钟**；暂停时停止显示进度；刷新或读档后直接显示到权威时钟为止的全部事实。
3. 遇到重大决定时，内核停在决定日期，界面显示到该日期的事实后弹出决定卡。
4. 一生时长与倍速是界面偏好（`lifesim.prefs.v1`），不写进存档、不影响结果。
5. M3-034 的单元测试与 E2E 只能扩展，不能放宽。

## 背景（只写执行者必须知道的事实）

- 现状：`TimeControl`（`apps/web/src/game/time-control.ts`）每个计时器 tick 用 `stepYear()` 推进**一个周年节点**，间隔是 `speed` 毫秒/年（`SPEED_LEVELS = [2000, 1000, 500, 250]`，默认 1000，即「一生约 3 分钟」）。`Timeline` 直接把 `session.facts` 全部渲染出来。`PlayPage` 把 `control`、`session` 传给 `TimeControls` / `Timeline`；`App` 创建 `TimeControl` 并在每次变化时自动存档。
- M3-034 的既有行为必须保留：开局与读档后停在权威时钟、一律暂停；「下一年」「跳转到下一个决定」「直接模拟至结局」都只在暂停时可用；遇到重大决定进入 `awaiting-decision`。
- `session.facts` 是权威事实列表（按 `sequence` 递增），`session.clock` 是权威时钟；界面**不得**缓存可写的模拟状态，只缓存展示状态（当前显示到第几条）。
- 测试环境：`vitest.config.ts` 的 `environment` 是 `node`，没有 jsdom；React 组件与 rAF 只能用 Playwright E2E 验收，纯逻辑（揭示状态机、偏好读写）必须做成可在 node 里单测的模块；**不要为测试新增依赖**。

## 实现要求

### 1. 偏好存储（`apps/web/src/game/prefs.ts`）

```ts
export const PREFS_KEY = 'lifesim.prefs.v1';
export const LIFE_LENGTH_MINUTES = [10, 30, 60] as const; // 一生时长的三个档位
export type LifeLengthMinutes = (typeof LIFE_LENGTH_MINUTES)[number];
export interface Preferences {
  version: 1;
  lifeLengthMinutes: LifeLengthMinutes; // 默认 30
  pace: PaceMultiplier; // 默认 1；档位取自 year-pacing 的 PACE_MULTIPLIERS
}
export interface PrefsStorage {
  // 只依赖这三个方法，测试用内存对象即可（node 环境没有 localStorage）
  getItem(key: string): string | null;
  setItem(key: string, value: string): void;
  removeItem(key: string): void;
}
export const DEFAULT_PREFERENCES: Preferences;
export function loadPreferences(store?: PrefsStorage | null): Preferences;
export function savePreferences(prefs: Preferences, store?: PrefsStorage | null): boolean;
```

- 键必须正好是 `lifesim.prefs.v1`；**读写任何其他键都是错误**（尤其是 `lifesim.save.v1` 与 `lifesim.save.v1.preserved`）。
- 缺失、JSON 损坏、`version !== 1`、档位不在 `LIFE_LENGTH_MINUTES` / `PACE_MULTIPLIERS` 里：回退到 `DEFAULT_PREFERENCES`，**不抛错、不写回**（读操作没有副作用）。
- `store` 省略时用 `globalThis.localStorage ?? null`；存储不可用或抛错时返回默认值 / 返回 `false`（照 `storage.ts` 的 `try/catch` 风格）。
- 偏好**不进入存档**：`GameSession.serialize()` 与 `saveGame` 不得出现任何偏好字段。

### 2. 揭示状态机（`apps/web/src/game/year-reveal.ts`，纯逻辑、可在 node 单测）

必须**只**通过 `year-pacing.ts` 的 `startYear` / `advanceYear` / `isYearDone` / `visibleFactCount` / `displayDate` 计算，不要复制一份公式。

```ts
/** 界面当前应显示的画面（展示状态，不是权威状态）。 */
export interface YearRevealView {
  /** 应显示 `session.facts.slice(0, visibleCount)`。 */
  readonly visibleCount: number;
  readonly progress: number; // 0—1
  readonly from: ISODate; // 这一年（或静止时）的起点
  readonly to: ISODate; // 这一年的终点＝权威时钟；view.date 恒 <= to
  readonly date: ISODate; // 进度条上的日期
  readonly animate: boolean; // 是否处于逐条揭示中
}

export class YearRevealClock {
  constructor(options: { yearMs: number; clock: ISODate; factCount: number });
  /** 偏好改变（一生时长/倍速）：下一次 frame / observe 用新的 yearMs；非法值抛 RangeError。 */
  setYearMs(yearMs: number): void;
  /**
   * 会话发生变化时调用一次。`isPlaying` 是该变化发生**之后** TimeControl 的状态，
   * `allowAnimation` 是「未开启减少动态效果」。
   * 只有「播放中、时钟前进了一年、且确有新事实」才逐条揭示（返回 animate: true）；
   * 其余一律立即显示到 `factCount`（返回 animate: false）。
   */
  observe(input: {
    clock: ISODate;
    factCount: number;
    isPlaying: boolean;
    allowAnimation: boolean;
  }): { animate: boolean };
  /** 计入一帧经过的毫秒数；没有进行中的揭示时是空操作。 */
  frame(elapsedMs: number): void;
  /** 立即显示全部（减少动态效果、重大决定、手动推进之前）。 */
  complete(): void;
  get view(): YearRevealView;
  get isComplete(): boolean;
}
```

语义细节（照抄）：

- `shownBefore` = 上一次 `observe` 记录的 `factCount`（即上一年结束时的全部事实数），`newFacts` = 本次 `factCount - shownBefore`。用 `startYear(shownBefore, newFacts)` 开始揭示，`from` = 上一次的 `clock`，`to` = 本次的 `clock`；因此**上一年的剩余事实不会丢失**：`visibleCount` 从 `shownBefore + 1` 起算。
- `view.visibleCount = visibleFactCount(reveal)`，`view.progress = reveal.progress`，`view.date = displayDate(from, to, progress)`；`frame` 走到 `isYearDone` 时立即把 `visibleCount` 置为 `factCount`、`animate` 置为 false。
- `complete()`：`visibleCount = factCount`、`progress = 1`、`date = to = clock`、`animate = false`；再调 `frame` 不改变任何值。
- 参数校验：`factCount` 必须是非负整数，`clock` 必须是不早于 `from` 的合法 ISO 日期，`yearMs` 必须是正的有限数；违反时抛 `RangeError`（照 `year-pacing` 的风格）。
- 不读墙钟、不用 `Date.now`、不用 `Math.random`：经过的时间只由 `frame(elapsedMs)` 传入。

### 3. 连接层（`apps/web/src/game/use-year-reveal.ts`）

```ts
export function useYearReveal(options: {
  control: TimeControl;
  session: GameSession;
  yearMs: number;
  allowAnimation: boolean; // !prefers-reduced-motion
}): YearRevealView;
```

- 初始化：`new YearRevealClock({ yearMs, clock: session.clock, factCount: session.facts.length })`（读档/刷新时就是「全部显示」）。
- 订阅 `control.subscribe(...)`：每次回调用当前 `session.clock` / `session.facts.length` / `control.state === 'playing'` / `allowAnimation` 调用 `observe`；`animate === true` 时启动 `requestAnimationFrame` 循环，每帧用 **两次 `performance.now()` 的差值**调用 `frame`（真正的墙钟只出现在这一层，和 `timerScheduler` 同理）。
- 只有 `control.state === 'playing'` 且揭示未完成时才继续申请帧；暂停时**停止申请帧、不推进进度**（下次 `play()` 从冻结值继续，不重新开始）。
- `allowAnimation` 变为 `false`（系统开启减少动态效果）时立即 `complete()`。
- 组件卸载时取消 `requestAnimationFrame` 与订阅。
- 该 hook 不得写存档、不得调用 `stepYear` / `choose` 等推进会。

### 2. `apps/web/src/game/year-reveal.test.ts`（node 环境）

1. 播放中推进一年（`isPlaying: true`，clock +1 年，factCount 增加）→ `animate: true`，`visibleCount = 上一年事实数 + 1`（第一条立刻出现），`progress = 0`，`date = from`。
2. 连续 `frame`：`visibleCount` 单调不减、不超过 `factCount`；`progress` 不超过 1；`date` 落在 `[from, to]`；走完后 `visibleCount === factCount`、`animate === false`、`date === to`（= 权威时钟）。
3. 单帧封顶：一次 `frame(60_000)` 只推进 `MAX_FRAME_MS / yearMs`（继承 `advanceYear` 的 250 ms 上限）。
4. 非播放变化（`isPlaying: false`，模拟「下一年」/「跳转」/「选择」/读档）→ `animate: false`，`visibleCount === factCount`，`date === clock`（一次性显示全部）。
5. `allowAnimation: false`（减少动态效果）→ 同上，一次性显示。
6. 重大决定：播放中的 tick 停下后 `control.state !== 'playing'` → 立即显示到决定日期全部事实（由第 4 条覆盖；此处断言 `date === clock` 且 `visibleCount === factCount`）。
7. 上一年剩余事实不丢：先部分揭示，再 `observe` 到下一年的 tick → 新的 `visibleCount >= 旧的 visibleCount`，走完后等于 `factCount`。
8. 参数校验：`factCount: -1`、`factCount: 1.5`、`yearMs: 0`、`clock` 早于 `from` → `RangeError`。
9. fast-check（`numRuns: 200`）：任意帧序列 → `visibleCount` 单调、不越过 `factCount`、`date` 不超过 `to`；任意「一次性」变化后 `visibleCount === factCount`。
