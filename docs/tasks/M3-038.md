## 目标

GDD §10：主角可能不知道远方 NPC 的私人事实；内部事实日志与玩家已知事实（可见时间线）要区分。M3-011 之后，父母会产生大量主角未必知道的事实，时间线需要只显示主角当时能知道的部分。

## 已定的约束（细化时不得改变）

1. **事实日志仍记录全部事实**，可见性只影响展示与生平报告；任何规则不得依据「玩家是否看见」改变结果。
2. 可见性在**事实产生时**确定并随事实保存（不可事后重算），方案由 ADR-0009 决定；Claude Code 的推荐方案是 `SimEventFact` 增加可选字段（缺省视为「已知」），这样旧事实与旧存档的读取不受影响。
3. 判定规则写在 `packages/systems` 的一个集中函数里（例如「与主角同住或为一等亲的 Tier1 → 已知；Tier2 的私人事实 → 内部」），各系统 `emit` 时调用它，不在各处散写条件。
4. 切换语言、刷新、存档往返后，已知/内部的划分不变；生平报告只汇总已知事实。
5. 提升 `SYSTEMS_VERSION`；黄金指纹若变化，逐条说明原因。

## 需要细化的内容（B 部分）

- 判定函数的完整规则表（关系类型 × 是否同住 × 事实类型），每一格给测试；
- 时间线与生平报告的过滤；开发模式下查看全部事实的开关（不进入生产构建的界面）；
- 中英文案（例如「你后来才得知……」类的延迟知晓是否在 v0.1 做——默认不做，列为待决）。

## 验收要点

- 已知事实是全部事实的子集；内部事实仍在存档与 `facts` 里；
- 规则表每一格至少一个测试；fast-check：可见性不影响任何后续事实（同一种子，把判定函数换成「全部已知」时结构化事实除可见性字段外逐字节相同）；
- E2E：时间线不出现内部事实。

## 可能的阻塞

- ADR-0009 未采纳；需要「延迟知晓」等超出约束的语义。
