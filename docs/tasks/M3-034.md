## 目标

玩家点「开始人生」后先看到出生与初始状态（默认暂停），之后可以**逐年**经历人生：下一年、自动播放（可调速、可暂停/继续）、快进到下一个重大决定、以及一个明确独立的「直接模拟至结局」。所有方式产生的权威结果完全相同。

## 背景（只写执行者必须知道的事实）

- 试玩反馈：点「开始人生」后直接跳到下一个重大决定，有时一次出现几十年的事件甚至接近死亡；玩家没有时间控制权。
- 原因（现有代码）：`App.tsx` 的 `start()` 创建会话后立刻 `session.advance()`；`GameSession.advance()` 以 `2200-01-01` 为目标、只在重大决定或死亡时停；`choose()` 选完后又调用 `advance()`。
- 产品依据：GDD §2 决定 02 与 §4.1——逐年、自动、快进共用同一规范模拟内核；重大事件暂停。
- 内核已经具备所需能力，**不需要改内核**：
  - `simulation.advanceTo({ targetDate, stopAtMajorDecision, maxWorkUnits })` 处理日期 ≤ `targetDate` 的全部事件；遇到未选择的重大决定时在它之前停下（`stopReason: 'major-decision'`），主角死亡时停（`'protagonist-died'`）。
  - `simulation.clock` 是**权威当前日期**（推进到目标日期后等于目标日期；在决定前停下时等于决定日期），并写入快照的 `at`，恢复后保持不变。
  - `addYears` / `ageOn`（`@lifesim/simulation-core`）是规范日历：2 月 29 日出生者在平年取 2 月 28 日，「生日」与「周岁增加」永远在同一天。
  - 逐年、快进、单事件推进的结果逐字节相同，内核测试已经保证；本任务要在网页层再证明一次。
- 1injp 参考（MIT，`Copyright (c) 2026 satoru.net`，评估见 [REFERENCE_REUSE](../REFERENCE_REUSE.md)）：`app.js` 约 578—749 行与 `index.html` 的时间控制条——每次只算一年，按速度节拍推进下一年；决定弹窗或暂停时不推进；读档后默认暂停并显示大号「已暂停」提示。**只借鉴交互语义，用 React 重新实现，不复制代码**（若确实移植了实质代码，必须在 `THIRD_PARTY_NOTICES.md` 补 MIT 声明并在报告中列出）。不得复制 1injp 的数据、字体、图片、音频。

## 实现要求

### 1. 会话层（`session.ts`）

1. `get clock(): ISODate`：返回 `this.simulation.clock`。`currentDate` 改为返回同一个值；**不得**再用最后一条事实的日期推算当前日期（有的年份没有任何新事实）。
2. `settleBirthDay()`：`advanceTo({ targetDate: clock, stopAtMajorDecision: true, … })`，把出生当天的其余事件（0 岁生日排程等）结算完。`GameSession.create` 之后由调用方调用一次。
3. `nextAnniversary(): ISODate`：`addYears(birthDate, ageOn(birthDate, clock) + 1)`。
4. `stepYear(): StepResult`：推进到 `nextAnniversary()`（含当日事件），遇到重大决定或死亡提前停。返回 `{ stopReason, newFacts, clock }`。已有待决事项时不推进（直接返回 `stopReason: 'major-decision'`，不追加任何事实）。`work-budget-exhausted` 时继续循环，与现有 `advance()` 相同。
5. `advanceToNextDecision()`：现有 `advance()` 的行为（推进到下一个重大决定或死亡），作为「快进」。保留 `advance` 作为别名或改名并同步调用方。
6. `choose(optionId)`：`decide()` 之后**只结算当天**：`advanceTo({ targetDate: clock, stopAtMajorDecision: true, … })`。**不得**再自动推进到下一个决定。
7. `finish()`：保持现有语义（剩余重大决定按人生原则自动选择，直到死亡），只由「直接模拟至结局」触发。
8. 事实只来自 `advanceTo` 返回的 `newFacts`，按序号追加；不得重新抽样、不得从快照重建事实。
9. `GameSession.restore`：增加一致性检查——`facts` 的 `sequence` 必须从 0 连续递增，且最后一条的 `sequence === snapshot.lastJournalSequence`；不一致时抛错（交给 `storage.ts` 已有的 M3-000 非破坏性路径：保留原始存档、提示、可下载备份）。

### 2. 控制状态机（`time-control.ts`）

纯 TypeScript，不依赖 React、DOM 或真实时间；计时器通过注入的接口提供（`schedule(fn, ms) → cancel`），测试用假计时器。

- 状态：`paused` | `playing` | `awaiting-decision` | `ended`。
- 创建与恢复后一律为 `paused`。
- `play()`：`paused → playing`，安排下一次 tick；在 `playing` 中再次调用是幂等的。
- `pause()`：`playing → paused`，取消已安排的 tick；在其他状态调用是幂等的。
- `setSpeed(level)`：速度档位为每年 2000 / 1000 / 500 / 250 ms（默认 1000）；`playing` 时从下一次 tick 起生效。速度是界面偏好，不写进存档（可以写入单独的键 `lifesim.prefs.v1`，读写失败时用默认值）。
- tick：调用一次 `session.stepYear()`；结果为 `major-decision` → `awaiting-decision`（记住决定出现前是否在播放）；`protagonist-died` → `ended`；否则在 `playing` 时安排下一次 tick。**每次 tick 恰好推进一个周年节点**，绝不预先模拟后面的年份再用动画「伪装」逐年。
- `stepOnce()`（下一年）：只在 `paused` 时可用，执行一次 tick 的推进逻辑但不安排下一次。
- `choose(optionId)`：只在 `awaiting-decision` 时可用；调用 `session.choose()` 后回到决定出现前的状态（原来在播放就继续按当前速度逐年播放，原来暂停就保持暂停）。若当天结算后主角死亡则 `ended`。
- `fastForward()`：只在 `paused` 时可用；调用 `advanceToNextDecision()`，结束后进入 `awaiting-decision` 或 `ended`。
- `finishLife()`：由界面在玩家二次确认后调用；结束后为 `ended`。
- 页面不可见（`visibilitychange` 为 hidden）时自动 `pause()`，回来后保持暂停。
- 每次推进后由调用方触发自动存档（与现在每次操作后存档一致）。

### 3. 界面

- 时间控制条（`TimeControls.tsx`）：「下一年」「播放 / 暂停」「速度」「快进到下一个决定」，以及与之分开、样式更弱的「直接模拟至结局」（点击后弹出二次确认，说明剩余决定将按人生原则自动选择）。
- 显示权威日期 `session.clock` 与周岁 `ageOn(birthDate, clock)`；状态文字（已暂停 / 播放中 / 等待你的决定 / 已结束）用 `aria-live="polite"`。
- 有待决事项时：时间控制禁用（「直接模拟至结局」除外），显示决定卡；选择后按上面的规则继续。
- 开局与读档：默认暂停，显示「已暂停」提示与「开始播放」按钮；时间线只显示已经发生的事实。
- 时间线按时间顺序追加新事实；已经显示的事实不重排、不重复。
- 键盘：空格切换播放/暂停（焦点在输入框或按钮上时不拦截）；所有按钮有可见文字或 `aria-label`；手机上触控目标 ≥ 44 px，控制条不产生横向滚动。
- 所有新文案中英齐全。
- 顺带修正过时文案：`app.stageNotice` 现在写「暂无家庭、NPC」，但 M3-010 已加入父母。改为说明「已有出生家庭（父母），但父母还没有独立的人生进程；暂无婚育、迁居与城市权重」，中英同步。

## 验收测试

### 单元测试（`session.test.ts`、`time-control.test.ts`）

1. **开局暂停**：`create` + `settleBirthDay` 后 `clock === birthDate`，事实包含 `life.birth` 与两条 `family.parent`，没有待决事项；控制器状态为 `paused`。
2. **逐年**：从开局连续 `stepYear()` 直到第一个决定，每一步的 `clock` 恰好是下一个生日（周岁每步 +1，不跳年、不重复）；没有新事实的年份 `clock` 也照样前进。
3. **闰日出生**：出生日 `2000-02-29`（固定种子与地区）连续 8 步的停止日期为 `2001-02-28、2002-02-28、2003-02-28、2004-02-29、2005-02-28、…`。
4. **决定打断**：`stepYear()` 在决定日之前停下，`clock` 等于决定日期；待决时再次 `stepYear()` 不追加事实；`choose()` 之后 `clock` 不超过当天，且没有出现下一个周年之后的事实。
5. **三种方式等价**：同一 request、同一组选择（例如每次都选 `recommended`），(a) 只用 `stepYear` + `choose`，(b) 只用 `advanceToNextDecision` + `choose`，(c) 混合（前 10 年逐年、之后快进），最终 `canonicalJson(facts)` 与 `canonicalJson(snapshot)` 完全相同。
6. **不预先模拟**：自动播放中用 spy 记录 `simulation.advanceTo` 的调用，每次 tick 的 `targetDate` 不超过当时的下一个周年。
7. **暂停**：假计时器下 `play()` → 推进 3 个 tick → `pause()` → 再快进假时间 10 秒，`clock` 与事实数不变；`play()` 后继续。
8. **存档往返**：任意一步之后 `serialize → JSON → parseGameSave → restore`，`clock`、事实、待决事项与原会话相同；随后两边继续推进的结果相同；恢复后的控制器为 `paused`。
9. **事实与快照不一致**：篡改存档里的事实数量或序号，`restore` 抛错；`loadGame()` 返回 `failed` 且原始存档仍在（沿用 M3-000 的断言方式）。

### E2E（`pnpm test:e2e`，桌面 + 手机）

1. 开始人生后：可见出生与父母事实、年龄 0、状态「已暂停」；没有决定卡。
2. 点「下一年」：年龄变为 1，日期为第一个生日；之前的事实条目原样保留（前 N 条文字不变）。
3. 播放（最快档）几秒后暂停：年龄增加；暂停后等待 1.5 秒年龄不变。
4. 播放直到出现决定卡：状态为「等待你的决定」，控制条禁用；作出选择后年龄不超过选择前 +1。
5. 「快进到下一个决定」停在决定卡；「直接模拟至结局」需要确认，确认后出现一生总结。
6. 播放中刷新页面：恢复后为暂停状态，事实数与日期与刷新前最后一次存档一致，没有重复条目。
7. 语言切换：控制条文案变化，事实数不变。
8. 现有 E2E（旧存档保护、无横向滚动、无控制台错误等）全部通过。

## 审查记录（Claude Code，2026-10-21）

结论：**通过**，建议合并。改动全部在 `apps/web` 内，没有触碰 `packages/*`、存档键或配置文件；实现与规格逐条对应。

- 实测：`pnpm verify` 56 个文件、449 项测试通过（含测试基线与构建）；`PW_CHANNEL=chrome pnpm test:e2e` 38 项通过。
- 会话：时钟取 `simulation.clock`；`settleBirthDay` / `stepYear` / `nextAnniversary` 正确；`choose` 只结算当天；读档检查事实序号与 `lastJournalSequence`，不一致时走 M3-000 的非破坏性路径。
- 控制器：计时器可注入、`setTimeout` 链式调度、每个 tick 只推进一个周年、失败退回暂停、页面隐藏时暂停；React 接线在卸载与 StrictMode 双挂载下都不会泄漏或重复推进。
- 测试有实质断言：三种玩法的事实与快照逐字节相同、闰日停止序列与规格一致、用 spy 证明不预先模拟、篡改存档被拒绝。

意见（不阻塞合并）：

1. **潜在缺陷（P2，M3-017 前必须修）**：`pendingDecision()` 不看日期，若将来有重大决定排在非生日日期，决定卡会提前最多一年出现。目前所有重大决定都排在当天，不会触发。修复见 [M3-040](M3-040.md)。
2. E2E 把所有冒烟测试固定为种子 `probe-0`（原来是随机种子），断言都保留了，但随机覆盖变少；单元测试仍覆盖多个种子。可以接受，记录在此。
3. `fastForward` 结束时若既没死亡也没有待决事项，会停在「等待决定」；主角必定在 2200 年前死亡，实际不可达。
4. 试玩数据（不是本任务的缺陷）：五国各 200 局，30%—47% 的人生没有任何重大决定，平均每局 0.54—0.70 个；约 15% 的年份没有任何事件。逐年推进让这个问题更明显，见 [V0.1_PLAN](../V0.1_PLAN.md) 的 D12。
