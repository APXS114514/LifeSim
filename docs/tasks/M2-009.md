# M2-009：许可核验与来源登记（UN WPP 2024、世界银行 WDI 城镇比例）

| 项       | 内容                                                                                     |
| -------- | ---------------------------------------------------------------------------------------- |
| 风险     | 高（许可决定）：**维护者必须亲自确认结论**，PR 需加 `arch-approved` 标签                 |
| 前置依赖 | M2-004                                                                                   |
| 涉及模块 | `data/sources.json`、`data/SOURCES.md`、`data/LICENSE_AUDIT.md`                          |
| 预计改动 | 新增 1 个文件，修改 2 个文件                                                             |
| 特殊要求 | 需要能打开网页的浏览器（联合国网站由 JavaScript 渲染，命令行取不到正文）；没有就报告阻塞 |

## 目标

在任何派生数据进入仓库之前，核验两个计划使用的数据来源的许可条款，并把结论登记在案。**本任务只做核验与登记，不下载、不转换任何数据。**

## 背景（只需知道这些）

- 计划使用的来源（ADR-0005 §3）：
  1. 联合国人口司 World Population Prospects 2024（WPP 2024）：年出生数、单岁生命表（男女合计）。
  2. 世界银行 World Development Indicators 指标 `SP.URB.TOTL.IN.ZS`（城镇人口占总人口百分比）。
- GDD §9.4：MIT 只覆盖本项目原创代码；外部数据各有许可，「联合国资料不能在核验具体条款前自动宣布为 MIT」，世界银行数据「多数是 CC BY 4.0，但需逐数据集核查」。
- 只有条款**明确允许再分发**（包括修改后再分发，并写明署名要求）时，才能标为 `allowed`。条款含糊、找不到、或有限制（例如禁止商业使用、禁止再分发），一律**不得**标为 `allowed`。
- 你的职责是**如实记录你看到的条款原文**；最终是否可用，由维护者在 PR 审查中确认。

## 必读文件

- `docs/DATA_POLICY.md`「流程」第 1、2 步
- `packages/content-schema/src/evidence.ts`（`SourceRecordSchema` 的字段）
- `data/sources.json`、`scripts/check-data.mjs`（M2-004 产物）

## 允许修改

- `data/sources.json`：新增两条来源
- `data/SOURCES.md`：只通过 `pnpm data:sources` 重新生成
- 新增 `data/LICENSE_AUDIT.md`

## 禁止修改

其他所有文件。不要下载数据文件，不要创建 `data/scripts/` 下的任何东西。

## 实现要求

### 1. 核验（对每个来源都要做）

1. 找到发布者官方网站上适用于该数据集的条款页面（使用条款、许可、版权声明）。只认官方域名（`un.org` 及其子域名、`worldbank.org` 及其子域名）。
2. 逐字摘录与以下问题有关的原文（附页面 URL 与访问日期）：是否允许再分发？是否允许修改后再分发？署名要求是什么？有没有商业使用限制？
3. 同时找到数据的官方下载入口：WPP 2024 的 CSV 下载页面，以及其中「Demographic Indicators（Medium 方案）」与「单岁生命表，男女合计」文件的名称与链接；世界银行该指标的 API 或下载链接。**只记录，不下载。**

找不到条款原文、页面打不开、条款含糊：该来源记为 `unknown`，在报告中写明，并把本任务标为阻塞（维护者会决定替代方案）。

### 2. `data/sources.json`

新增两条（数组按 `id` 字典序）：

| 字段             | WPP 2024                                                                              | 世界银行                          |
| ---------------- | ------------------------------------------------------------------------------------- | --------------------------------- |
| `id`             | `un-wpp:2024`                                                                         | `worldbank-wdi:SP.URB.TOTL.IN.ZS` |
| `title`          | 官方名称，例如 `World Population Prospects 2024`                                      | 官方指标名称                      |
| `publisher`      | 官方发布者名称                                                                        | 同左                              |
| `url`            | 数据集主页                                                                            | 指标页面                          |
| `version`        | `2024`                                                                                | 你访问时页面显示的最后更新日期    |
| `license`        | 条款对应的 SPDX 标识符（例如 `CC-BY-3.0-IGO`、`CC-BY-4.0`）；不确定时用 `NOASSERTION` | 同左                              |
| `redistribution` | `allowed` / `restricted` / `unknown`，依据上面的规则                                  | 同左                              |
| `verifiedAt`     | 核验日期（只在 `allowed` 时必填，其他情况也建议填写）                                 | 同左                              |
| `notes`          | 署名要求原文的简短转述                                                                | 同左                              |

### 3. `data/LICENSE_AUDIT.md`

每个来源一节，包含：来源 ID；条款页面 URL 与访问日期；**条款原文摘录**（引用块，逐字）；再分发 / 修改 / 署名 / 商业使用四项结论及依据；数据下载入口与文件名；核验人（写「执行 Agent，待维护者确认」）；结论（建议 `allowed` / `restricted` / `unknown`）。

文件开头写明：本文件记录许可核验的证据；结论须经维护者确认后才生效；任何派生数据进仓库前，其来源必须在此确认为可再分发。

### 4. 生成与检查

运行 `pnpm data:sources` 重新生成 `SOURCES.md`，再运行 `pnpm check:data`。

## 验收测试

本任务不新增代码测试；`pnpm check:data` 会校验 `sources.json` 的结构、排序与 `SOURCES.md` 的同步。维护者的审查是本任务的验收。

## 验收命令

```bash
pnpm check:data
```

```bash
pnpm verify
```

## 完成定义

- 两个来源都有条款原文摘录与官方 URL；`sources.json` 与 `LICENSE_AUDIT.md` 结论一致；`pnpm check:data` 通过。
- 报告中逐条列出：每个来源的建议结论、依据的原文、下载入口与文件名。
- 维护者在 PR 中确认结论后，M2-010 至 M2-012 才能开始。

## 可能的阻塞（遇到就停止并报告）

- 没有浏览器或无法访问官方网站。
- 条款不允许再分发或含糊（这本身是重要结论，照实报告）。
- 官方网站上找不到上述数据文件。
