# M3-029：M3 文档、已知限制与验收准备

| 项       | 内容                                       |
| -------- | ------------------------------------------ |
| 风险     | 低（只改文档）；不修改任何规则、数据或测试 |
| 前置依赖 | M3-028                                     |
| 涉及模块 | `docs/`、`README.md`、`CHANGELOG.md`       |
| 预计改动 | 修改 4—6 个文档，新增 1 个验收清单         |

## 目标

把 M3 的真实状态写清楚：玩家能做什么、规则来自哪里、哪些是 D 级假设、已知缺口、如何复现测试；给维护者一份逐条验收清单。**不宣布 M3 已验收**——验收由维护者签字。

## 背景

- ROADMAP/AGENT_HANDOFF/PLAYABLE_TEST 目前描述的是 M3-lite；M3 完成后这些描述会过时，必须更新。
- GDD §16 要求向用户披露：A/B/C/D 等级、未来年份是预测、朝鲜资料局限、随机出生不代表全球抽样、存档可能丢失。
- M3 验收需要「实际测试报告与未完成事项」。

## 必读文件

- `docs/ROADMAP.md`、`docs/AGENT_HANDOFF.md`、`docs/PLAYABLE_TEST.md`、`README.md`、`CHANGELOG.md`
- `docs/QA_GATE.md`、`docs/DATA_POLICY.md`
- M3-028 的测试输出与数字
- `docs/tasks/INDEX.md`

## 允许修改

- `docs/PLAYABLE_TEST.md`：更新可玩内容、限制、数据披露
- `docs/ROADMAP.md`：M3 状态改为「实现完成，待维护者验收」
- `docs/AGENT_HANDOFF.md`：更新现状、模块职责、版本号、已知风险
- 新增 `docs/M3_ACCEPTANCE.md`：逐条验收清单（对应 GDD §13 的五项退出条件 + QA_GATE 的 M3 门禁）
- 新增 `docs/KNOWN_LIMITATIONS.md`：明确列出未验证/缺失/简化项（若已存在则更新）
- `README.md`、`CHANGELOG.md`：更新状态与变更摘要

## 禁止修改

任何源码、数据、测试、`docs/GDD.md`、`docs/adr`、`AGENTS.md`、`docs/tasks/M3-*.md`（任务文件是历史记录）。

## 实现要求

1. PLAYABLE_TEST 必须如实写：五国可玩的内容、家庭/NPC/迁移/历史事件、**仍然缺失**的部分、数据等级披露、如何复现。
2. M3_ACCEPTANCE 必须逐条列出：
   - GDD §13 M3 的五项退出条件，每项给出对应测试文件与命令；
   - QA_GATE M3 行的每一条；
   - M3-001…028 的状态；
   - 未完成事项与阻塞（含 Q1…Q13 中仍未答复的）；
   - 「维护者签字」留空，不得代签。
3. KNOWN_LIMITATIONS 必须区分「未验证」「已知简化」「数据缺失」三类，并给出对应任务编号。
4. 不得把未运行的测试写成通过；引用 M3-028 的真实输出。
5. 不得声称 M3 已验收或已发布。

## 验收测试

1. 文档中所有命令都可复制执行（至少抽查 3 条并记录真实输出）。
2. 链接全部有效（相对路径指向存在的文件）。
3. 中文术语与仓库其他文档一致（证据等级、地区 ID、任务编号）。
4. `pnpm format:check` 与 `pnpm verify` 通过（文档格式）。

## 验收命令

    pnpm format:check

    pnpm verify

## 完成定义

- 五份文档更新完成，验收清单可供维护者逐条勾选；报告里明确「M3 未验收」。
- 没有改任何源码或数据。

## 可能的阻塞（遇到就停止并报告）

- M3-028 有失败用例 → 先报告失败，不要写「已完成」。
- 需要更新 `docs/adr`（例如 ADR-0007 从提议变已采纳）→ 这属于维护者权限，报告并等待。
