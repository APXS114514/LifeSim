## 目标

建立**程序化因果事件目录**，并用中国大陆特色事件跑通第一条完整链路：事件按年代与资格触发，有真实状态后果（不是背景文案），带证据与双语叙事。后续 M3-024…027 复用同一框架。

## 背景

- 现状：所有事件都是手写的 `EventDefinition`，由生日处理器逐个安排；没有统一的「国家/年代事件」入口。
- GDD §7：事件结构至少包含稳定 ID/版本、日期、适用地域与时代、前置条件、独立触发风险、相关角色、因果父 ID、玩家选项、影响字段、后续事件、双语模板、来源与置信标识。
- GDD §3.1：国家特色事件必须「有实质后果」；中国示例是特定历史背景下的教育和职业制度变迁。
- 参考项目 1injp 的统计事件表（见 [REFERENCE_REUSE](../REFERENCE_REUSE.md) R3）值得借鉴**字段结构**，但它的文本与数值不能用；也不要复制它的正则改写层（I1）。
- 框架必须**最小**：只有「每年分发 + 目录条目 + 双语覆盖检查」，不做 DSL、脚本化条件或动态注册。

## 实现要求

### A. 目录框架（`catalog.ts`）

    export interface EventCatalogEntry {
      readonly id: string;          // 稳定 ID，例如 'cn.gaokao-restored'
      readonly version: number;
      readonly priority: number;    // 复用 PRIORITY 的档位，不要自造序号
      readonly regions: readonly BirthRegionId[];
      readonly from: ISODate;       // 事件可发生的起始日（含）
      readonly to: ISODate | null;  // 结束日（含）；null 表示不设限
      readonly minAge: number;
      readonly maxAge: number;
      /** 纯函数：只读状态，不抽随机数。 */
      applies(context: EventContext, actor: CharacterState): boolean;
      /** 年度发生概率（0—1）。 */
      chance(context: EventContext, actor: CharacterState): number;
      /** 真正发生时的状态变更与事实。 */
      run(context: EventContext): void;
    }

1. `catalogEvents(entries)` 返回 `EventDefinition[]`，包含：
   - 一个分发事件 `life.annual-events`：在 `birthday` 当天安排（优先级 `PRIORITY.annual`，介于 career 与 health 之间）；
   - 每个条目一个事件，类型 = 条目 `id`，处理器调用 `run` 并设置 `eventVersion = version`。
2. 分发逻辑：
   - 按 `id` 字典序排序（**不是**声明顺序），保证新增条目不会改变其他条目的抽样位置；
   - 对每个在地区、日期窗口、年龄窗口与 `applies` 都通过的条目，抽一次 `ctx.random.chance(chance)`；**所有通过资格检查的条目都要抽**，命中与否只影响是否安排；
   - 命中的条目按（priority, id）排序，最多安排 2 个（每年上限常量，写进 catalog.ts 并测试）；
   - 被安排的条目安排到**同一天**，period 为 `age:<当前年龄>`，causes 指向触发它的事实（若没有则留空）。
3. 每个条目事件执行时必须重新检查一次「角色仍存活且资格仍成立」，防止同日连锁导致的状态变化。
4. 不做：不做条件表达式 DSL、不做脚本文件、不做运行时注册、不做可视化编辑器。

### B. 中国大陆特色事件（`cn.ts`，至少 3 条）

每条都必须：有稳定 ID（`cn.<slug>`）、年代窗口、真实状态后果、来源登记、双语模板、测试。

候选（执行者必须核实来源，核不到就换成可核实的，或报告）：

| ID                      | 年代      | 资格                 | 状态后果                                                                 |
| ----------------------- | --------- | -------------------- | ------------------------------------------------------------------------ |
| `cn.gaokao-restored`    | 1977 起   | 中学毕业、准备升学   | 额外一次大学录取机会；失败有独立事实                                     |
| `cn.sent-down-youth`    | 1968—1978 | 城镇中学毕业、未升学 | 迁往农村（`currentResidenceId` 改变、`coResident` 变化），教育与就业延迟 |
| `cn.soe-layoffs`        | 1995—2002 | 城镇国企就业         | 失业概率显著上升；再就业培训选项                                         |
| `cn.rural-migrant-work` | 1985—2010 | 农村青年             | 外出务工：居住地迁往城市、收入变化、家庭分离                             |
| `cn.housing-reform`     | 1998 起   | 城市家庭             | 住房支出上升（M3-014 的消费分类），影响储蓄                              |

至少要覆盖「教育」「职业/经济」「迁移」三类后果各一条。每条事件的事实类型 = 事件 ID，`details` 只放语言无关的标量。

### C. 叙事

每条事件在 `LIFE_NARRATIVE` 的 `templates` 下加一条（中英各一），键与事件 ID 一致；占位符来自 `details`；枚举文字放 `enums`。叙事必须描述**发生了什么**，不得写成史实科普段落。

### D. 证据

每条事件在 `data/sources.json` 登记来源（标题、发布者、URL、版本、许可、`redistribution`、`verifiedAt`），`LICENSE_AUDIT.md` 写「只引用事实，不再分发原文」；事件的 `evidenceIds` 指向这些来源。

## 验收测试

1. **窗口**：窗口外（例如 1970 年）不发生 `cn.gaokao-restored`；窗口内固定 seed 至少发生一次。
2. **资格**：不满足 `applies` 的角色不会触发（例如未上学的人不参加高考）。
3. **确定性**：新增一条目录条目（测试夹具）不改变其他条目的命中结果（因为按 id 排序且全量抽样）；同一 seed 两次运行一致。
4. **预算**：同一年最多 2 条目录事件；第 3 条被丢弃且不影响已安排的事件。
5. **覆盖**：遍历 `CN_EVENTS`，每条都有 zh-Hans 与 en 模板、都有 `evidenceIds`、都有 `applies/chance/run`。
6. **后果**：每条事件至少有一个状态字段发生变化（测试逐条断言），不允许只发事实。
7. **复活/死亡**：死亡角色不会被目录事件选中；事件执行后仍满足不变量。
8. **黄金指纹**：报告 `factCount` 与指纹变化原因。
