# M4-013：端到端验收（五国、桌面/手机、断网、刷新恢复）

| 项       | 内容                                          |
| -------- | --------------------------------------------- |
| 风险     | 低（只加测试与报告）                          |
| 前置依赖 | M4-001…M4-012                                 |
| 涉及模块 | `apps/web/tests/e2e`                          |
| 预计改动 | 新增 3—5 个 Playwright spec；可能扩展测试辅助 |

## 目标

用可重复的浏览器测试证明 M4 的退出条件：桌面与手机从出生到人生报告全流程可玩；断网后的已缓存游戏可用；多语言状态完全一致；存档往返与恢复一致；五国都通过关键路径。

## 背景

- QA_GATE 的 M4 行：存档中途恢复、导入导出与版本迁移；断网后已缓存版本可玩；中英切换后结构化结局不变；手机竖屏全流程。
- 现有 E2E 已有冒烟（开局、语言切换、自动结局、刷新恢复、年份越界、无横向滚动、无控制台错误）；本任务扩展到完整矩阵。
- 本任务不修改产品代码；发现缺陷时报告并指向对应任务，不要为了让测试通过而放宽断言。

## 必读文件

- `apps/web/tests/e2e/*.spec.ts`、`apps/web/playwright.config.ts`
- `docs/QA_GATE.md`、`docs/PLAYABLE_TEST.md`
- GDD §13 M4、§14.1

## 允许修改

- `apps/web/tests/e2e/*.spec.ts`（新增与必要的辅助函数）
- `apps/web/playwright.config.ts`：只允许新增项目/视口（若必要）
- 不修改产品代码

## 禁止修改

`packages/*`、`apps/web/src/*`（发现缺陷只能报告）、`docs/adr`、`qa/test-baseline.json`、`scripts/check-*`。

## 实现要求

至少 5 个 spec：

1. **五国关键路径**（桌面 1280×800）：每国 1 局，出生 → 逐年推进至少 3 次 → 至少 1 个决定 → 快进到死亡 → 总结可见 → 无控制台错误。
2. **手机完整流程**（390×844）：出生 → 推进 → 抽屉 → 决定 → 死亡总结；无横向滚动；触控目标达标。
3. **存档往返**：自动保存 → 刷新 → 继续（事实数一致）；导出 → 清空 → 导入 → 继续；损坏文件导入被拒绝且游戏可玩。
4. **断网**：在线加载 → 断网 → 刷新 → 继续已缓存人生；未缓存国家包有提示（配合 M4-011）。
5. **双语一致性**：同一局切换 zh/en，事实数量与结构化字段（可在页面暴露 data 属性或读取总结数字）不变；所有关键文案切换。
6. **恢复一致性**（可并入 3）：从存档恢复后继续推进 5 年，与不中断推进的最终事实数/死亡年龄一致（用两个上下文对比）。

## 验收测试

- 上述 spec 全部通过（使用 `PW_CHANNEL=chrome` 或已安装的 Playwright 浏览器，报告里写明）。
- 不削弱现有断言；新增 spec 的等待策略稳定（不使用固定长时间 sleep）。

## 验收命令

    PW_CHANNEL=chrome pnpm test:e2e

    pnpm verify

## 完成定义

- 五国、桌面/手机、存档、断网、双语、恢复全部有可重复测试；报告里贴出通过数与耗时。
- 已知缺陷如实列出并指向任务，不写成通过。

## 可能的阻塞（遇到就停止并报告）

- 本机没有 Chromium/Chrome 或 Playwright 浏览器未安装 → 报告环境限制与已尝试的命令。
- 离线/文件上传在 Playwright 中受限 → 说明实际覆盖范围。
