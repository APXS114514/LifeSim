# M4-011：PWA 离线支持

| 项       | 内容                                                                      |
| -------- | ------------------------------------------------------------------------- |
| 风险     | 高（Service Worker 缓存与版本兼容）：走 `task/M4-011-pwa` 分支            |
| 前置依赖 | M4-006…010（可玩界面）、M4-012（按需加载的国家包需要有稳定的 chunk 命名） |
| 涉及模块 | `apps/web`（public、构建配置）                                            |
| 预计改动 | 新增 service worker、manifest、注册代码、版本脚本；修改构建配置；E2E      |

## 目标

首次在线加载并缓存后，断网也能继续游玩：应用外壳、界面资源与至少一个已加载的国家包可用；Service Worker 缓存版本与存档数据版本不混淆；更新时提示而不是静默混用新旧版本。

## 背景

- GDD §11.1：离线意味着首次访问后所需静态包与五国数据包已成功缓存；Service Worker 更新须避免旧页面/新数据包混用。
- GDD §3.2：离线模式不能依赖在线 AI、云存储或远程业务 API。
- 现状：没有 manifest、没有 service worker；构建产物是单 chunk（M4-012 会拆分）。站点图标已由 M4-015 提供（`favicon.svg`、`icon-192.png`、`icon-512.png`、`apple-touch-icon.png`），manifest 直接复用。
- 本任务不引入第三方 PWA 插件也可以：手写 `sw.js` + 版本文件；若引入插件，必须登记依赖许可并接受工具链审查。

## 实现要求

1. **缓存策略**：
   - 预缓存：index.html、JS/CSS、locale 资源、manifest、offline 页面；
   - 运行时缓存：首次加载的国家包 chunk（cache-first，带版本）；
   - 不缓存 API/远程请求（本项目没有远程业务 API；若有第三方字体/CDN 一律不使用）。
2. **版本**：缓存名包含构建版本（由构建产物哈希或提交 SHA 生成）；旧版本在激活时清理；页面检测到新版本时提示「有新版本，刷新以更新」，不强制刷新。
3. **更新安全**：如果新 SW 激活但页面仍是旧版本，禁止混用（例如禁止用旧页面请求新 chunk，或提示刷新）；存档版本（`systemsVersion`）与 SW 版本分别处理，不互相覆盖。
4. **离线检测**：`navigator.onLine` + 请求失败提示；离线时照常可玩已缓存内容；未缓存国家包时给出明确提示而不是白屏。
5. **安装**：提供 manifest（名称、图标用纯 SVG/内联，不使用未授权素材）；可选「添加到主屏幕」提示不强制。
6. **无远程依赖**：SW 不请求任何外部域名。

## 验收测试

1. E2E：在线加载 → 生成一局 → 断网（`context.setOffline(true)`）→ 刷新 → 仍能继续这一局（已缓存的存档与资源）。
2. E2E：断网后启动新局 → 若该国家包未缓存，显示明确提示；若已缓存，可以完成出生选择与推进。
3. 版本混用：模拟旧页面 + 新 SW（可通过修改 cache 名与版本文件），断言页面提示刷新且不产生错误状态。
4. 离线时不发起任何外部域名请求（记录 request 列表断言）。
5. SW 注册失败（不支持/被禁用）时游戏仍可以在线可玩，并有非阻断提示。
6. 现有 E2E 全部通过。
