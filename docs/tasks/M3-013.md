## 目标

把「有工作/没工作」升级为有**职业类别、技能与职业流动**的就业系统：求职、转行、失业、再就业、退休都受国家、年代、学历、技能与地区经济结构影响。

## 背景

- 现状：`EmploymentStateSchema` 只有 `status`、`wageLevel`、`lastFactId`；求职概率只看学历与经济周期。
- GDD §8.2：学历、知识、技能、工作经验、法律执业资格分开存储；职业机会由能力、行业需求、年代、制度与关系影响；不得把现代互联网职业放到 1950 年。
- 数据：`employment-agriculture-share`（M3-005）可以约束农业就业份额；其余职业结构数据缺失时用 C/D 级表并标证据（Q4）。工资按 Q5 已确认的口径：优先真实工资/收入统计；没有可信校准基准与方法时用明确登记的 D 级假设，禁止把人均 GDP 当平均工资。
- 本任务**不引入性别**（Q1），也不做家庭财务（M3-014）。

## 实现要求

1. **契约**：`EmploymentStateSchema` 增加
   - `occupation: OccupationId | null`（就业或退休时非空，其他状态为 null）；
   - `skill: z.number().min(0).max(1)`（职业技能，随工作年限增长，增长只来自有事实依据的事件）。
     跨字段规则：`status === 'employed'` 或 `'retired'` 时 `occupation` 非空；其他状态为 null。
2. **职业目录**（`occupations.ts`）：稳定的 `OccupationId` 列表，至少覆盖农业、工业、建筑、运输、商业服务、公共服务、专业职业、军警；每个职业带 `validFrom/validTo`（年代资格）与 `regions`（国家资格），例如「软件工程师」类职业 `validFrom` 不得早于 1990。
3. **求职**：概率 = 基础（学历）× 地区经济结构 × 技能 × 疾病惩罚；经济衰退按年份锚点调整。成功后选择职业时，只能从**当年该国家可得**的职业里选，选择顺序确定性。
4. **职业流动**：转行只允许在资格满足时发生；技能增长与工作时长挂钩；失业后求职失败要记录原因（职业需求不足/技能不匹配/疾病）。
5. **退休**：按国家与年代（M3-012 或 ADR 定义的退休年龄）与职业类别（例如重体力职业更早）计算；养老金基于职业工资。
6. **兼容**：旧快照会被 `SNAPSHOT_SCHEMA_VERSION` 或 `SYSTEMS_VERSION` 拒绝（按 ADR 决定）；不得静默把旧存档的 `occupation` 补成默认值。

## 验收测试

1. 职业资格：1950 年出生的中国大陆角色不会得到 1990 年后才存在的职业；五国各一个断言。
2. 农业份额：农村出生者的农业就业概率显著高于城市（用固定 seed 批量 200 局比较，给出比例）。
3. 转行：技能达到阈值时可转行并记录事实；技能不足时不可用（决策选项 `eligible: false`）。
4. 状态一致性：`employed`/`retired` 与 `occupation` 的跨字段规则，用 fast-check 生成状态断言无违规。
5. 确定性：同 seed 两次运行一致；快照往返一致。
6. 双语：新增事实与职业名在 zh/en 都有文字（职业名走 `enums.occupation`）。
