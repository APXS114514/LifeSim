## 目标

让 Tier1 NPC（出生家庭里的父母）过自己的日子：每年生日推进教育/就业/健康/死亡；**死亡后不再产生任何事实**；NPC 的层级可以提升，但已经确定的事实不得重抽。这是 M3-A 的核心：NPC 不是主角的附属字段。

## 背景

- GDD §6.3：Tier1 核心家庭/密友运行连续的教育、工作、健康、关系与重大事件；Tier2 压缩；Tier3 统计。
- GDD §7：不能出现「死亡父亲次年失业」。
- 现有内核：`life.birthday` 只为主角安排年度事件；不变量 `lifeInvariants` 遍历全部角色，所以 NPC 状态必须始终满足年龄资格。
- 命名：本任务**不引入人名**，叙事用关系角色称谓（`role: 'mother'` 等）经 `enums.role` 渲染；M4 再决定是否加姓名。
- 性别未决（Q1）：NPC 不写 sex，不按性别区分概率。

## 实现要求

1. **生日推进**：为每个 Tier1 NPC 安排 `npc.birthday`（事件类型新常量），每年：
   - 教育：沿用 `region.rules` 的学制与 `education` 的概率；NPC 的升学结果独立抽样；
   - 就业：达到工作年龄且未就业/未退休 → 求职；已就业 → 年度失业风险；到退休年龄 → 退休；
   - 健康：沿用 `health.ts` 的发病与死亡公式（**同一次检查定生死与死因**，不得为 NPC 另写一套重复抽样）；
   - 死亡：写 `life.death`（`actorIds: [npc]`），之后不再为该 NPC 安排任何事件。
2. **状态一致性**：
   - 死者不参与任何后续事件；事件处理入口先检查 `vitalStatus.kind === 'deceased'` 并直接返回；
   - 未成年人不得就业、未到龄不得退休（不变量已有，必须保持通过）；
   - NPC 的求职失败/失业不得以主角的事实 ID 为原因。
3. **叙事**：NPC 事实的模板键以 `npc.` 开头（例如 `npc.hired`），`details` 里带 `role`；zh/en 模板分别为「母亲找到了工作。」/「Mother found a job.」这类**关系称谓**，不使用第三人称代词。
4. **层级提升**：提供 `promoteToTier1(state, actorId)` 的纯函数（Tier2 → Tier1 时才用，M3-017/018 与 M3-030 会调用）；提升只增加排程，不重抽已有字段。
5. **性能**：每个 NPC 的年度事件必须复用主角规则的函数或共享实现，禁止再复制一份概率公式；在报告里记录 `pnpm bench --lives 500` 的 p50/p99 与事实数量变化。

## 验收测试

1. 父母在主角 30 岁前至少发生 1 条就业或健康事实；所有事实的 `actorIds` 指向存在的角色。
2. **死者无新行为**：构造一个父母在建档后 3 年内去世的种子（可通过固定 seed 找到），断言死亡事实之后没有任何以该 NPC 为 actor 的事实。
3. 不变量测试：用 fast-check 随机 seed 跑 50 局，断言「未成年人就业」「未到龄退休」「死者有新增事实」三类违规一次都不出现。
4. 确定性：同 seed 两次运行的规范事实指纹相同；快照恢复后继续推进与不中断一致。
5. 叙事：每类 NPC 事实在 zh-Hans 与 en 下都能渲染，且不含 `{{`。
6. 黄金指纹：若变化，报告 `factCount` 与指纹差值并解释。

## 完成定义

- NPC 有独立生命周期，死亡后停止；测试通过；性能数字记录在报告里。
- 没有为 NPC 复制一套并行的死亡/职业公式。

## 可能的阻塞（遇到就停止并报告）

- 内核不允许为同一实体安排多个不同周期的事件，或死亡后仍会处理已排队的事件（需要内核改动 → 停下来报告）。
- 性能超出 M3 预算的合理范围（例如 p50 超过 3 倍）。
- 现有的出生日顺序假设（主角先、NPC 后）导致事实日期倒流。
