## 目标

GDD §14.2：每次提交 100—500 局轻量回归、夜间约 1 万局、发布候选 5—10 万局。现在只有合成地区的 `pnpm bench`；没有面向五个真实国家包、按国家/年代/城乡分层的批量运行与报告。

细化后本任务交付**一个**分层批量运行器与报告（`apps/cli` 的 `batch` 命令）、一个夜间 CI 工作流、以及报告格式说明。报告同时承担 [V0.1_PLAN](../V0.1_PLAN.md) §2 的**三个体验指标**的度量：每年可见事件数、无事件年份比例、每局可选决定数（D12）。本任务只**测量与留档**，不声明容差、不判定发布资格（那是 M5-002 与维护者的门禁职责）。

## 背景（执行者必须知道的事实与已定的决定）

测量配方（规划阶段的一次性探针，**未提交**；实施后用本任务的 `batch` 命令重测并对照）：

### 2. 与骨架一致的实测规模（决定夜间参数）

同机同提交、同一套分层规则（五国 × 8 个年代 × 城乡 = 80 层，每层 125 局 = 10,000 局）：

- 10,000 局**总墙钟 59.4 s**（探针墙钟，含拒绝抽样与每局指标计算，与报告的 `workload.totalMs` 同量级）；每局耗时 p50 6.0 ms / p95 8.2 ms / p99 14.1 ms / max 64.3 ms（探针口径把该局的拒绝尝试也算进去了，所以会比报告里只计接受局的 `timing.perLifeMs` 略高）。
- 为命中分层目标，共发起 **27,231 次**模拟：接受的 10,000 局 + 17,231 次被拒尝试（即 1.72 倍的额外开销，见「背景 §4」）。
- 不变量违规 0、运行错误 0；没有不可达的层；逐国可见事实/年 pooled 0.208—0.317、无事件年份比例 0.826—0.874、`all` 口径可选决定中位数 1、零决定占比 0.111—0.209。

结论：夜间 1 万局在本机约 1 分钟，CI `ubuntu-latest` 按慢 3—4 倍估约 3—4 分钟，45 分钟超时有余量。骨架列的「批量太慢」这一条**当前不成立**（见「可能的阻塞」）。

### 3. 已定的约束（骨架原文，未改动；下文只是解读，不改变约束）

1. 种子与分层确定（国家 × 出生年代 × 城乡），**不按五国人口加权后忽略小国**（GDD §9.3）；同一参数两次运行的报告指纹相同。
2. 只读模拟结果，不改规则与数据；不联网；`packages/*` 不引入非确定性 API。
3. 报告是 JSON，字段至少包括：每层局数、每局耗时 P50/P95/P99、事实数、快照字节、不变量违规数（必须为 0）、死亡年龄分布、事件重复率（GDD §3.3 用它决定内容扩容）。
4. 夜间任务只在 `main` 上定时运行，失败时 CI 标红并保留报告产物；不阻塞普通推送的 CI。

解读（不改变约束）：

- 约束 1 的「分层确定」在本任务落成「固定的层枚举顺序 + 层内固定的出生年与种子推导」，见「实现要求 §2」。
- 约束 2 的「只读」指不改规则、数据、内核与契约。批量运行器会推进模拟并**给每个决定预设推荐项**（`preset`，ADR-0008），与 `apps/cli/src/run-real-life.ts` 现有做法同类。实测：同一局用 `preset` 或 `decide` 推荐项，事实类型序列与决定完全相同，只有 `decision.made.decidedBy` 一个字段不同（`preset` / `player`）——所以它不改变人生路径。
- 约束 4 的「只有 `main` 定时运行」由 `schedule` 事件本身保证（GitHub 只在默认分支触发）。

### 4. 分层与抽样（本任务的实现细节）

- 层 = 国家 × 出生年代 × 城乡。国家取五地 `BIRTH_REGION_IDS`（默认全部）；年代取 1950、1960、…、2020（8 个，覆盖 1950—2026 的出生范围：2020s 层内出生年 2020—2026）；城乡取 `urban`、`rural`。默认 80 层，**每层局数相同**。
- 不做人口加权：一是约束 1；二是实测未加权抽样的城乡比例极偏（CN urban 39%、JP urban 83%、KP urban 55%、KR urban 64%、RU urban 67%），若按观测城乡事后分组，JP 的 `rural` 层只有约 17% 的样本、小层会随机塌缩，无法逐层给数。
- `selectBirth` 只按当年 `urban-share` 抽城乡，`BirthRequest` / `RealLifeRequest` 没有 settlement 覆盖（见「需要维护者决定的问题」1）。因此层内用**确定性拒绝抽样**：对每个「层 + 局序号」，从 `attempt = 0` 起依次尝试候选种子，直到 `session.birth.settlement` 等于该层城乡；单局尝试上限 `--max-attempts-per-life`（默认 200），超限记 `unreachableLives`。实测开销 1.72×，最费的层 125 局用了 1,547 次尝试；对 10,000 局总时长的影响已含在上面 59.4 s 里。
- 年代内的出生年：`year = decade + (i % span)`，`span = min(10, 2027 - decade)`（i 为层内局序号）。2020s 层因此覆盖 2020—2026，`i = 7` 回到 2020。不传 `birthDate`，月日仍由 `selectBirth` 从种子抽，保持出生日期分布连续。
- 种子：`<seedPrefix>-<country>-<decade>-<settlement>-<i>`，`attempt > 0` 时追加 `-r<attempt>`；`seedPrefix` 默认 `m5-001`。
- 顺序固定（指纹依赖它）：国家按命令行给出的顺序（默认 `BIRTH_REGION_IDS` 顺序）→ 年代升序 → 城乡 `urban` 先于 `rural` → 局序号升序。

### 5. 三个体验指标的口径，以及与 M5-002、GDD §3.3 的边界

三个指标全部逐国给出（`experience.byCountry`）、另有总体（`experience.overall`）。阈值取自 [V0.1_PLAN](../V0.1_PLAN.md) §2 与 D12，写进报告的 `experience.targets`，由 `experience.byCountry[].met` 计算达标布尔值；**退出码不受它影响**（见「实现要求 §7」）。

1. **每年可见事件数** = `Σ可见事实 / Σ在世年份`（pooled，主口径，与 §1 的「约 20 条 / 78 年」同口径）；另报每局各自的比值再取平均（`meanOfLifeMeans`，只作辅助，因为长命与短命权重不同）。P1 目标：pooled ≥ 1.5。
2. **无事件年份比例** = `没有任何可见事实的在世年份数 / Σ在世年份数`（pooled）。P1 目标：≤ 0.10（即 ≥ 90% 的年份至少 1 条可见事件）。
3. **每局可选决定数** = 每局在 `pauseOn` 枚举中遇到的**非 `background`** 决定里，`eligible` 选项 ≥ 2 的个数。报均值、中位数、以及 `selectableZeroShare`（一个可选决定都没有的人生占比）。P1：中位数 ≥ 5 且零决定占比 ≤ 0.10；P2：中位数 ≥ 8。
   - **不得用 `decision.made` 事实条数代替**：`background` 决定（例如 M3-041 的「年度重点」）不暂停、不面向玩家，但同样写 `decision.made` 事实。当前两者数值相等只因为年度重点尚未合并（实测每局 1.09—1.39 个 = 同时期的 `decision.made` 条数）；M3-041 合并后这个等式会失效。必须用引擎的 `pendingDecision` 枚举（`advanceTo({stopAtMajorDecision: true, pauseOn})` 的返回值）。
   - 1 个合格选项的决定不算「可选」（没有选择），不计入。

- 逐国聚合一律从**逐局原始值**重算，不把已四舍五入的层值相加。

边界：

- **M5-002（统计校准指标与容差）** 管的是模型与真实统计的偏差（年龄别死亡率 vs 生命表、教育分布、生育、经济等），由 D10 声明逐指标容差；**不包含**上面三项体验指标。若维护者要把这三项形式化进门禁，应在 M5-002 里另行声明并由 M5-001 的报告提供字段，本任务只提供测量，不声明容差、不判定发布资格。
- **GDD §3.3 事件重复率** 是内容扩容信号，不是校准指标，也不是体验指标的一部分：它衡量**多样性**，三项体验指标衡量**密度与选择机会**（同一 `templateId` 反复出现可以保持密度却仍然单调）。`repetition` 单独成块、不设阈值、不参与 `met`。
- 报告里体验类字段统一放在 `experience.*`、重复率放在 `repetition.*`，不与 M5-002 的校准指标混用同一命名。

### 2. 分层、出生年与种子（`strata.ts`）

```ts
export type Settlement = 'urban' | 'rural';

export interface BatchConfig {
  countries: readonly BirthRegionId[]; // 默认 BIRTH_REGION_IDS
  decades: readonly number[]; //          默认 [1950, 1960, …, 2020]
  settlements: readonly Settlement[]; //  默认 ['urban', 'rural']
  livesPerCell: number; //                默认 1，必须为 ≥ 1 的整数
  seedPrefix: string; //                  默认 'm5-001'
  maxAttemptsPerLife: number; //          默认 200，必须 ≥ 1
}

export interface Stratum {
  country: BirthRegionId;
  decade: number;
  settlement: Settlement;
}

export function decades(): readonly number[]; // 1950..2020 步长 10
export function enumerateCells(config: BatchConfig): Stratum[]; // 顺序见「背景 §4」
export function yearFor(decade: number, lifeIndex: number): number; // decade + (lifeIndex % span)
export function seedFor(cell: Stratum, lifeIndex: number, attempt: number, prefix: string): string;
```

- `span(decade) = Math.min(10, 2027 - decade)`（2020s → 7）。
- `seedFor` 的输出必须满足：`attempt === 0` 时等于 `<prefix>-<country>-<decade>-<settlement>-<i>`，否则追加 `-r<attempt>`；同一层内不同 `i` 的种子互不相同。

### 3. 单局流程（`run.ts`）

对每个层、每个 `i`：

1. 拒绝抽样：从 `attempt = 0` 起，用 `seedFor` 与 `yearFor` 调 `createRealLifeSimulation({ seed, region: country, year })`；若 `session.birth.settlement === cell.settlement` 则接受。构造抛错（例如该年出生权重缺失）→ 记一条错误、该层计 1 个失败尝试并继续下一局；`attempt > maxAttemptsPerLife` → 该层 `unreachableLives++`，继续下一局。**任何情况下都不整体中断批量运行。**
2. 计时开始（`performance.now()`），推进：

```ts
for (;;) {
  const result = simulation.advanceTo({
    targetDate: '2200-01-01',
    stopAtMajorDecision: true,
    pauseOn, // 'all'（默认）或 'major'
    maxWorkUnits: 200_000,
  });
  const pending = result.pendingDecision;
  if (result.stopReason === 'major-decision' && pending) {
    decisions.push({
      type: pending.type,
      at: pending.at,
      eligible: pending.options.filter((o) => o.eligible).length,
    });
    simulation.preset(pending.key, pending.recommended.optionId); // ADR-0008
    continue;
  }
  if (result.stopReason === 'work-budget-exhausted') throw new Error('work-budget-exhausted');
  break;
}
```

3. 计时结束（`perLifeMs`）。之后再做快照序列化与指标统计（与 `bench.ts` 一致，不计入 `perLifeMs`）。
4. `try/catch` 包住第 2 步：`SimulationError` 且 `code === 'invariant-violation'` → `invariants.violations++`，并把该局计入 `invariants.lives`；其他错误 → `errors.count++`。两条都记一条样本（最多 10 条）：`{ seed, code, eventKey, at, message }`（`message` 截断到 200 字符）。
5. 该局失败时仍计入 `achievedLives`，但不计入 `completedLives`，其事实与指标也不进入体验指标与 `facts` / `repetition` / `death` / `snapshots` / `timing` 的统计（计时只覆盖跑完的局）。

`run.ts` 的对外形状（`BatchOptions.createSession` 是**测试夹具入口**，不得在 CLI 参数里暴露）：

```ts
export interface SessionLike {
  // 结构类型：只要求这四个成员，测试夹具才能不构造完整 Simulation。
  simulation: Pick<Simulation, 'advanceTo' | 'preset' | 'facts' | 'snapshot'>;
  birth: BirthContext; // @lifesim/country-packs 的 BirthContext（要 settlement / birthDate / packId）
}

export interface BatchOptions extends BatchConfig {
  pausePolicy: 'all' | 'major';
  out?: string; //                           缺省不写文件
  createSession?: (seed: string, country: BirthRegionId, year: number) => SessionLike; // 默认 createRealLifeSimulation
}

export function runBatch(options: BatchOptions): BatchReport; // 同步执行；options.out 存在时先写文件再返回
```

### 4. 指标定义（`measure.ts`）

```ts
export interface LifeMetrics {
  years: number; //                 在世年份数
  visibleFacts: number; //          可见事实条数
  emptyYears: number; //            没有可见事实的在世年份数
  decisions: { total: number; selectable: number }; // 引擎枚举的决定数 / 其中合格选项 ≥ 2 的个数
  decisionFacts: number; //          fact.type === 'decision.made' 的条数（只作诊断，不得当可选决定数）
  snapshotBytes: number; //          Buffer.byteLength(JSON.stringify(snapshot), 'utf8')
  ageAtDeath: number | null; //      summarizeLife(...).ageAtDeath
  aliveAtEnd: boolean; //           ageAtDeath === null
  byType: Record<string, number>; // 全部事实按 type 计数（含 finance.settlement；报告的 facts.byType 用它）
  templateCounts: Record<string, number>; // 可见事实按 templateId 计数
}
```

规则：

- 可见事实：`fact.type !== 'finance.settlement'`（`decision.made` 计入）。不得再加别的过滤；常量放进 `measure.ts` 并在 `docs/QA_BATCH_REPORT.md` 说明。
- `years` = `endYear - birthYearYear + 1`：`birthYear` 取 `session.birth.birthDate` 的年份，`endYear` 取 `summarizeLife(...).deathDate` 的年份；`deathDate === null` 时取 `snapshot.at` 的年份（并置 `aliveAtEnd = true`，报告里 `death.aliveAtEnd` 合计应为 0）。
- 空年份：对 `birthYear..endYear` 的每个年份，若没有任何可见事实落在该年，计 1。
- 年/月日一律从事实的 `at` 前 4 位取年份（`ISODate` 是 `YYYY-MM-DD`）。

### 6. 指纹与基线比较

- `fingerprint.workload`：按层顺序与局序号升序，对每个**接受**的局做
  `fp = fingerprint(fp + fingerprint(canonicalJson(facts)))`（空串起，与 `bench.ts` 的链式指纹同构）。
- `fingerprint.metrics`：`fingerprint(canonicalJson(projection))`，`projection` 是报告去掉 `command`、`machine`、`timing`、`comparison`、`fingerprint` 以及 `workload.totalMs` / `workload.livesPerSecond` 之后的整份对象。
- 确定性要求：同参数两次运行，`fingerprint.workload` 与 `fingerprint.metrics` 必须完全相同（耗时与机器信息不参与）。
- `--baseline <path>`：读入一份旧报告，产出 `comparison`：

```jsonc
{
  "baseline": {
    "schemaVersion": 1,
    "command": "…",
    "fingerprint": { "workload": "…", "metrics": "…" },
  },
  "verdict": "comparable", // 或 "incomparable"
  "reasons": [], //          incomparable 时列出差异路径，例如 "config.livesPerCell: 2 → 1"
  "metrics": [
    {
      "metric": "experience.overall.visiblePerYear.pooled",
      "current": 0.24,
      "baseline": 0.3,
      "delta": -0.06,
      "deltaPct": -20,
    },
  ],
}
```

可比性要求 `schemaVersion`、`versions.engine`、`versions.systems`、`versions.dataPacks` 与 `config` 全部相同；否则 `verdict = "incomparable"`，`metrics` 仍列出但消费方**不得**据此判定回归。
比较的指标固定为：`facts.meanPerLife`、`facts.meanVisiblePerLife`、`experience.overall.visiblePerYear.pooled`、`experience.overall.emptyYearRatio.pooled`、`experience.overall.decisions.selectableMedian`、`experience.overall.decisions.selectableZeroShare`、`snapshots.meanBytes`、`repetition.overall.withinLifeRepeatedShare`、`death.meanAgeAtDeath`，以及 `timing.perLifeMs.p50` / `p95`（**只在同一机器上比较才有意义**，报告里注明）。

### 7. CLI 参数与退出码（`batch.ts`）

```text
pnpm --filter @lifesim/cli batch [选项]

  --lives-per-cell <n>        每层局数，默认 1（80 层 → 80 局；2 → 160 局；125 → 10,000 局）
  --countries <CN,JP,...>     默认五国全部；顺序即层顺序
  --decades <1950,1980>       默认 1950,1960,…,2020；取值必须是 1950—2020 之间 10 的倍数
  --settlements <urban,rural> 默认两者
  --pause-policy <all|major>  默认 all
  --seed-prefix <s>           默认 m5-001
  --max-attempts-per-life <n> 默认 200
  --out <path>                把报告写到文件（省略则把完整 JSON 打到 stdout）
  --baseline <path>           读入旧报告并附上 comparison
  --help                      打印用法，退出 0
```

- 退出码：`0` = 报告生成成功且 `invariants.violations === 0 && errors.count === 0`；`1` = 有违规/错误（**报告仍必须写出**，先写文件再设退出码）；`2` = 用法或配置错误（非法参数、未知国家、年代非法、读不到 `--baseline`、写报告失败）。
- 指定 `--out` 时 stdout 只打印一行摘要（`wrote <path> · <totalLives> lives · evidence <fingerprint.workload>`），未指定时打印完整 JSON；诊断信息走 stderr。
- CLI 里**不得**另写退出码逻辑，只能 `process.exitCode = reportExitCode(report)`。

## 验收测试

全部落在 `apps/cli/src/batch.test.ts`（只新增；不改 `cli.test.ts`）。集成用例用最小配置（1 国 × 1 年代 × 1 城乡 × 2 局）以免拖慢 CI；另有一个 80 层冒烟用例（`--lives-per-cell 1`，单测超时 30 s）。

1. **层枚举与推导**：默认配置得到 80 层，顺序为「国家按 `BIRTH_REGION_IDS` → 年代升序 → urban 先于 rural」；`--countries CN --decades 1970 --settlements rural` 得到 1 层。
2. **出生年**：`yearFor(1970, 0) === 1970`、`yearFor(1970, 13) === 1973`；2020s 层 `i = 0…6` 得 2020—2026、`i = 7` 得 2020。
3. **种子**：`seedFor` 的 `attempt = 0` 无后缀、`attempt = 2` 追加 `-r2`；同一层 `i = 0…9` 的种子互不相同。
4. **可见事实与年份**（夹具事实，测试文件里标明是夹具）：`birthDate 1970-05-01`、`deathDate 1975-02-03` 时 `years === 6`；6 年里只有 1970 与 1974 有可见事实 → `emptyYears === 4`、`emptyYearRatio === 4/6`；1 条 `finance.settlement` 不计入可见事实、但计入 `facts.byType`。
5. **可选决定不数事实**：夹具里放 2 条 `decision.made` 但传入 `decisions: { total: 0, selectable: 0 }` → `selectable === 0`、`decisionFacts === 2`（证明两者分开）。
6. **percentile / median / round**：`percentile([1…100 的升序], 50/95/99)` = 50 / 95 / 99，`max` = 100；`median([1,2,3,4]) === 2.5`、`median([1,2,3]) === 2`；`round(0.12345, 4) === 0.1235`。
7. **快照字节与死亡分桶**：`snapshotBytes` 等于 `Buffer.byteLength(JSON.stringify(snapshot))`；年龄 4 / 5 / 94 / 95 分别落 `[0,4]` / `[5,9]` / `[90,94]` / `[95,null]`。
8. **重复率**：夹具可见事实 `templateId` 为 `['a','a','b']` → `withinLifeRepeatedShare === 2/3`、`distinctTemplates === 2`。
9. **确定性**：同参数两次 `runBatch`（最小配置）→ `fingerprint.workload` 与 `fingerprint.metrics` 相同，且把 `timing`、`machine`、`command` 删掉后两份报告深度相等；改 `livesPerCell` 或 `seedPrefix` → `fingerprint.workload` 不同。
10. **不变量违规计入并使命令失败**（骨架验收要点）：往 `runBatch` 注入一个测试专用 `createSession`（测试夹具，在测试里标明），返回的模拟在第一次推进时抛 `new SimulationError('invariant-violation', …, { seed })` → `report.invariants.violations > 0`、`report.invariants.lives > 0`、`report.errors.count === 0`、`reportExitCode(report) === 1`，且 `--out` 指向的文件已写出。再注入一个抛 `handler-failed` 的夹具 → `errors.count > 0`、`invariants.violations === 0`、退出码 1。
11. **不可达层**：注入总是返回 `settlement: 'urban'` 的夹具并只跑 `rural` 层 → 该层 `unreachableLives === requestedLives`、`achievedLives === 0`、`achievedLives + unreachableLives === requestedLives`，报告不抛错、退出码仍为 0（数据驱动，不算失败），并出现在 `workload.layers` 里。
12. **基线比较**：`compareReports` 对「只改数字」的两份夹具报告给出 `verdict: 'comparable'` 与 `delta`/`deltaPct`；对「改 `config.livesPerCell`」或「改 `versions.engine`」给出 `verdict: 'incomparable'` 且 `reasons` 含对应路径。
13. **报告自洽**：`Σ layers.achievedLives === workload.totalLives`；`Σ layers.completedLives === workload.completedLives`；每层 `achievedLives + unreachableLives === requestedLives`；每层 `p50 ≤ p95 ≤ p99 ≤ max`；`experience.overall.years === Σ byCountry.years`；80 层冒烟用例里每层 `requestedLives === 1` 且 `invariants.violations === 0`、`errors.count === 0`（当前数据下 `unreachableLives` 全为 0，但不写死成断言）。
14. **CLI**：`node src/batch.ts --countries CN --decades 1970 --settlements urban --lives-per-cell 2 --out <临时文件>` 退出码 0、文件可解析、stdout 含 `wrote`；`--lives-per-cell 0`、`--countries XX`、`--decades 1949`、`--pause-policy foo`、`--baseline <不存在>` 退出码 2 且 stderr 有说明；不带 `--out` 时 stdout 是完整 JSON（可直接 `JSON.parse`）。
15. **现有测试不变**：`pnpm test` 全绿、`pnpm check:tests` 通过（新增测试只增不减，不改 `qa/test-baseline.json`）。

## 可能的阻塞

1. **真实国家包批量太慢**（骨架原列）：已实测本项目当前状态下 10,000 局（80 层 × 125）耗时 59.4 s、p50 6.0 ms/局，**不成立**。若实施后实测 p50 > 60 ms/局（慢 10 倍以上），先报告，不要自行缩小夜间规模或删字段。
2. **某层不可达**：该年代城乡比例导致目标城乡抽不到时记 `unreachableLives`，不失败。若夜间出现 > 1% 的层不可达，报告给维护者判断分层是否仍合理；不要自行改成人口加权或合并层。
3. **报告字段不够 M5-002 用**：由 M5-002 在自己的任务里升 `schemaVersion` 扩展，本任务不预埋空字段。
4. **M3-041/M3-042 合并后口径要复核**：年度重点（`background` 决定）会新增事实类型、且 `decision.made` 条数不再等于可选决定数。实施时若与「背景 §5」的定义冲突，停下报告，不要私改口径。
5. **CI 跑不了 `pnpm`**：本机没有全局 node/pnpm，命令都要带 `PATH`；CI 上由 `pnpm/action-setup` + `.nvmrc` 提供，不要改成 `npm`/`npx`。
