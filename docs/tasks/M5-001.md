## 目标

GDD §14.2：每次提交 100—500 局轻量回归、夜间约 1 万局、发布候选 5—10 万局。现在只有合成地区的 `pnpm bench`；没有面向五个真实国家包、按国家/年代/城乡分层的批量运行与报告。

## 已定的约束

1. 种子与分层确定（国家 × 出生年代 × 城乡），**不按五国人口加权后忽略小国**（GDD §9.3）；同一参数两次运行的报告指纹相同。
2. 只读模拟结果，不改规则与数据；不联网；`packages/*` 不引入非确定性 API。
3. 报告是 JSON，字段至少包括：每层局数、每局耗时 P50/P95/P99、事实数、快照字节、不变量违规数（必须为 0）、死亡年龄分布、事件重复率（GDD §3.3 用它决定内容扩容）。
4. 夜间任务只在 `main` 上定时运行，失败时 CI 标红并保留报告产物；不阻塞普通推送的 CI。

## 需要细化的内容

报告 schema、分层表、CLI 参数、夜间任务的规模与超时（先在本机测吞吐量再定）、报告与基线的比较方式。

## 验收要点

- 固定参数两次运行指纹相同；故意注入一个违规（测试夹具）时报告计数非零且命令退出码非零；
- 本机 1 万局的耗时记录在报告与任务完成报告里。

## 可能的阻塞

真实国家包的批量运行太慢（报告实测数字，交给 Claude Code 判断是否需要内核优化）。
