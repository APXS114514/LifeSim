## 目标

让玩家能手动备份、导出文件、导入恢复；导入必须经过完整校验（大小、UTF-8、危险键、schema、校验和、日志不变量、版本兼容），损坏文件被安全拒绝且不影响当前游戏。

## 背景

- GDD §2 决定 19：自动存档、导入导出；§11.1 要求浏览器存储不绝对可靠，提供明确备份提示与导出文件。
- `encodeSave` / `decodeSave` 已实现，但界面没有入口。
- 导入时不能「部分导入」；不能为了恢复旧存档而改随机算法或数据版本（GDD §9 / 用户指令）。

## 实现要求

1. **导出**：调用 `encodeSave`（`exportedAt` 由界面传入当前时间），触发浏览器下载，文件名含地区、出生年、日期（ASCII 安全）；导出后提示「已备份」。
2. **导入**：
   - 读取文件（限制大小，超过上限直接拒绝）；
   - 调用 `decodeSave` 并映射错误码到双语提示；
   - 版本不兼容（engine/systems/dataPack）→ 拒绝并说明；
   - 导入成功 → 写入 IndexedDB（M4-001）并在确认后载入会话；**不得**覆盖现有存档除非用户明确选择。
3. **恢复**：从存档列表选择一局 → 载入并继续；载入失败时保持当前会话不变。
4. **安全**：不接受非本格式文件；解析不执行任何代码；错误信息不回显原始内容（避免注入）。
5. **可访问性**：按钮可键盘操作、有 aria-label；移动端菜单可关闭。
6. **i18n**：所有提示、按钮、错误原因都有 zh-Hans 与 en。

## 验收测试

1. 单元：导出 → 导入往返，快照/事实逐字节相同。
2. 错误映射：8 种 `SaveDecodeError` 各一个夹具，断言提示键正确。
3. 版本不兼容：伪造 engineVersion 不同的信封 → 拒绝且当前会话不变。
4. 大文件：超过上限的文件被拒绝，耗时 < 1 秒（不做主观性能承诺，只断言不崩溃）。
5. E2E：导出后刷新页面、导入、继续游戏，事实数与导出前一致；损坏文件导入后页面仍可玩。
6. 双语：新增文案键在两种语言都存在且占位符一致。
