# M2-010：转换 WPP 2024 年出生数

| 项       | 内容                                                                |
| -------- | ------------------------------------------------------------------- |
| 风险     | 高（真实数据）：PR 需维护者审查并加 `arch-approved` 标签            |
| 前置依赖 | M2-001、M2-005、M2-009（且维护者已确认 `un-wpp:2024` 为 `allowed`） |
| 涉及模块 | `data/scripts/wpp2024/`、`packages/country-packs/data/`             |
| 预计改动 | 新增 3 个脚本文件、5 个数据文件                                     |
| 特殊要求 | 需要下载 M2-009 登记的官方文件；无法下载就报告阻塞                  |

## 目标

用一个可复现的脚本，从 WPP 2024 官方 CSV 中取出五个地区 1950—2100 年的年出生数，写成 `StatSeries` 数据文件。出生数用于随机出生地区的加权（GDD §4.3）。

## 背景（只需知道这些）

- 数据格式：M2-001 的 `StatSeriesSchema`；单位 `thousand-persons`（WPP 以千人为单位，**原样保留，不换算、不取整**）。
- WPP 2024 中 1950—2023 年是估计，2024—2100 年是预测（`projected: true`）。证据等级 B（权威机构模型估计）。
- 地区与 WPP 地点代码（`LocID`，即 ISO 3166-1 数字代码）及 WPP 中的地点名称：

  | packId | LocID | WPP 中的名称（须核对）          |
  | ------ | ----- | ------------------------------- |
  | CN     | 156   | China                           |
  | JP     | 392   | Japan                           |
  | KP     | 408   | Dem. People's Republic of Korea |
  | KR     | 410   | Republic of Korea               |
  | RU     | 643   | Russian Federation              |

  WPP 的 `China` 指中国大陆（不含港澳台），与 GDD 的 `CN` 一致；`Russian Federation` 是按今天的领土回溯的序列，1991 年以前同样适用于 `RU` 地区（领土与政治实体分开，见 GDD §5）。

## 实现要求

### `inputs.json`

```json
[
  {
    "id": "demographic-indicators",
    "file": "<官方文件名>",
    "url": "<官方下载链接>",
    "sha256": "<文件的 SHA-256>",
    "retrievedAt": "<YYYY-MM-DD>"
  }
]
```

### `births.mjs`

导出纯函数（供测试），并在 `import.meta.main` 时执行：

```js
/**
 * @param {Record<string, string>[]} records  readCsvRecords 的结果
 * @param {'CN'|'JP'|'KP'|'KR'|'RU'} packId
 * @returns {import('../../../packages/content-schema/src/index.ts').StatSeries}
 */
export function toBirthSeries(records, packId);
```

1. 在 CSV 表头中找到这些列：地点代码、地点名称、年份、方案、出生数（WPP 文件中通常名为 `LocID`、`Location`、`Time`、`Variant`、`Births`）。**列名与此不同时，停止并报告**，不要猜。
2. 只取 `LocID` 等于上表代码、方案为 `Medium` 的行；若文件没有方案列，报告阻塞。
3. 所选行的地点名称必须与上表一致，不一致就抛错（防止取错地区）。
4. 年份必须恰好覆盖 1950—2100、每年一行；缺年、重复、出生数不是有限数字，都抛错（消息包含年份）。
5. 输出：
   - `id: 'wpp2024/<packId>/births'`，`indicator: 'births'`，`geographyId: 'country:<packId>'`，`unit: 'thousand-persons'`，`ageBasis: 'none'`，`sex: 'both'`；
   - `evidence: { grade: 'B', sourceIds: ['un-wpp:2024'], modelVersion: 'wpp2024-medium', geographyId: 'country:<packId>', yearRange: [1950, 2100], methodId: 'wpp2024-demographic-indicators' }`；
   - `points`：按年份升序，`age: null`，`value` 为 CSV 中的数值（`Number(...)`），`projected: year >= 2024`。
6. 返回前用 `StatSeriesSchema.parse` 校验。

命令行：`node data/scripts/wpp2024/births.mjs --input <文件路径>`

1. 计算输入文件的 SHA-256，与 `inputs.json` 中的记录比较，不一致就退出码 1。
2. 用 `readTextFile` 读取（支持 `.gz`），`readCsvRecords` 解析，对五个地区调用 `toBirthSeries`。
3. 写入 `packages/country-packs/data/<packId>/wpp2024-births.json`，内容为 `JSON.stringify(series, null, 2) + '\n'`。
4. 打印每个地区的点数与 1950、2000、2023、2024 四年的值。

## 验收测试（必须新增，写在 `births.test.ts`）

用一小段**夹具 CSV**（注释标明「测试夹具，数值虚构」，包含一个带逗号的地名行与一个其他地区的干扰行）：

1. 只选出指定地区的 Medium 行，结果通过 `StatSeriesSchema`。
2. 2023 年 `projected: false`，2024 年 `projected: true`。
3. 地点名称不符、缺一年、出生数非数字，各自抛错且消息含年份或地区。
4. 输出按年份升序，即使夹具里的行是乱序的。
5. 若仓库里已有 `packages/country-packs/data/*/wpp2024-births.json`：每个文件都通过 `StatSeriesSchema`，恰好 151 个点，所有值 > 0。

为了让测试覆盖 151 年，夹具可以用代码生成行；只要清楚标明是夹具。

## 可能的阻塞（遇到就停止并报告）

- `un-wpp:2024` 在 `data/sources.json` 中不是 `allowed`。
- 下载不到 M2-009 登记的文件，或文件列名、方案名与本文不同。
- 某个地区的名称或年份覆盖与本文不符。
