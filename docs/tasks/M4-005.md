## 目标

提供逐年推进、自动推进（可调速）、快进到下一个重大事件/死亡、暂停与取消；所有方式最终调用同一个 `advanceTo`，暂停或取消不破坏模拟状态。

## 背景

- GDD §2 决定 02：逐年、快进、自动推进共用同一模拟路径；重大事件暂停。
- GDD §10：长快进时展示进度及可取消。
- 内核与 Worker（M4-004）已提供推进与取消；本任务只做控制状态机与界面。
- 关键不变量：单一权威状态在 Worker；控制器不缓存事实之外的派生状态。

## 实现要求

1. **状态机**：`idle → running → paused → running → … → ended`；`cancelling` 为过渡态。非法转换（例如暂停中再次暂停）必须是幂等而不是报错。
2. **模式**：
   - 逐年：推进到下一个生日（或下一个重大决定/死亡，以先到者为准）；
   - 自动：逐年推进 + 可调间隔（例如 200/500/1000 ms 或「瞬间」），遇到重大决定暂停；
   - 快进：推进到下一个重大决定或死亡，显示进度（日期 + 已处理事件数）；
   - 暂停：停止自动推进，保留状态；
   - 取消：中止当前快进/自动，状态可继续。
3. **一致性**：三种推进方式在同一 request 下产生的事实在测试中逐字节相同。
4. **响应性**：快进时按钮可点击、进度条更新；不得阻塞主线程（依赖 M4-004）。
5. **持久化**：每次稳定停止（重大决定、暂停、死亡）后触发自动存档（M4-001/002），不中断模拟。
6. **可访问性**：按钮有 aria-label 与键盘快捷键（空格暂停/继续），移动端触控目标 ≥ 44px。
7. **i18n**：所有按钮、状态、进度文案双语。

## 验收测试

1. 状态机单元测试：所有转换与幂等性。
2. 一致性：逐年 vs 自动 vs 快进的最终事实指纹相同（用内存通道，不依赖真实计时）。
3. 暂停/取消：中途暂停再继续，事实不重复不丢失；取消后可以再次快进。
4. 重大决定：自动推进遇到重大决定时停止，按钮状态变为「等待选择」。
5. 自动存档：每次稳定停止后仓库被调用一次（用 spy）。
6. E2E：点击快进 → 出现进度 → 暂停 → 继续 → 死亡总结；无控制台错误。
7. 双语：切换语言后控制文案变化、模拟结果不变。
