## 目标

用一组验收测试证明 M2 的退出条件（GDD §13）：「五地任何出生年均能实例化；苏联—俄罗斯历史映射正确；缺失数据不会默默等于零」，并覆盖各地区的币制与行政边界日期。**只写测试，不改任何实现。**

## 背景（只需知道这些）

- 实例化 = `selectBirth` 返回合法的 `BirthContext`（M2-021）。
- 各地区的边界日期由国家包定义（M2-014 至 M2-018）。测试中的边界日期**从国家包数据里读取**（锚点日期、归属的有效期），不要在测试里重新写死另一套日期——这样测试检验的是「行为与数据一致」。
- 测试失败说明实现或数据有问题：**报告，不要修改实现、数据或放宽断言。**

## 实现要求

在 `acceptance.test.ts` 中写以下测试（每组一个 `describe`）：

1. **逐年实例化**：对每个地区、1950—2026 的每一年，用种子 `accept-<地区>-<年份>`（例如 `accept-CN-1950`）调用 `selectBirth({ seed, region, year })`：不抛错；返回的出生日期在该年内；`placeId` 是该地区的人口池地点之一；`adminUnitId` 与 `politicalEntityId` 等于用 `resolve.ts` 在该日期解析的结果；`currency` 等于 `currencyAt` 的结果。
2. **随机地区逐年**：对 1950—2026 每一年，`region: 'random'` 不抛错，且 `provenance.regionWeights` 的五个值都是正数。
3. **政体与名称边界**：对每个国家包中的每个 `polity-change` 锚点，用 `birthDate` 指定锚点前一天与当天，断言政治实体分别为 `fromEntityId` 与 `toEntityId`，而 `placeId` 与 `adminUnitId` 不变。
4. **币制边界**：对每个国家包中的每个 `redenomination` 锚点，锚点前一天与当天的 `currency.version` 分别为 `fromVersion` 与 `toVersion`。
5. **行政归属边界**：对每个国家包中有多段归属的地点，用 `resolve.ts` 断言每段起始日的前一天与当天属于不同的行政单位或政治实体（这一组不调用 `selectBirth`，因为城市不会被随机选中）。
6. **城镇比例的来源标记**：对每个地区，1950 年 `provenance.urbanShare.method` 不是 `'exact'` 时，其证据等级必须是 C 或 D（即回退结果被如实标注）；各地区在其城镇比例最早非 null 年份的 `method` 是 `'exact'`。
7. **没有静默的 0**：上面所有结果中，`provenance` 里的数值都大于 0。
