## 目标

用 IndexedDB 实现正式的本地存档：按 `SaveRepository` 契约保存快照与事实、支持多局存档、记录请求参数与版本元数据、校验 request/snapshot/facts 的对应关系。localStorage 只作为迁移来源（M4-002）。

## 背景

- GDD §2 决定 19：IndexedDB 本地优先，自动存档、导入导出，预留可选云同步接口（v0.1 不实现云）。
- 现状：`apps/web/src/game/storage.ts` 只有一个 localStorage 键 `lifesim.save.v1`，存 `{version, request, snapshot, facts}`；无法多局、无元数据、配额小。
- `packages/save` 已有 `SaveRepository` 接口与导入导出信封（`encodeSave/decodeSave`），但接口是抽象的，没有 IndexedDB 实现。
- 领域包（`packages/*`）不得使用浏览器存储；实现必须放在 `apps/web`。
- 存档的权威内容仍是快照 + 事实日志；UI 不得另存一份「权威状态」。

## 实现要求

1. **数据库**：`lifesim`，版本 1，对象仓库 `saves`（keyPath `id`）与 `facts`（keyPath `saveId` + `sequence`，按 `saveId` 分片）。索引：`updatedAt`。
2. **记录结构**：每条存档包含
   - `id`（稳定 ID，可用种子 + 出生参数派生 + 单调后缀）；
   - `request`（`RealLifeRequest`，恢复时必须能重建同一 region）；
   - `snapshot` 与 `facts`；
   - `meta`：`engineVersion`、`systemsVersion`、`dataPackVersions`、`lastJournalSequence`、`factCount`、`sizeBytes`、`sha256`、`createdAt`（ISO，来自调用方时间）、`updatedAt`。
3. **写入**：自动保存 debounce（例如 500 ms）由调用方控制；写入用事务保证快照与事实一致；失败（配额、被禁用）必须抛可识别的错误，不得静默吞掉。
4. **读取**：读取时用 `SimulationSnapshotSchema`、`SimEventFactSchema`、`checkJournalInvariants` 校验；`lastJournalSequence` 必须等于最后一条事实的 `sequence`；request 与 snapshot 的 `activeCharacterId`/出生日期必须一致。
5. **多局**：支持列出存档摘要（不含完整事实），按 `updatedAt` 倒序；删除单局；不实现云同步。
6. **接口**：优先实现 `packages/save` 的 `SaveRepository` 方法；若接口签名不适合多局（`saveId` 参数），在报告里说明并保持行为等价，不要改接口。
7. **时间**：`createdAt/updatedAt` 用 `new Date().toISOString()` 一类调用方时间；**不得**让时间影响模拟结果。

## 验收测试

1. 单元（fake-indexeddb 或等价夹具）：写入 → 读取 → 快照/事实逐字节相同；删除后读不到；多局按时间倒序。
2. 校验：篡改快照（改余额）但保留 checksum → 读取被拒绝；删除一条事实导致序号断裂 → 被拒绝；request 与 snapshot 出生日期不符 → 被拒绝。
3. 事务：写入过程中模拟配额错误，断言不留下半条记录。
4. 与 `GameSession.serialize()` 的兼容：从仓库记录构造的会话推进 5 年，与不中断会话一致。
5. 现有 `session.test.ts` 通过；新增测试不弱化旧断言。
6. （若加了 devDependency）`pnpm notices` 更新且 `pnpm check:licenses` 通过。
