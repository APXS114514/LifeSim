# M3-017：婚恋、婚姻与离婚

| 项       | 内容                                                                                        |

## 目标

实现「认识 → 交往 → 结婚 → 分居/离婚/丧偶」的连续路径：伴侣是独立 NPC，有自己的意愿与状态；玩家可以追求但不能强制；婚姻、离婚、丧偶改变关系图、共同居住与家庭结构。

## 背景

- GDD §8.4：法律婚姻、情感关系、共同居住、亲生亲属、收养与抚养责任分离；双方各有信任、亲密、价值观与冲突状态；玩家可协商不能控制 NPC；不婚是合理路径。
- 性别未决（Q1）：**不得**假设配偶性别，也不得按性别分配概率。伴侣用 `relation: 'spouse'` 与角色 ID 标识。
- 法定婚龄：各国各年代不同（例如中国大陆 1950 年婚姻法、日本 1947 年民法、韩国民法、苏联/俄罗斯 1965/1968 年婚姻家庭法）。没有性别字段时使用**该国当年的单一最低婚龄**（取当时法规中最低年龄的较大值），在 ADR/任务报告里写明这一简化。
- 关系契约目前没有「交往」种类：本任务允许把 `partner` 加进 `RELATIONSHIP_KINDS`，并同步 M3-002 的测试。

## 实现要求

1. **伴侣实例化**：成年后按年度概率（来源或 D 级表）遇到潜在伴侣；创建 Tier1 NPC（ID `char:<主角>:partner-1`，再婚时序号递增），带年龄、学历、职业、健康与人生原则；**不得**在之后升级时重抽这些字段。
2. **交往**：建立 `partner` 关系，双方 `bonds` 随事件（相处、冲突、支持）变化；冲突高到阈值时可能分手（关系 `until` 置为当天）。
3. **婚姻**：
   - 玩家可以在重大决定里选择结婚/不婚；NPC 是否同意由**它自己的**关系与原则决定（不得无条件接受）；
   - 满足婚龄与关系阈值才可结婚；结婚登记产生事实、把 `partner` 关系结束、建立 `spouse` 关系（`until: null`），双方 `coResident` 置 true；
   - 不婚、晚婚、再婚都必须可发生。
4. **离婚与分居**：冲突、经济压力、疾病等因素提高离婚概率；离婚产生 `former-spouse` 关系（`until` 为离婚日）、`coResident: false`，并产生事实；资产分割留给 M3-014 的口径，本任务只记录「共同账户/账户是否共享」的现状，不发明分割规则。
5. **丧偶**：配偶死亡时把 `spouse` 关系 `until` 置为死亡日、`coResident: false`，产生 `family.widowed` 事实（原因指向配偶死亡事实），并影响主角关系/健康（乘数由 M3-016 消费）。
6. **状态不变量**：同一角色最多一条有效 `spouse`（M3-002 已有）；离婚后不得再出现有效 `spouse` 与同一人；死者不得发起婚恋事件。
7. **不重抽**：伴侣在升级为更深模拟时（M3-011 的 `promoteToTier1`）保留已确定字段。

## 验收测试

1. 婚龄：1950 年与 2000 年出生者最早结婚年龄不同（至少 2 国断言）；未达婚龄时结婚选项 `eligible: false`（`ineligibleReason: 'under-marriage-age'`）。
2. NPC 自主：构造低关系值夹具，求婚被拒（事实为 `family.marriage-refused`），关系图不产生 `spouse`。
3. 离婚：离婚后关系为 `former-spouse` 且 `until` 正确，`coResident: false`，主角不能再对同一人发起「结婚」（必须有新关系）。
4. 丧偶：配偶死亡后关系 `until` === 死亡日，产生事实，且主角后续不再为该配偶安排任何事件。
5. 不婚路径：固定 seed 下存在不婚角色（至少 10 局里有 1 局），说明这不是必经路径。
6. 确定性：同 seed 两次运行一致；快照往返一致。
7. 双语：全部新增事实在 zh/en 渲染无残留占位符。
