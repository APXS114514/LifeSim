## 目标

从 WPP 2024 单岁生命表（男女合计）取出五个地区 1950—2100 年、0—100 岁的死亡概率 `qx`，写成 `StatSeries`。它将是 M3 死亡风险的基线（GDD §8.3）。

## 背景（只需知道这些）

- `qx`：活到 x 岁的人在 x 岁到 x+1 岁之间死亡的概率；单位 `probability`，年龄口径 `single-year`。
- 100 岁是开口组（100 岁及以上），按定义 `qx = 1`。
- WPP 2024 的单岁生命表通常分为两个文件：1950—2023 年（估计）与 2024—2100 年（预测）。两个文件都要读，合并成一个序列。
- 地区代码与名称对照、领土说明：与 M2-010 相同（CN 156、JP 392、KP 408、KR 410、RU 643）。
- **只用男女合计**（ADR-0005 §3）；不要读取分性别的文件。

## 必读文件

- `data/LICENSE_AUDIT.md`（文件名与下载入口）
- `data/scripts/wpp2024/births.mjs` 与 `inputs.json`（M2-010 的写法，照同样的结构写）
- `data/scripts/lib/csv.mjs`、`data/scripts/lib/files.mjs`
- `packages/content-schema/src/series.ts`

## 允许修改

- `data/scripts/wpp2024/inputs.json`：追加两条输入记录（`life-table-both-1950-2023`、`life-table-both-2024-2100`）
- 新增 `data/scripts/wpp2024/qx.mjs`、`data/scripts/wpp2024/qx.test.ts`
- 新增 `packages/country-packs/data/{CN,JP,KP,KR,RU}/wpp2024-qx.json`（由脚本生成）

## 禁止修改

其他所有文件，包括 `births.mjs` 与已生成的出生数文件。

## 实现要求

### `qx.mjs`

```js
/**
 * @param {Record<string, string>[]} records  两个文件的记录合在一起
 * @param {'CN'|'JP'|'KP'|'KR'|'RU'} packId
 */
export function toQxSeries(records, packId);  // => StatSeries
```

1. 需要的列：地点代码、地点名称、年份、方案、年龄起点、年龄跨度、`qx`（WPP 文件中通常为 `LocID`、`Location`、`Time`、`Variant`、`AgeGrpStart`、`AgeGrpSpan`、`qx`）。若文件有性别列，只取表示男女合计的行，并在报告中写明该列名与取值。**列名或取值与预期不同时，停止并报告。**
2. 只取对应地区、`Medium` 方案（若估计期文件的方案列取值不同，如 `Estimates`，照实报告并按维护者意见处理——不要自行决定）。
3. 年龄：只接受 0—99 岁的单岁行（跨度 1）与 100 岁开口组（跨度 -1 或文件中表示开口的值）；其他行抛错。
4. 每个年份必须恰好有 0—100 共 101 个年龄，年份恰好覆盖 1950—2100；否则抛错（消息含年份与年龄）。
5. 每个 `qx` 必须是 [0, 1] 内的有限数；100 岁的 `qx` 必须等于 1，否则抛错（不要改成 1）。
6. 输出：
   - `id: 'wpp2024/<packId>/qx'`，`indicator: 'life-table-qx'`，`geographyId: 'country:<packId>'`，`unit: 'probability'`，`ageBasis: 'single-year'`，`sex: 'both'`；
   - `evidence: { grade: 'B', sourceIds: ['un-wpp:2024'], modelVersion: 'wpp2024-medium', geographyId: 'country:<packId>', yearRange: [1950, 2100], methodId: 'wpp2024-life-table-single-age-both' }`；
   - `points`：先按年份、再按年龄升序；`projected: year >= 2024`；`value` 为原始数值，不取整。
7. 返回前用 `StatSeriesSchema.parse` 校验。

命令行：`node data/scripts/wpp2024/qx.mjs --estimates <文件> --projections <文件>`，两个文件都校验 SHA-256（`inputs.json`），写出五个文件（格式同 M2-010），打印每个地区的点数，以及 1950、2023、2024 年 0 岁与 60 岁的 `qx`。

## 验收测试（必须新增，写在 `qx.test.ts`）

用代码生成的**夹具记录**（注释标明「测试夹具，数值虚构」）：

1. 正常输入得到 151 × 101 个点，通过 `StatSeriesSchema`，排序正确。
2. 2023 年 `projected: false`，2024 年 `projected: true`。
3. 缺一个年龄、缺一个年份、`qx` 为 1.2、100 岁 `qx` 不等于 1、出现 5 岁组（跨度 5）的行，各自抛错且消息含年份或年龄。
4. 其他地区的行被忽略。
5. 若仓库里已有 `packages/country-packs/data/*/wpp2024-qx.json`：每个文件都通过 `StatSeriesSchema`，恰好 15,251 个点，每年 100 岁的值都是 1。
