## 目标

把 M2 已经建好的 `polity-change` 历史锚点接入人物模拟：1991-12-26 之后仍在世的苏联居民，政治实体与国籍随之改变；**居住地不变**，不产生迁移，也不改币制。ADR-0005 §3 已定义契约，本任务只负责实现，不重新设计。

## 背景（执行者只需要知道这些）

- 现状一：`packages/systems/src/history.ts` 的 `history.anchor` 处理器遇到 `polity-change` 时直接抛错，错误信息是 `Polity-change anchors are applied from M3 (ADR-0005)`。
- 现状二：`packages/real-world/src/region-model.ts` 在构造 `RegionModel` 时用 `filter` 把 `polity-change` 锚点整体排除了，所以人生模拟里根本收不到这类锚点。
- 数据：五个国家包里只有俄罗斯有 `polity-change` 锚点 `anchor:ru-polity-change-1991`（`1991-12-26`，`polity:ussr` → `polity:ru-russian-federation`）。其他四国没有，所以本任务的行为只影响 RU。
- 产品约束：GDD §4.2「政体变化与迁居是不同事件，不能因 1991 年的政治实体更替自动搬动莫斯科居民」；GDD §5 要求 `placeId`、`politicalEntityId`、`citizenshipIds` 分开保存。
- `CharacterState` 已经有 `politicalEntityId` 与 `citizenshipIds`，本任务**不需要**改 `content-schema`。

## 实现要求

### 1. `region-model.ts`：不再过滤锚点

把

    const anchors = pack.anchors.filter((anchor) => anchor.kind !== 'polity-change');

改成直接使用 `pack.anchors`（保留 `const anchors: readonly HistoricalAnchor[] = pack.anchors;` 以便类型不变）。同时更新文件顶部注释：政体更替现在由 `history.ts` 处理，但**不改变居住地**。`macroAtBirth` 不需要改：它本来只处理 `redenomination` 与 `economy-phase`，遇到 `polity-change` 会自然跳过。

### 2. `history.ts`：实现 `polity-change` 分支

在 `handle` 里把「抛错」替换为下面的行为（保持在 `redenomination` 分支之前判断即可，顺序不影响结果）：

1. 先发一条全局事实，表示锚点本身发生：
   - `type: 'history.anchor'`
   - `outcomeCode: 'polity-change'`
   - `templateId: 'history.polity-change'`
   - `actorIds: []`
   - `evidenceIds: evidence`（沿用现有 `[anchor.id, evidenceId(region, 'history')]`）
   - `details: { from: anchor.fromEntityId, to: anchor.toEntityId }`
2. 遍历 `ctx.state.actors`，只处理同时满足 `vitalStatus.kind === 'alive'` 且 `politicalEntityId === anchor.fromEntityId` 的角色：
   - 把 `politicalEntityId` 改成 `anchor.toEntityId`；
   - 把 `citizenshipIds` 里所有等于 `anchor.fromEntityId` 的项换成 `anchor.toEntityId`，并去重（保持原有顺序）；
   - 发一条个人事实：
     - `type: 'identity.polity-change'`
     - `outcomeCode: 'changed'`
     - `templateId: 'identity.polity-change'`
     - `actorIds: [actor.id]`
     - `causes: [anchorFact]`（即第 1 步返回的 ID）
     - `evidenceIds: evidence`
     - `details: { from: anchor.fromEntityId, to: anchor.toEntityId }`
3. **不得**修改 `currentResidenceId`、`birthPlaceId`、`householdAccounts`、`macro.currency`；**不得**调用 `ctx.random`（本事件不消耗随机流）。
4. 处理完直接 `return`，不要继续走币制分支。

注意：`causes` 只能指向更早的事实，所以必须先 `emit` 全局事实、再为角色发个人事实。

### 3. `narrative.ts`：补充两条双语文案

在 `templates.history` 增加 `'polity-change'`，在 `templates` 下新增 `identity` 子树：

- zh-Hans：
  - `history['polity-change']`：`'政治实体更替：{{from}} → {{to}}。'`
  - `identity['polity-change']`：`'政治归属随政体更替改为{{to}}；居住地没有改变。'`
- en：
  - `history['polity-change']`：`'The political entity changed: {{from}} → {{to}}.'`
  - `identity['polity-change']`：`'Political allegiance changed to {{to}}; the place of residence did not change.'`

两种语言的键与占位符必须完全一致（`checkLocaleParity` 会检查）。

### 4. `narrator.ts`：把政治实体名并入 `enums.polity`

在 `labels()` 里像 `places` 一样收集 `pack.politicalEntities`：`polities[entity.id] = entity.names[locale]`，然后返回 `{ enums: { place: places, currency: currencies, polity: polities } }`。这样 `{{from}}`/`{{to}}` 会显示成「苏联」「俄罗斯联邦」而不是裸 ID。

### 5. `shared.ts`：版本号

只把 `SYSTEMS_VERSION` 从 `'0.1.0'` 改成 `'0.2.0'`。理由写进提交信息：新增政体更替对人物状态的作用，旧快照继续恢复会得到不一致结果。

## 验收测试（写在 `polity-change.test.ts`，并可在 `index.test.ts` 追加同类用例）

测试夹具一律用真实国家包（RU / JP），不要另造虚构地区。所有断言都要落到具体值。

1. **1991 年前的出生者**：`createRealLifeSimulation({ seed: 'polity-1', region: 'RU', year: 1980, birthDate: '1980-05-04' })`，推进到 `1992-01-01`。断言：
   - 主角 `politicalEntityId === 'polity:ru-russian-federation'`；
   - `citizenshipIds === ['polity:ru-russian-federation']`；
   - `currentResidenceId` 与 `birthPlaceId` 与出生时完全相同（居住地未变）；
   - 存在事实 `type === 'identity.polity-change'`、`at === '1991-12-26'`、`details.from === 'polity:ussr'`、`details.to === 'polity:ru-russian-federation'`；
   - 该事实的 `causeEventIds` 恰好指向同一时刻的 `history.anchor` 事实。
2. **锚点事实**：存在 `history.anchor`、`outcomeCode === 'polity-change'`、`at === '1991-12-26'`，且它的 `evidenceIds` 包含 `anchor:ru-polity-change-1991` 与 `RU/history`。
3. **1991 年后的出生者**：`region: 'RU', year: 2000, birthDate: '2000-01-01'` 跑完整人生，断言没有任何 `polity-change` 事实，且出生时 `politicalEntityId === 'polity:ru-russian-federation'`。
4. **没有该锚点的国家**：`region: 'JP', year: 1978` 跑完整人生，断言事实里没有 `identity.polity-change`，`politicalEntityId` 始终是 `polity:jp-japan`。
5. **币制不受影响**：RU 1980 出生者跨越 1991 后，1998-01-01 的 `finance.redenominated` 仍然正常发生，且 `macro.currency` 版本从 2 变到 3；1991 年锚点前后账户余额不变。
6. **确定性**：同一 `seed` + 出生参数跑两次，`facts` 的规范 JSON 指纹相同；两次都推进到死亡，事实数量相同。
7. **快照恢复**：推进到 `1990-01-01` 取快照，`Simulation.restore`（用同一 region）后推进到 1992，事实序列与不中断推进逐字节相同（可用 `canonicalJson` 比较）。
8. **双语渲染**：用 `createRealNarrator(pack, birthDate)` 渲染上述两条事实，zh-Hans 与 en 都不含 `{{`，且包含对方政体名（中文「俄罗斯联邦」；英文里包含对应英文名）。
9. **不消耗随机流**：`polity-change` 处理器里不得出现 `ctx.random`。测试侧用第 6 条的指纹稳定性保证：同一 seed 下加入本功能前后，除新增的两类事实外其余事实的随机结果不漂移（实现时先在 `0.1.0` 规则下记录一份基线，再改代码对照）。
