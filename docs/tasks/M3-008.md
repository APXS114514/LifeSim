## 目标

把「真实数据如何驱动教育、职业、收入、价格、医疗与迁居规则」写成一份可评审的 ADR 草案（ADR-0007），回答 Q3、Q5、Q8、Q11 涉及的设计问题，并给出接口、回退规则、版本与回归测试计划。**本任务不实现接口**。

## 为什么需要单独的设计任务

- `packages/systems/src/region.ts` 的 `RegionModel` 是 M1 为合成公式设计的（13 个查询 + 规则/效应系数）。AGENT_HANDOFF §9 明确「M3 接入真实数据时预计要重塑（届时写 ADR）」。
- 该文件在 guardrails 高风险清单里；按 AGENTS.md，改变公共接口必须先有 ADR，并由维护者审查。
- 如果直接边写边改，会把「数据缺失怎么回退」「职业分类如何映射」等决定埋进代码，无法评审。

## 实现要求（ADR 必须回答的问题）

1. **接口分层**：`RegionModel` 是继续扩容，还是拆成 `DemographyModel / EducationModel / LaborModel / PriceModel / HealthModel` 并由 `LifeRegion` 组合？给出推荐方案与备选，说明每个调用点的迁移成本。
2. **数据映射**：每个新指标（M3-003 的 7 个）如何进入规则；哪些规则用精确年、哪些必须用相邻年份回退、哪些在缺失时降级为 D 级假设并如何标注。
3. **职业与教育分类**：是否引入职业类别枚举；学历与职业资格的映射；不能出现「1950 年代就有未来职业」的资格规则如何表达。
4. **金额与购买力**：工资缺数据时的替代（人均 GDP × 劳动份额 × CPI？）与精度要求；禁止浮点累加；CPI 折算的函数签名与舍入规则。
5. **死亡风险校准**：乘数链的上下限、按年龄带的校准检查、死因权重表的证据等级（Q8）。
6. **版本与兼容**：`SYSTEMS_VERSION`、`SNAPSHOT_SCHEMA_VERSION`、数据包版本与旧存档拒绝策略（Q9）。
7. **回退与披露**：界面上如何让玩家看到「这条规则来自 B 级数据 / 这条是 D 级假设」。
8. **回归测试计划**：五国 × 1950/1970/1990/2020 出生年的确定性测试、年龄别死亡率对照、教育完成率分布对照、性能预算（加 NPC 后重新测量）。
9. **实施顺序**：把 ADR 拆成 M3-009…M3-016 的任务边界，逐条对应到现有任务编号。
10. **不做的事**：明确列出本 ADR 不覆盖的内容（例如性别、家庭账户粒度、国际迁移目的地包），指向 Q1/Q2/Q6。

## 验收测试（对文档而非代码）

1. ADR 结构包含：状态、日期、背景、决定、接口草案（TypeScript）、回退规则、证据与许可、版本与迁移、测试计划、后果、未决问题。
2. 每个新指标都有「数据来源 / 证据等级 / 缺失时行为」三列。
3. 接口草案能通过人工对照：现有 5 个规则文件里每一处 `region.*` 调用都能在草案里找到对应项或明确标注「保持不变」。
4. 不包含任何未经来源支持的具体数值（数值只能来自已登记的 B 级数据或标注 D 级并说明推导）。
5. 运行 `pnpm verify`（文档改动不应破坏格式检查）；提交说明写「草案，待维护者确认」。
