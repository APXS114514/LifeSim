# M3-030：Tier2 压缩 NPC 与熟人网络

| 项       | 内容                                                                                      |
| -------- | ----------------------------------------------------------------------------------------- |

## 目标

补齐 GDD §6.3 的第二层：同事、邻居与普通熟人作为 **Tier2** 存在，只运行压缩后的年度/多年摘要（换工作、退休、生病、死亡），不逐人展开完整人生；人数与事实量有上限；Tier2 升级为 Tier1 时不得重抽已经确定的事实。Tier3（尚未实例化的人口）仍用统计分布表示，不逐人建模。

## 背景

- GDD §6.3：Tier1 连续模拟；Tier2 压缩事件摘要；Tier3 统计分布；层级可以提升但此前已确定的经历不能被重抽。
- 现状：只有主角与（M3-010 起）父母；没有同事/邻居/熟人，也没有任何「压缩」机制。
- 本任务**不引入人名**：Tier2 用关系与角色称谓渲染（`role: 'colleague' | 'neighbor' | 'acquaintance'`），`enums.role` 提供中英文案。
- 性别未决（Q1）：Tier2 不写 sex/gender。
- 设计边界：Tier2 不是「简化版 Tier1」——它不安排年度生日事件，只在确定的检查点产生摘要事实。

## 实现要求

1. **创建**：在就业（同事）与迁居/邻里（邻居）事件中按确定性规则创建 Tier2 角色：
   - ID 形如 `char:<主角>:tier2-<序号>`；
   - 字段：`tier: 'tier2'`、出生日期、出生地、学历、职业、健康状态、关系（`colleague`/`neighbor`/`acquaintance` 用现有 `RelationshipSchema` 的某种表达——若现有 kind 不够，**报告并停止**，不要擅自改契约）；
   - 同时活跃的 Tier2 上限 **8 人**（常量，测试）；超出时不再创建，不淘汰已有关系（淘汰规则属于设计决定，报告）。
2. **压缩更新**：每位 Tier2 每 **5 年**（从创建日起）做一次摘要检查：
   - 抽一次职业变动/退休/疾病/死亡（概率来自现有 `RegionModel` 接口，不新造）；
   - 产生**最多一条**摘要事实（`tier2.summary`，`details` 带 `role`、`change`）；
   - 不做年度结算、不安排生日事件、不进入主角的时间线细节层（可在「熟人」面板查看）。
3. **一致性**：
   - 死亡后不再更新、不再产生事实；
   - 年龄资格、退休资格与现有不变量一致；
   - Tier2 的死亡不能以主角事实为原因，反之亦然。
4. **升级**：`promoteToTier1`（M3-011）把 Tier2 提升为 Tier1 时：
   - 保留全部已确定字段与已发生事实；
   - 从提升之日起安排年度生日事件；
   - 不补发提升前的事实，不重抽已有字段。
5. **Tier3**：不创建角色；文档与报告里说明 Tier3 如何用现有统计（出生数、生命表）表示，且**不**实现逐人模拟。
6. **性能与体积**：记录 M3 前后 `pnpm bench --lives 500` 的 p50/p99、平均事实数、平均快照字节；Tier2 事实量不得超过总事实的 20%（用一个批量断言）。

## 验收测试

1. 创建：就业后至少存在 1 名 `colleague`，迁居后至少存在 1 名 `neighbor`（固定 seed）。
2. 上限：构造超过 8 名候选的夹具，断言不超过 8 名活跃 Tier2。
3. 压缩节奏：Tier2 每 5 年最多 1 条事实；10 年内事实数 ≤ 2（夹具断言）。
4. 死亡：固定 seed 找到 Tier2 死亡，断言之后没有以该角色为 actor 的事实。
5. 升级：把一名 Tier2 提升为 Tier1，断言字段不变、事实不重抽、之后开始有年度事件。
6. 性能：Tier2 事实占比 ≤ 20%；bench p50 不超过 M3 前的 2 倍（记录真实数字）。
7. 确定性：同 seed 两次运行一致；快照往返一致。
8. 双语：`tier2.summary` 与 `enums.role` 在 zh/en 都存在。
