## 目标

为 ADR-0010 的「姓名写进角色状态」提供五个地区、按年代与性别区分、许可清楚的姓名表，以及确定性的选择函数。本任务**不改角色契约、不改规则**（规则在 M3-043 调用这里的函数），因此黄金指纹与 bench 不变。

## 背景（只写执行者必须知道的事实）

- 维护者 2026-10-21 决定：姓名写进角色状态（ADR-0010 方案 b）；姓名要考虑地区、时代、文化与语言，不能共用一套姓名库；不得使用未授权数据、历史不合理的姓名与刻板印象。
- 角色出生年跨度：主角 1950—2026；父母比主角大 18—45 岁，最早约 1905 年出生；俄罗斯父称还需要「父母各自父亲的名」，最早约 1880 年。**姓名表要覆盖 1880—2026 的出生年**。
- 存档只存表引用 `{ table, id }`，各语言写法在表里（GDD §10）；条目 ID 一旦发布只增不删。
- 命名方案（ADR-0010 A2）：`zh`（中国大陆）、`ja`（日本）、`ko`（韩国、朝鲜）、`ru`（俄罗斯含苏联时期）。

## 实现要求

1. **表结构**（`NameTableSchema`，严格对象）：`id`（表 ID，例如 `jp-given`）、`scheme`、`kind`（`family` / `given`）、`version`、`entries[]`。条目：`id`（表内唯一、只用小写字母数字与连字符）、`sex`（`female` / `male` / `any`）、`born`（适用出生年区间 `[from, to]`，可多段）、`weight`（正数）、`grade`（A—D）、`forms`（`native`、`zh-Hans`、`en`，均非空；`ru` 的姓与父称需要阴性与阳性两套）、`sourceIds`（必须已在 `data/sources.json` 登记且可再分发）。
2. **覆盖**：五个地区 × 1880—2020 每十年 × 两种性别，可选的名字至少 15 个、姓氏至少 30 个。达不到的组合列入 `docs/data/NAMES.md` 的缺口表；**不用别的地区或年代的名字凑数**。
3. **选择函数**：按 `born` 过滤后按 `weight` 抽取，只调用一次 `random`；同一表、同一输入、同一随机流状态 → 同一结果；没有可选条目时返回 `null`（由 M3-043 决定显示「姓名待接入」），不得抛出或回退到其他年代。
4. **内容边界**：不收录政治人物、名人的全名组合（姓与名分开抽取，但要在审校名单里检查高知名度组合）；朝鲜部分按资料核实与领导人姓名相关的命名限制并写成排除规则，且只收录有公开惯用汉字写法的姓与名（中文写法即该惯用写法）；不收录带贬义或宗教敏感的名字；`docs/data/NAMES.md` 附「待维护者抽查」清单。
5. **合成地区**：虚构音节组成，不与五地真实姓名重合（测试校验），标注 D 级。

## 验收测试

1. 契约：正反例（缺写法、`born` 越界、权重为 0、重复 ID、未登记来源）。
2. 覆盖：按「实现要求 2」逐组合检查；未达标的组合必须恰好等于缺口表里列出的组合。
3. 选择：确定性（同输入同输出）；分布（固定 2000 个种子，抽中频率与权重之比的偏差在 ±20% 内，用于发现权重写错）；空集返回 `null`。
4. 写法：所有条目的三种写法非空且不含 `{{`；`ru` 条目阴阳性齐全；`zh-Hans` 写法只含简体中文字符或中间点。
5. 来源：每条 `sourceIds` 都已登记且 `redistribution` 为允许。
6. `pnpm check:data` 通过且确实检查了姓名表（用一个来源未登记的夹具文件验证它会报错，夹具只放在测试里）；黄金指纹与 bench 工作量指纹**不变**。
