# M4-004：Web Worker 模拟与 RPC

| 项       | 内容                                                               |
| -------- | ------------------------------------------------------------------ |
| 风险     | 高（权威状态迁移到 Worker + 新协议）：走 `task/M4-004-worker` 分支 |
| 前置依赖 | M4-001（存档仓库，便于 Worker 侧持久化）                           |
| 涉及模块 | `apps/web`（worker、controller、页面）                             |
| 预计改动 | 新增 3—4 个文件；修改 `GameSession` 的使用方式与页面；新增测试     |

## 目标

把权威模拟状态放进 Web Worker：界面只通过带版本的 RPC 请求推进/决定/取快照；长时间模拟不冻结主线程；取消、暂停与进度可工作；结果与主线程运行逐字节一致。

## 背景

- GDD §11.2：UI → GameController → Worker RPC → SimulationCore；UI 不持有整个世界对象。
- 现状：`apps/web/src/game/session.ts` 在主线程同步推进（M3-lite 实测几十毫秒，但 M3 加入 NPC 后会变慢）。
- 内核 `advanceTo` 支持 `cancellationToken` 与 `maxWorkUnits`，可在 Worker 里分片推进并上报进度。
- 协议必须显式版本化；主线程不得信任 Worker 返回的任意 JSON，仍需 schema 校验。

## 实现要求

1. **协议**（`protocol.ts`）：
   - 请求：`init`（request/存档记录）、`advance`（目标日期、stopAtMajorDecision、maxWorkUnits）、`decide`、`snapshot`、`cancel`、`persist`；
   - 响应：`ready`、`facts`（增量）、`pending-decision`、`ended`、`progress`（已处理事件数/当前日期）、`error`（可识别错误码）；
   - 每个消息带 `protocolVersion` 与 `requestId`；不匹配直接拒绝。
2. **Worker**：持有 `GameSession`（或等价对象）；处理 `cancel` 时使用内核的取消令牌；推进过程中每 N 个事件（例如 200）发一次 `progress`，并让出事件循环；不得使用 `Math.random` 或时间改变模拟。
3. **主线程**：`WorkerClient` 负责请求排队、超时、错误映射；收到事实后仍用 schema 校验；不得在 React state 里保存权威快照（只保存渲染所需视图）。
4. **一致性**：同一 request + 不推进方式在 Worker 与主线程（测试里直接调用 session）产生的事实逐字节相同。
5. **取消语义**：取消后内核状态不破坏（可继续推进），已产生的事实不丢。
6. **加载失败**：Worker 启动失败时回退到主线程？**不允许静默回退**——显示错误并提供重试；主线程回退会导致两套权威状态。

## 验收测试

1. 协议：版本不匹配、未知消息、超时各一个断言。
2. 一致性：同一 seed 在 Worker 与直接调用之间的事实指纹相同（用可注入的内存通道测试，不依赖真实 Worker）。
3. 取消：推进到一半取消，快照仍可继续；没有重复或丢失事实。
4. 进度：至少收到 2 条 `progress`，日期单调递增。
5. E2E：页面加载后 Worker 启动；点击「快进到死亡」时主线程仍能响应（在 E2E 里检查按钮可点击/无控制台错误）。
6. 现有 `session.test.ts` 的纯逻辑断言保留。

## 完成定义

- Worker 承载权威状态，RPC 可取消、可进度、可恢复；一致性测试通过。
- 报告里写明协议版本与消息类型。

## 可能的阻塞（遇到就停止并报告）

- 内核的取消令牌不能从 Worker 消息安全触发（需要内核改动）→ 报告。
- Vite worker 构建与 E2E 环境不兼容。
- 需要把 `packages/systems` 的会话逻辑移到新包 → 属架构变更，先报告。
