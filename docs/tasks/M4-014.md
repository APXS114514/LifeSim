# M4-014：性能预算与长人生压力

| 项       | 内容                                               |
| -------- | -------------------------------------------------- |
| 风险     | 中（性能与测试；不改规则）                         |
| 前置依赖 | M4-013                                             |
| 涉及模块 | `apps/web`、`apps/cli`（批量基准）                 |
| 预计改动 | 新增性能测试与报告脚本文档；可能少量优化（需报告） |

## 目标

按 GDD §14.3 记录可测的性能基线：普通交互 P75 ≤ 200 ms、暂停 P95 ≤ 250 ms、80 年无逐帧模拟桌面 ≤ 5 s；长时间线（万条事实）滚动不冻结；批量基准与工作量指纹可复现。

## 背景

- QA_GATE 已解释口径：所有指标记录 P50/P75/P95/P99；交互 P75 ≤ 200 ms；暂停 P95 ≤ 250 ms；无逐帧 80 年模拟桌面 ≤ 5 s、中档手机 ≤ 15 s。
- 现有 `pnpm bench --lives 500` 是 headless 基准（Node），不含浏览器渲染。
- M3 加入 NPC 后需要重新测量（AGENT_HANDOFF §9 已提醒）。

## 必读文件

- `docs/QA_GATE.md`「性能预算的解释」
- `apps/cli/src/bench.ts`、`test-results/bench-report.json`（CI 产物）
- `apps/web/tests/e2e/*.spec.ts`
- GDD §14.2、§14.3

## 允许修改

- 新增 `apps/web/tests/e2e/performance.spec.ts`
- 新增 `docs/PERFORMANCE.md`（记录基线、机器、方法）
- `apps/cli/src/bench.ts`：只允许增加按国家的分组统计（不改变工作量指纹）
- 若测出瓶颈：允许在对应任务范围内做优化，但必须在报告里列出改动与前后数字

## 禁止修改

`packages/simulation-core`、`packages/content-schema`、`packages/systems` 的规则语义、`country-packs` 数据、`docs/adr`、`qa/test-baseline.json`、`scripts/check-*`。

## 实现要求

1. **浏览器测量**：用 Playwright + Performance API 测量：
   - 首屏可交互时间；
   - 逐年推进一次（含渲染）的 P50/P75/P95；
   - 暂停/取消指令到界面响应的 P95；
   - 快进到死亡的端到端时间；
   - 万条事实时间线滚动 10 次的帧时间。
     记录机器（CPU/内存/浏览器版本）与日期。
2. **批量基准**：五国各 500 局，记录 p50/p99、平均事实数、平均存档字节、工作量指纹；与 M3-029 记录的数字对比。
3. **预算判定**：逐项对照 GDD §14.3 写明「达标/未达标/因环境无法判定」；不达标时写瓶颈与建议，不修改目标。
4. **稳定性**：同一测量跑 3 次，记录波动；不使用固定 sleep 制造「通过」。

## 验收测试

1. 性能 spec 通过（阈值用宽松上限避免 CI 抖动，但记录真实数字）。
2. `docs/PERFORMANCE.md` 包含机器、方法、原始数据与结论。
3. `pnpm bench --lives 500` 的输出与指纹可复现（跑两次指纹相同）。
4. 万条事实的夹具下 DOM 节点数受限（M4-007 的断言保持）。
5. 没有为了达标而降低测试严格度（对比 M4-007/008/013 的断言）。

## 验收命令

    pnpm bench --lives 500

    PW_CHANNEL=chrome pnpm test:e2e

    pnpm verify

## 完成定义

- 基线文档入库，真实数字与 GDD 预算逐项对照；测试通过。
- 报告里明确哪些指标未达标、原因与后续建议。

## 可能的阻塞（遇到就停止并报告）

- CI/本机性能差异过大，无法给出稳定结论 → 记录两种环境并说明。
- 需要修改内核或数据来达标 → 属高风险，先报告。
