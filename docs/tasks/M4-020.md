## 目标

三块「对照」信息，都在本机算、都不影响玩家这一局：

1. **同一秒出生的四人**：与玩家同一天出生、在五地按出生人数加权抽出的另外四个人，用同一个引擎按人生原则自动生活，显示他们「此刻同龄时」的状况。
2. **生存曲线**：与玩家同年同地出生的人，到每个年龄还活着的比例。
3. **人生方格**：一年一格，按当年的主要经历着色。

## 已定的约束（来自骨架，逐字保留；细化不得改动）

1. 四人的种子由玩家种子确定性派生（例如 `<seed>#cohort-1…4`），用 `selectBirth` 固定出生日期；**不改变玩家这局的任何结果**，也不写进玩家存档（读档后按种子重算到当前时钟）。
2. 四人只推进到玩家的权威时钟，不提前模拟到未来。
3. 生存曲线来自 WPP 生命表，沿出生队列逐年取当年的 q 计算（以时期生命表近似队列）：界面披露数据等级与方法，2100 年后的部分标为情景；不得把模拟结果当成统计。
4. 性能：四人的额外推进不得让单年推进超过 16 ms（在报告里实测）。

## 背景：本任务依赖的现有代码事实（2026-10-21 核对）

- **确定性出生**：`selectBirth({ seed, region, year, birthDate? })` 先消费固定顺序的抽样（年份 → 地区 → 城乡 → 日期），地区按当年五地出生数加权。给出 `birthDate` 时仍消费该抽样但不使用其日期结果，所以**同一天出生 + 种子不同 → 地区/城乡不同**，这正是「同一秒出生的四人」的确定性来源。
- **创建一局**：`createRealLifeSimulation({ seed, region, year, birthDate })` 返回 `{ request, birth, pack, region, simulation }`。**不要**为了四人改用 `GameSession`：它固定 `stopAtMajorDecision: true`，会为四人停下来等玩家；四人应当按人生原则自动决定。
- **内核对未作决定的决策会自动按人生原则结算**：`advanceTo({ targetDate, stopAtMajorDecision: false, maxWorkUnits })` 时，`#resolveChoice` 用 `chooseByPrinciples` 选，事实里 `decidedBy: 'principles'`。所以四人只需循环推进，不需要 `decide()`。
- **生命表数据**：`packages/country-packs/data/<PACK>/wpp2024-qx.json`：指标 `life-table-qx`、单岁、`sex: 'both'`、证据等级 **B**（`un-wpp:2024`）、`yearRange: [1950, 2100]`、`age 0—100`、2024 起为 projected。数据文件只到国家层，没有城市层。
- **只读查询**：`RegionModel.tables.ageValue('life-table-qx', year, age)` 返回 `DataValue | null`（含 `grade`/`quality`/`projected`/`sourceYear`，**不带**情景规则：2101 年以后返回 `null`）。`RegionModel.mortalityQ(year, age)` 是规则侧基线（年龄 ≥100 返回 1，缺失时抛错，允许 `scenario-hold-last`）。`RegionModel.evidence.mortality` 给出整表的 `EvidenceMeta`。
- **依赖边界**：`apps/web` **不得** 导入 `@lifesim/data-registry`（`scripts/check-boundaries.mjs` 的 `ALLOWED_INTERNAL`）；可以用 `@lifesim/real-world`、`@lifesim/country-packs`、`@lifesim/systems`。所以生存曲线走 `session.region.tables.ageValue` 即可，**不需要**新接口（见下「待维护者/Claude Code 决定」）。
- **展示**：`describeCharacterLocations(pack, actor, date, locale)`（地点/政体）、`LIFE_NARRATIVE[locale].enums.level`（学历中英）、`factCategory(fact)`（`apps/web/src/components/fact-category.ts`，已有类别）。
- **快照**：`SimulationSnapshot.actors` 里的角色有 `education.completed`、`employment.status`（`child/student/not-in-labor-force/employed/unemployed/retired`）、`health.conditions`、`vitalStatus`。
- **逐字节对比**：`canonicalJson`（`@lifesim/simulation-core`）用于「玩家的结果完全不变」的断言。

### 1. 四人的派生与推进（`apps/web/src/game/cohort.ts`）

```ts

}

/** 第 index 人（1..4）的请求：种子派生、地区随机、年份与出生日期与玩家相同。 */
export function cohortRequest(input: CohortRequestInput, index: number): RealLifeRequest;
// => { seed: `${seed}#cohort-${index}`, region: 'random', year: Number(birthDate.slice(0,4)), birthDate }
```

- 种子的字符串格式固定为 `${seed}#cohort-${index}`（`index` 为 1—4）；**不得**用 `Math.random`、时间或界面状态参与派生。

- 四人各自 `createRealLifeSimulation(cohortRequest(...))`。**不**复用玩家的 `simulation`、**不**读取玩家的 `facts`。
- 推进函数：

- 成员已去世（`sim.ended`）后不再推进。

### 2. 生存曲线（`apps/web/src/game/survival.ts`，纯函数）

```ts
export type SurvivalMethod = 'period-table' | 'scenario-hold-last';

export interface SurvivalPoint {
  age: number; // 0..100
  survived: number; // S(age)，0—1
  periodYear: number; // 产生这个点所用的生命表年份（通常 = 出生年 + age − 1；情景期固定为序列末年 2100）
  projected: boolean; // 该点是否来自 WPP 的 projected 年份
  method: SurvivalMethod;
  grade: EvidenceGrade; // 'B'（观测期）/ 'D'（情景）
}

export interface SurvivalCurve {
  birthYear: number;
  packId: string;
  points: readonly SurvivalPoint[];
  /** 观测期与情景期里最差的等级（'A' 最好）。 */
  worstGrade: EvidenceGrade;
  /** 第一个使用情景的年龄；没有情景时为 null。 */
  scenarioFrom: number | null;
  /** 数据不足而提前结束的年龄；没有提前结束时为 null。 */
  truncatedAt: number | null;
}

export interface SurvivalLookup {
  value: number;
  grade: EvidenceGrade;
  projected: boolean;
}

export function buildSurvivalCurve(input: {
  birthYear: number;
  packId: string;
  /** 由组件从 session.region.tables.ageValue('life-table-qx', year, age) 适配而来。 */
  lookup(year: number, age: number): SurvivalLookup | null;
  /** 生命表序列的最后一年（当前数据为 2100）。 */
  seriesEndYear: number;
  maxAge?: number; // 默认 100
}): SurvivalCurve;
```

算法（固定）：

1. `S(0) = 1`，`points[0] = { age: 0, survived: 1, periodYear: birthYear, projected: false, method: 'period-table', grade: 'B' }`（存活率恒为 1，这一点的等级只用于图例）。
2. 对 `a = 0 … maxAge-1`：`y = birthYear + a`；用 `q` 表示这一步取到的死亡概率，
   - `y ≤ seriesEndYear` → `q = lookup(y, a)`；为 `null` 时**提前结束**并记 `truncatedAt = a`；
   - `y > seriesEndYear` → `q = lookup(seriesEndYear, a)`，这一点记为 `method: 'scenario-hold-last'`、`grade: 'D'`、`projected: true`；仍为 `null` 时提前结束并记 `truncatedAt = a`；第一个情景的 `a` 记 `scenarioFrom = a`。
   - 计算 `S(a+1) = S(a) × (1 − q)` 并追加 `points[a+1] = { age: a+1, survived: S(a+1), periodYear: min(y, seriesEndYear), projected, method }`。也就是说：**点的 `age` 是「活到几岁」，`periodYear` 是产生这一步的生表年份**，所以 `birthYear = 1950` 时 `points[1].periodYear === 1950`、`points[2].periodYear === 1951`。
3. `worstGrade` = 所有点里最差的等级（等级序 `A > B > C > D`，取最差）。
4. 不四舍五入中间值（保留双精度）；界面显示时再格式化到 0.1%。
5. 只有 100 岁以内（含）；「100 岁以上按 q = 1 处理」写进披露文字。

**手算示例（写进测试）**：中国大陆 1950 年出生，`lookup(1950, 0)` = 0.12711866（数据文件里的原值），所以 `S(1) = 0.87288134`；`lookup(1950, 1)` = 0.03384495 → `S(2) = 0.87288134 × 0.96615505 = 0.8433387146917669`（测试用 `toBeCloseTo`，精度 8 位）。

### 3. 人生方格（`apps/web/src/game/life-grid.ts`，纯函数）

```ts
export type GridCategory =
  | 'life'
  | 'decision'
  | 'education'
  | 'career'
  | 'health'
  | 'family'
  | 'history'
  | 'finance'
  | 'other'
  | 'none';

export interface GridCell {
  year: number;
  category: GridCategory;
}

export function buildLifeGrid(input: {
  birthYear: number;
  /** 去世年份；尚在世时传 null。 */
  deathYear: number | null;
  /** 权威时钟的年份。 */
  currentYear: number;
  facts: readonly SimEventFact[];
}): readonly GridCell[];
```

- 年份区间是 `birthYear … (deathYear ?? currentYear)`，**含两端**；去世后不再产出更晚的年份。
- 每年：取该年事实里**优先级最高**的类别；优先级固定为 `life > decision > education > career > health > family > history > finance > other`。`finance.settlement` 只在没有任何更高优先级事实时着色为 `finance`。
- 该年没有任何事实 → `none`；仍在世且年份晚于 `currentYear` → 不产出（不要造「未来格」）。
- 类别判定复用 `factCategory(fact)`（已有实现），不另写一套映射。
- 输出按年份升序，长度等于「已发生的年数」（出生年到现在/去世年，含两端）。

## 验收测试

单元（`cohort.test.ts`、`survival.test.ts`、`life-grid.test.ts`）：

1. **四人可重现**：同一 `{ seed: 'cohort-0', birthDate: '1978-05-04' }` 构造两次 `Cohort`，`advanceTo('2000-05-04')` 后四人的 `canonicalJson(simulation.snapshot())` 与 `canonicalJson(simulation.facts)` 两两相同。
2. **种子派生固定**：`cohortRequest({ seed: 'a', birthDate: '1978-05-04' }, 1).seed === 'a#cohort-1'`；`index` 为 0、5、1.5 时抛 `RangeError`。
3. **与玩家互不影响**：`s0 = GameSession.create({ seed: 'iso-0', region: 'JP', year: 1978, birthDate: '1978-05-04' })`；先记录 `canonicalJson(s0.simulation.snapshot())` 与 `canonicalJson(s0.facts)`，再构造 `Cohort` 并 `advanceTo(s0.clock)`（以及推进到 2000 年），断言两者仍逐字节相同；再让两者各 `finish()`，最终快照与事实仍逐字节相同。
4. **不提前模拟**：给每个成员的 `simulation.advanceTo` 装 spy 记录 `targetDate`，对玩家时钟 `1950-03-02` 与 `2000-05-04` 各跑一次：断言所有 `targetDate ≤ 玩家时钟`，且 `members[i].simulation.clock <= 玩家时钟`。
5. **幂等**：`advanceTo(clock)` 连续调用两次，第二次不会新增事实（`facts.length` 不变）。
6. **生存曲线手算**：用桩 `lookup`（`q(1950,0)=0.1`、`q(1950,1)=0.2`、`q(1950,2)=0.3`、`seriesEndYear: 2100`）：`S(0)=1`、`S(1)=0.9`、`S(2)=0.72`、`S(3)=0.504`（`toBeCloseTo`，12 位）。
7. **真实数据点**：用 `createRealRegion('CN', '1950-01-01')` 的 `tables.ageValue` 适配成 `lookup`，断言 `points[1].survived` 约等于 `0.87288134`（8 位），`points[1].grade === 'B'`，`points[1].periodYear === 1950`。
8. **情景段**：`birthYear: 2026` 时 `scenarioFrom === 75`（`2026 + 75 = 2101 > 2100`）。因此 `points[75]`（活到 75 岁）仍来自时期生命表 2100 年（`method === 'period-table'`，`grade === 'B'`，`periodYear === 2100`，`projected === true`，因为 2100 本身是 WPP 的 projected 年份）；`points[76]` 起 `method === 'scenario-hold-last'`、`grade === 'D'`、`periodYear === 2100`；`worstGrade === 'D'`。
9. **数据缺口提前结束**：`lookup` 在 `age = 40` 返回 `null`（year ≤ seriesEnd）时 `points` 到 40 岁为止，`truncatedAt === 40`，且不产出 41 岁以后的点。
10. **人生方格优先级**：用事实夹具（某年同时有 `finance.settlement` 与 `career.hired`）断言该年着色 `career`；只有 `finance.settlement` 的年份着色 `finance`；没有任何事实的年份 `none`；出生年 `life`；去世年 `life`；格子数量等于 `deathYear - birthYear + 1`（已故）或 `currentYear - birthYear + 1`（在世）。
11. **方格不造未来格**：在世且 `currentYear = 1990`、`birthYear = 1980` 时长度为 11，最后一格 `year === 1990`。

## 需要维护者 / Claude Code 决定的问题

1. **是否需要在 `packages/real-world` 新增只读的生存曲线查询**（骨架「涉及模块」里写了「必要时…（报告）」）。现状是 `RegionModel.tables.ageValue` 已经够用，所以**本文件按不新增接口实现**；若要把它做成 `realSurvivalCurve(packId, birthYear)` 之类的领域接口（供 M5 复用、便于统一证据披露），需要 Claude Code 决定，并注意 `apps/web`→`data-registry` 的依赖边界问题。**降级路径已给出**：不改任何 `packages/*`。
2. **「按当日出生人数加权」的数据粒度**：WPP 出生数序列只有**年度**值（`wpp2024-births`，年频率），`selectBirth` 的地区权重也是按年取的。因此四人的地区加权实际是「按出生年五地出生人数加权」，不是逐日出生数。界面披露要如实写「按出生年的五地出生人数加权」，否则会暗示一个并不存在的数据精度。是否接受这个近似由维护者确认。
3. **生存曲线的队列近似口径**：本文件按骨架写的「以时期生命表逐年近似出生队列」（`q(a) = q_{birthYear+a}(a)`）。这既不是真正的队列生命表也不是当期生命表；`docs/GDD.md` §9 与 ADR-0007 没写这条，属统计口径，需要 Claude Code 审查同意（本文件已要求界面披露方法与等级）。
4. **性别口径**：数据是 `sex: 'both'`（D4「是否引入 `sex` 字段」未定）。曲线与四人都按男女合计披露；若要分性别，需先执行 D4。
5. **「同年同地」的范围**：曲线按「同国家包 + 同出生年」计算（数据只到国家层，代表城市/城乡没有分层的生命表）。若要做城乡或城市级，需要新数据（D5）。
6. **四人的「此刻同龄时」要展示到什么程度**：本文件展示地区、在世/已故、年龄、学历、就业状态、慢性病数、是否同国。若要展示收入、婚姻、子女等，依赖 M3-017/018 与 M4-016 的指标，属后续扩展。
7. **16 ms 的口径**：本文件按「四人各推进一年」的额外成本测（不含界面渲染）。是否把渲染也计入预算，由维护者/Claude Code 定；若计入，界面要按第 5 条分片。

## 本章节之外发现的骨架问题

- 骨架「同一秒出生的四人 … 在五地按**当日**出生人数加权随机出生」与数据粒度不符：生命表/出生数序列都是年度数据（见上第 2 项），细化只能按年加权并披露，已写进实现要求与决定问题。
