## 目标

保存最近 **10 局已结束**人生的摘要与卡片，可以重新打开查看、可以删除；开新局时不丢失过往记录。

## 已定的约束（来自骨架，逐字保留；细化不得改动）

1. 只存本机（IndexedDB）；不上传、不分享到公共墙（GDD §3.2）。
2. 摘要来自结束时的事实与快照；版本不兼容时按 Q9 保留并提示，不静默删除。
3. 删除需要二次确认。

## 实现要求

### 1. 存储（IndexedDB，位置只在 `apps/web`）

- 数据库：沿用 M4-001 的 `lifesim`，**新开一个对象仓库 `pastLives`**（keyPath `id`，索引 `finishedAt`）。
- 版本升级：打开数据库时先 `indexedDB.open('lifesim')` 读**当前**版本（不要假写死 1），再用 `version + 1` 打开并 `upgrade`：**只**在 `contains('pastLives')` 为 false 时创建它，**绝不**删除或重建 `saves`/`facts`（Q9）。
- 若 M4-001 的实际实现与本文件描述不一致（数据库名、版本、仓库名不同）：**停止并报告**，按 M4-001 的现状调整方案，不要自造第二个数据库。
- 所有读写都要处理 `blocked`/`error`/`onversionchange`：失败时抛可识别的错误（如 `PastLivesError('unavailable' | 'quota')`），由界面提示，**不得**静默吞掉，也不得阻断结局流程。

### 2. 记录结构

```ts
export const PAST_LIVES_LIMIT = 10;

export interface PastLifeRecord {
  /** 记录 id；优先用 M4-001 的存档 id（一局一条，天然幂等）。 */
  id: string;
  /** M4-001 的存档 id；存档被删除后仍保留记录（记录自带摘要，不依赖存档）。 */
  saveId: string | null;
  /** 结束时的时间（ISO 8601，调用方时间；只用于排序与显示，不参与任何模拟）。 */
  finishedAt: string;
  /** 版本元数据：用于判断「旧版本记录」。 */
  engineVersion: string;
  systemsVersion: string;
  dataPackVersions: Record<string, string>;
  /** 结束时由事实与快照派生的摘要（结构同 LifeSummary）。 */
  summary: LifeSummary;
  /** 结束时渲染好的卡片文本（两种语言各一份），见 §3。 */
  card: { 'zh-Hans': string; en: string };
  seed: string;
  nickname: string | null;
}
```

- `id` 必须稳定且幂等：读档后在同一局再次触发「结束」时，`put` 同一 `id`（覆盖），**不得**产生重复记录。
- 若 M4-001 不能提供当前存档的稳定 id：**停止并报告**（由维护者决定是否扩展 M4-001 的 API）；**不得**另造一套与存档无关的 id 方案。
- 记录里不存完整 `facts`/`snapshot`（那是存档的职责），只存摘要、卡片文本与版本元数据。

### 3. 结束时写入

- 触发点：`App` 的 `onChange` 里，若 `session.isEnded` 且本局还没有写入过记录，则：
  1. `const summary = session.summary`；
  2. 用 M4-019 的 `buildLifeCard(...)` + `renderCardSvg(...)` 渲染 `zh-Hans` 与 `en` 两份 **SVG 字符串**（不下载、不联网）；
  3. `await put({ ... })`；
  4. 写入失败时在界面上给一次性提示（`pastLives.saveFailed`），**游戏照常结束**。
- 写入**只读**会话：不得调用 `stepYear`/`choose`/`finish`，不得修改 `facts`/`snapshot`。
- 写入**不得**影响模拟结果：有无前世记录时，玩家的快照与事实逐字节相同。
- 写入幂等：同一局重复触发只覆盖同一条记录。

### 4. 列表、打开与删除

- 入口：`App` 头部（`header.masthead` 下）加一个按钮 `pastLives.open`（「前世记录」/ "Past lives"），**没有进行中的局时也能打开**；打开后渲染 `<PastLivesPanel>`。
- 列表：按 `finishedAt` 倒序，最多 `PAST_LIVES_LIMIT` 条；每条显示出生国家与地区、享年、结束日期、昵称（若有）与「旧版本」标记。当前版本常量用已导出的 `ENGINE_VERSION`（`@lifesim/simulation-core`）与 `SYSTEMS_VERSION`（`@lifesim/systems`）；任一不同即标记为旧版本记录（只影响提示，不影响查看）。
- 打开：点一条记录 → 详情区显示摘要字段与该记录的卡片 SVG（`<img src={dataUrl}>`，与 M4-019 的预览同一写法）+ 「保存为图片」按钮（复用 M4-019 的 `svgToPngBlob`/`downloadPng`，文件名 `lifesim-past-life-<id>.png`）。
- 删除：第一次点击变成「再次点击以确认删除（不可恢复）」的按钮，第二次才真正删除；确认文案与 `SaveIssuePanel` 的二次确认同构。**只删这条前世记录**，不删存档（见「需要维护者决定的问题」第 2 条）。
- 淘汰：写入时若记录数 > `PAST_LIVES_LIMIT`，在**同一个事务**里删掉 `finishedAt` 最早的记录（同值时按 `id` 字典序），保证任何时刻最多 10 条。
- 版本不兼容（Q9）：读不出来的记录（字段缺失、`summary` 结构不符、`card` 不是两份文本）**不删除**，在列表里显示为「无法读取的记录」并提供删除入口；能读但版本不同的记录照常显示 + 「旧版本」标记。所有读取失败都必须让其余记录照常显示。

### 5. 界面与文案

- 面板：`<section class="past-lives" aria-labelledby="past-lives-heading">`，标题 `pastLives.heading`；空列表时显示 `pastLives.empty`。
- 文案键（zh-Hans 先加）：`pastLives.open / heading / empty / age / finishedAt / oldVersion / unreadable / open / download / delete / confirmDelete / saveFailed / keptHint`。
- 中英齐全；`locales.test.ts` 通过；手机窄屏下卡片预览 `max-width: 100%`，页面不横向滚动。
- 不出现分享、链接、二维码或上传入口（GDD §3.2）。

### 6. 不做的事

- 不做云同步、不导出到服务器、不做公共墙。
- 不把记录写进 `GameSaveData`（记录是独立仓库，存档形状不变）。
- 不改 M4-001 的 `saves`/`facts` 仓库结构；不改 `packages/save` 的接口。
- 不重新模拟旧局来「恢复」记录：查看只用记录里保存的摘要与卡片文本。

## 验收测试

单元（`apps/web/src/game/past-lives.test.ts`，用 fake-indexeddb 或 M4-001 已建立的等价夹具）：

1. **往返**：写入一条记录 → 读回，`summary`、`card`、`engineVersion`/`systemsVersion`/`dataPackVersions` 逐项相等；`finishedAt` 只影响排序。
2. **幂等**：同一 `id` 写入两次（第二次改 `finishedAt`）→ 记录数为 1，内容为第二次的值。
3. **上限淘汰**：写入 11 条（`finishedAt` 递增）→ 列表为 10 条，被淘汰的是最早那条；再次写入 → 仍为 10 条且淘汰继续按最早。
4. **删除**：删除一条后列表少一条，其余不受影响。
5. **旧版本保留**：写入 `systemsVersion: '0.0.0'` 的记录 → 读取时**不抛错、不删除**，并被标记为旧版本（`isOldVersion(record) === true`）。
6. **读不出来的记录保留**：直接往仓库 `put` 一条字段缺失的记录（测试夹具，标明是夹具）→ 列出时该条进入 `unreadable` 分组，其他记录正常；不删除它。
7. **升级不破坏存档仓库**：先建 `lifesim` 的 `saves`/`facts` 并写入一条假快照（夹具），再用本任务的升级逻辑打开 → `saves`/`facts` 里的数据仍在（这是「不 `deleteObjectStore`」的回归）。
8. **写入失败可识别**：模拟 `put` 抛错（stub）→ 抛 `PastLivesError`，且不留下半条记录。
9. **与模拟隔离**：结束一局（`finish()`）→ 记录 `summary`；再对比「有记录」与「无记录」两条同种子人生的 `canonicalJson(snapshot())` 与 `canonicalJson(facts)`，逐字节相同。

## 需要维护者决定的问题

1. **前置依赖不完整**：骨架只写 `M4-001`，但「卡片」需要 M4-019。建议把前置依赖补成 `M4-001、M4-019`（以及隐含的 M3 验收）。
2. **淘汰是否连存档一起删**：本文件只删前世记录、保留存档（非破坏、Q9 取向）。若维护者希望「淘汰即彻底回收」（同时删存档与记录、释放配额），属数据语义变更，需要确认。
3. **记录的 id 与去重口径**：本文件用 M4-001 的存档 id 作为记录 id（一局一条）。若维护者希望「同一局多次结束各留一条」（例如未来支持读档到死后再改主意），ID 规则要改。
4. **卡片文本是「结束时渲染」还是「查看时渲染」**：本文件存结束时渲染好的两种语言 SVG 文本，好处是旧版本记录仍可查看、不需要旧引擎；代价是记录较大（每条两份 SVG，约几十 KB），且卡片样式升级后旧记录不会自动变新。若维护者要求「总是用最新样式渲染」，就只能在查看时重渲染，那旧版本记录可能渲染不出来（与 Q9 冲突），需要权衡。
5. **昵称与语言**：记录的卡片文本在结束时按当时昵称与「两种语言」各存一份 —— 若玩家之后改昵称，旧记录不变。是否要在查看时以当前昵称重渲染，属产品决定。
