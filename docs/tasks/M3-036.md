# M3-036：内核逐事件校验关系图

| 项       | 内容                                                                                 |
| -------- | ------------------------------------------------------------------------------------ |
| 风险     | 高（模拟内核 `engine.ts`）：走 `task/M3-036-relationship-verify` 分支                |
| 前置依赖 | M3-035（增量校验，复用其「只校验改动部分」的机制）                                   |
| 涉及模块 | `packages/simulation-core`                                                           |
| 执行者   | Claude Code（内核改动，不交给执行 Agent）                                            |
| 状态     | 未开始；建议在 M3-011 之前完成（M3-011 会改关系的 `coResident`），最迟在 M3-017 之前 |

## 背景

- M3-002 加入了 `RelationshipsSchema`（自环、日期顺序、双向 bonds、配偶约束、ID 与关系去重、亲子图无环）。
- 内核 `#verify` 每个事件校验事实、角色与账户，但**不校验 `relationships`**；关系只在 `Simulation.restore` 解析快照时校验，`systems` 的不变量只检查两端角色存在。
- 后果：规则写出非法关系（例如 bonds 超出 [0,1]、亲子成环）时，当前事件照常提交，直到下次读档才失败——存档在玩家手里变成「无法恢复」，且无法定位是哪个事件造成的。这违反 ADR-0004 决定 4 的意图（违反契约的状态不得提交）。

## 实现要求

1. `#verify`：若 `draft.relationships` 与提交前的关系数组 `jsonEqual` 相同则跳过；否则用 `RelationshipsSchema.safeParse(draft.relationships)` 校验整个数组（数组级规则——去重、无环——需要整体检查），失败时违规信息以 `relationships:` 开头。
2. 不改快照结构、`ENGINE_VERSION` 或任何规则；黄金指纹、基准工作量指纹不变。
3. ADR-0004「增量校验」一节补一句：关系图在改动时整体校验。

## 验收测试

1. toy-world 夹具新增陷阱：自环关系、bonds 越界、亲子成环；各自在发生的那个事件上抛 `invariant-violation`，状态回滚。
2. 未改动关系的事件不调用 `RelationshipsSchema.safeParse`（调用计数，参照 M3-035 的测试写法）。
3. `pnpm verify` 通过；`pnpm bench --lives 1000` 的工作量指纹不变，p50 与 M3-035 基线（2.72 ms）相比的变化写进报告。
