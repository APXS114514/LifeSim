## 目标

在若干人生节点（5、15、30、50、70 岁）暂停，提出一个与这段人生有关的问题，玩家可以选一个预设回答或留一句话，也可以不回答；这一生的总结里回顾这些话。

它是 1in8b 与 1injp 里最打动人的环节之一，但**问题、选项、卡片文字全部为本项目原创**（见「原创文案」）。

## 已定的约束（来自骨架，逐字保留；细化不得改动）

1. 问题由我们原创撰写（中英），**不得复制** 1in8b 或 1injp 的文字。
2. 留言只存在本机存档里（`GameSaveData` 增加**可选**字段，旧存档缺省为空），**不进入模拟状态、不影响任何结果**；不上传。
3. 可在设置里关闭；自动播放时可选择跳过。
4. 内容平和、不诱导；遇到严肃人生经历（重病、丧亲）时措辞克制。

### 2. 记录结构与存档字段

```ts
export const REFLECTION_NOTE_MAX = 60; // 按 Unicode 码点计

export interface ReflectionRecord {
  /** 节点年龄，必须属于 REFLECTION_NODES。 */
  node: ReflectionNode;
  /** 记录时的权威时钟（`session.clock`），只用于回顾排序与显示。 */
  at: ISODate;
  /** 选中的预设选项 id；没有选时为 null。 */
  option: string | null;
  /** 玩家留言（已 trim、已截断到 REFLECTION_NOTE_MAX 个码点）；没有时为 null。 */
  note: string | null;
  /** answered = 选了选项或写了话；skipped = 明确「不回答」或自动播放跳过。 */
  status: 'answered' | 'skipped';
}
```

- `GameSaveData` 增加**可选**字段 `reflections?: ReflectionRecord[]`；**`version` 保持 1**（可选字段缺省即空数组，不需要版本迁移，也不改变恢复语义）。
- `parseGameSave` 必须接受缺少该字段的旧存档（得到 `[]`），并调用 `parseReflections` 校验：
  - 不是数组 → `[]`；
  - 未知 `node`、`status` 非法、`at` 不是 `YYYY-MM-DD`、`option`/`note` 类型不对 → **丢弃这一条**，其余保留，**绝不抛错**。理由：反思是可选的界面数据，损坏它不能让整份存档无法读取（Q9 的非破坏性取向）。
  - 同一 `node` 出现多条时保留**最早**的一条（数组顺序在前者）。
- `session.serialize()` 输出 `reflections`；`GameSession.restore()` 读入后原样保留（重绘需要）。
- 反思**只**存在这个字段：不写 `snapshot`、不写 `facts`、不调用 `simulation` 的任何方法、不影响随机流。

### 3. 纯函数（全部在 `reflections.ts`，无 DOM、无 `Date`、无 `Math.random`）

```ts
/** 最早一个「已到年龄但还没有记录」的节点；没有则 null。 */
export function dueReflection(
  age: number,
  records: readonly ReflectionRecord[],
): ReflectionNode | null;

export type PlaybackState = 'paused' | 'playing' | 'awaiting-decision' | 'ended';

export interface ReflectionPrefs {
  enabled: boolean;
  skipDuringAutoPlay: boolean;
}

export type ReflectionPlan =
  | { kind: 'show'; node: ReflectionNode }
  | { kind: 'record-skipped'; node: ReflectionNode }
  | { kind: 'none' };

export function planReflection(input: {
  age: number;
  records: readonly ReflectionRecord[];
  playback: PlaybackState;
  prefs: ReflectionPrefs;
}): ReflectionPlan;

/** 追加一条记录：同节点已存在则原样返回；否则按节点升序插入，长度不超过节点数。 */
export function addReflection(
  records: readonly ReflectionRecord[],
  record: ReflectionRecord,
): readonly ReflectionRecord[];
```

判定顺序固定（决定 `planReflection` 的语义）：

1. `prefs.enabled === false` → `{ kind: 'none' }`（关闭期间既不提示也不记录）。
2. `playback === 'ended'` → `{ kind: 'none' }`。
3. `dueReflection(age, records) === null` → `{ kind: 'none' }`。
4. `playback === 'playing' && prefs.skipDuringAutoPlay` → `{ kind: 'record-skipped', node }`。
5. 其他情况 → `{ kind: 'show', node }`。

写记录时的规则：选项与留言至少要有一个才记为 `answered`；两者都没有（点「不回答，继续」）记 `{ option: null, note: null, status: 'skipped' }`。留言 `trim()` 后为空按 `null` 处理；超过 `REFLECTION_NOTE_MAX` 个码点时截断（`[...text].slice(0, REFLECTION_NOTE_MAX).join('')`）。

## 验收测试

单元与属性测试（`apps/web/src/game/reflections.test.ts`、`session.test.ts`、`storage.test.ts` 追加）：

1. **节点表形状**：`REFLECTION_NODES` 等于 `[5, 15, 30, 50, 70]`；每节点恰好 3 个选项、id 唯一；每条的 `zh-Hans` 与 `en` 都非空且不含 `{{`；选项数量两语言一致。
2. **触发边界**：`dueReflection(4, []) === null`；`dueReflection(5, []) === 5`；`dueReflection(5, [记录5]) === null`；`dueReflection(16, [记录5]) === 15`；`dueReflection(71, []) === 5`（同一时刻只提示最早未答的节点）；`dueReflection(0, []) === null`。
3. **各年龄示例**：`dueReflection(30, [记录5, 记录15]) === 30`；`dueReflection(30, [记录5, 记录15, 记录30]) === null`。
4. **计划判定**：`enabled: false` 在 `paused`/`playing` 下都返回 `none`；`playback: 'ended'` 返回 `none`；`playing + skipDuringAutoPlay: true` 返回 `record-skipped`；`playing + skipDuringAutoPlay: false` 返回 `show`；`paused` 返回 `show`。
5. **追加与去重**：`addReflection([], 记录30)` 得到 `[30]`；再追加 `记录5` 得到 `[5, 30]`（升序）；重复追加 `记录5` 长度不变、内容不变；`recordReflection` 对重复节点返回 `false` 且不改 `reflections`。
6. **留言清洗**：`'  你好  '` → `'你好'`；`'   '` → `note: null` 且若选项也为空则 `status: 'skipped'`；61 个字符的字符串 → 截断为 60 个码点（用 `'あ'.repeat(61)` 这类多字节夹具断言长度）。
7. **存档往返**：`serialize() → parseGameSave → restore()` 后 `reflections` 深度相等；缺少 `reflections` 字段的旧存档（用现有夹具删掉该键）恢复成功且 `reflections` 为 `[]`；`reflections` 被污染（`'x'`、`[{ node: 99 }]`、`[{ node: 5, status: 'wat' }]`）时整份存档仍能恢复，坏条目被丢弃。
8. **结果不变（关键验收点）**：同一 `request` 建两局，A 在 5 岁与 15 岁各写一条反思、B 不写；两者 `canonicalJson(session.simulation.snapshot())` 与 `canonicalJson(session.facts)` 逐字节相同；随后两局都 `finish()`，最终 `canonicalJson(facts)` 与 `canonicalJson(snapshot())` 仍逐字节相同。
