## 目标

在 `content-schema` 里定义「关系」的 zod schema，并把快照里目前还是 `z.json()` 的 `relationships` 收紧成它。**只加契约与测试**：不写任何家庭事件、婚育规则或 NPC 模拟；那些是 M3-009 以后的任务。

## 背景

- GDD §6.3：关系图必须区分**双向主观感受**与**客观法定/生物/共同居住事实**；支持多次婚姻、收养、监护、亲子、不婚、不育。
- GDD §6.1：关系是底层状态，幸福/关系等表层指标由它派生，不能独立增减。
- 现状：`SimulationSnapshotSchema.relationships` 是 `z.json()`，注释写明「M3 再收紧为具体 schema」；内核把它初始化成空数组 `[]`（`simulation-core/src/engine.ts:168`），所以收紧后**现有快照仍然合法**，不需要提升 `SNAPSHOT_SCHEMA_VERSION`。
- 性别尚未决定（见 [M3_OPEN_QUESTIONS.md](../M3_OPEN_QUESTIONS.md) Q1）：本契约**不得**出现 sex/gender 字段，也不得假设配偶异性。
- 家庭财务已确认 **Q2 = 方案 A**（每个角色独立账户 + 家庭层共同收支/责任记录）：本契约仍**不得**定义共同账户、财产份额或抚养费，只允许 `coResident` 这类共同居住事实；家庭层记录由 M3-014 引入。

## 实现要求

### 1. `relationships.ts` 的字段

    export const RELATIONSHIP_KINDS = [
      'parent-child',
      'adoptive-parent-child',
      'sibling',
      'spouse',
      'former-spouse',
    ] as const;

    export const BondSchema = z.strictObject({
      trust: z.number().min(0).max(1),     // 信任
      intimacy: z.number().min(0).max(1),  // 亲密
      conflict: z.number().min(0).max(1),  // 冲突
    });

    export const RelationshipSchema = z.strictObject({
      id: EntityIdSchema,
      kind: z.enum(RELATIONSHIP_KINDS),
      /** 有序对：parent-child 是 [父/母, 子/女]；sibling 与婚姻按创建时的顺序。 */
      fromId: EntityIdSchema,
      toId: EntityIdSchema,
      since: ISODateSchema,
      /** null 表示仍然有效（婚姻未解除、亲子关系持续、共同居住持续）。 */
      until: ISODateSchema.nullable(),
      /** 客观事实，与主观感受分开（GDD §6.3）。 */
      biological: z.boolean(),
      legal: z.boolean(),
      coResident: z.boolean(),
      /** 双向主观感受：键只能是 fromId 或 toId。 */
      bonds: z.record(EntityIdSchema, BondSchema),
    });

    export const RelationshipsSchema = z.array(RelationshipSchema);

类型用 `z.infer` 推导，不要写平行 interface。

### 2. 校验规则（单条关系，`superRefine`）

| #   | 规则                                                                                                                          | path        |
| --- | ----------------------------------------------------------------------------------------------------------------------------- | ----------- |
| 1   | `fromId !== toId`（无自环）                                                                                                   | `['toId']`  |
| 2   | `until === null` 或 `until >= since`（ISO 日期字符串比较）                                                                    | `['until']` |
| 3   | `bonds` 的键只能是 `fromId` 或 `toId`                                                                                         | `['bonds']` |
| 4   | `bonds` 必须同时有这两个键（双向感受都要记录；没有数据时用 `{trust:0.5,intimacy:0.5,conflict:0}` 之类的显式默认值，不能缺键） | `['bonds']` |
| 5   | `kind === 'spouse'` 时 `biological === false` 且 `until === null`                                                             | `['kind']`  |
| 6   | `kind === 'former-spouse'` 时 `biological === false` 且 `until !== null`                                                      | `['kind']`  |

### 3. 校验规则（数组级，`RelationshipsSchema.superRefine`）

| #   | 规则                                                                                                                                                          | path        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| 7   | `id` 不得重复                                                                                                                                                 | `[i, 'id']` |
| 8   | 同一 `(kind, fromId, toId, since)` 不得重复                                                                                                                   | `[i]`       |
| 9   | sibling 是无向关系：同一无序对 `{a,b}` 不得有两条 sibling（不论方向）                                                                                         | `[i]`       |
| 10  | 每个角色最多出现在一条 `until === null` 的 `spouse` 关系里（禁止同时有两段有效婚姻）                                                                          | `[i]`       |
| 11  | 亲子图无环：把 `parent-child` 与 `adoptive-parent-child` 当作有向边 `fromId → toId`，DFS 检测环；允许同一对亲子同时有生物与收养两条边（重组家庭），但不得成环 | `[i]`       |

### 4. 快照收紧

`SimulationSnapshotSchema.relationships: RelationshipsSchema`；在快照的 `superRefine` 里追加：每条关系的 `fromId`、`toId` 都必须是 `actors` 里的角色，否则报 `relationships[i].fromId` 一类的路径。**不要**改 `SNAPSHOT_SCHEMA_VERSION`（现有快照的 `[]` 仍然通过）。

### 5. 与 NPC 层级的关系

不要在本任务加 `tier` 校验（例如「关系只能连 tier1」）：Tier2 关系在 M3-030 才引入，提前限制会挡路。

## 验收测试（`relationships.test.ts`，夹具为虚构 ID，注释写明「测试夹具」）

1. 一条合法 `parent-child` 关系通过 `RelationshipSchema`（`biological: true, legal: true, coResident: true`，双向 bonds 齐全）。
2. 规则 1—6 每条各有一个被拒绝的样例（可用 `it.each`），断言错误路径。
3. 规则 7—11 每条各有一个被拒绝的数组样例；规则 11 至少覆盖三节点环（A→B→C→A）与四节点环。
4. 合法组合通过：同一角色有两段婚姻（一段 `former-spouse`、一段 `spouse`）；一对夫妻有 2 个子女；收养 + 亲生并存的重组家庭；单向 sibling 注册两次（不同方向）被判为重复（规则 9）。
5. 快照测试：用 `SimulationSnapshotSchema` 构造一个最小快照（1 个主角 + 空关系）通过；把关系指向不存在的角色时被拒绝，错误路径在 `relationships`。
6. 未知字段（例如 `gender`）被拒绝（strictObject）。
7. 现有快照夹具（若 `schemas.test.ts` 里有）不受影响；不改动它的断言。
