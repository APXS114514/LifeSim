## 目标

- **出生证明卡**：开局后可随时查看并保存为图片；内容是出生日期、出生地、**当时的**政体名与旗帜、城乡、家境。
- **人生卡片**：结局生成；内容是出生与去世日期、享年、出生地、去世时居住地、学历、工作年数、死因、最终余额、重大决定、主要经历。
- 两张卡都能**在本机**保存为 PNG 下载；完全离线，不生成分享链接，不上传。

## 已定的约束（来自骨架，逐字保留；细化不得改动）

1. 完全在本机生成（SVG/Canvas → PNG 下载），**不上传、不联网、不生成分享链接**（GDD §3.2）。
2. 内容来自权威事实与派生指标：出生日期、出生地与当时的政体名与旗帜、家庭背景、享年、主要经历与决定；不出现未发生的内容。
3. 只用已登记许可的素材：旗帜按 `FLAG_SOURCES.md`，字体用系统字体或许可已登记的字体。
4. 可选的昵称只存本机，不进入模拟状态。

## 实现要求

### 1. 卡片数据（`apps/web/src/game/cards.ts`，纯函数，无 DOM / 无 i18n / 无 `Date`）

```ts
/** 从会话里取卡片需要的最小接口，方便用真实 GameSession 测试。 */
export interface CardSource {
  readonly birth: BirthContext;
  readonly pack: CountryPack;
  readonly clock: ISODate;
  readonly facts: readonly SimEventFact[];
  readonly summary: LifeSummary;
  snapshot(): SimulationSnapshot; // 需要 activeCharacterId 对应的 actor
}

export interface BirthCardModel {
  kind: 'birth';
  nickname: string | null;
  birthDate: ISODate;
  packId: BirthRegionId;
  birthPlaceId: string;
  polityIdAtBirth: string;
  settlement: string;
  familyResources: string;
  flagFile: string | null;
}

export interface LifeCardModel {
  kind: 'life';
  nickname: string | null;
  birthDate: ISODate;
  deathDate: ISODate | null;
  ageAtDeath: number | null;
  packId: BirthRegionId;
  birthPlaceId: string;
  polityIdAtBirth: string;
  residencePlaceId: string;
  residencePolityId: string;
  education: EducationLevel;
  yearsEmployed: number;
  causeOfDeath: string | null;
  finalBalanceMinor: number;
  currency: string;
  decisions: readonly { decision: string; option: string }[];
  highlights: readonly SimEventFact[];
  factCount: number;
  flagFile: string | null;
}

export function buildBirthCard(source: CardSource, nickname: string | null): BirthCardModel;
export function buildLifeCard(source: CardSource, nickname: string | null): LifeCardModel;
```

规则：

- **只读会话，不推进、不重算**：两个函数都不允许调用 `stepYear`/`advanceTo`/`simulation.decide`，也不允许改 `facts`。
- `polityIdAtBirth` 取 `source.birth.politicalEntityId`（`selectBirth` 已按出生日期解析），**不要**用当前政体；`flagFile` 用 `flagFileFor(polityIdAtBirth, birthDate)`，未登记时为 `null`（卡片显示中性占位，不拿现代国旗顶替历史政体）。
- 「主要经历」选择规则（固定，不可另定）：`HIGHLIGHT_TYPES = ['education.admitted', 'education.tertiary-completed', 'career.hired', 'career.retired', 'health.illness-onset', 'identity.polity-change']`，按时间顺序扫描 `source.facts`，**每种类型最多取第一条**，最后按时间排序，上限 **4** 条。
- 「重大决定」直接来自 `summary.decisions`，保持原有顺序；卡片显示上限 6 条，其余以 `card.moreDecisions`（`{{count}}`）折叠。
- `wrapText(text, maxCharsPerLine, maxLines)`：中日韩按字符切；含空格的（英文）按词切且不拆分单词；超过 `maxLines` 时最后一行末尾加 `…`（英文 `...`）。纯函数，含空串、超长单词、恰好边界三种夹具。

### 2. SVG 渲染（`apps/web/src/game/card-svg.ts`，纯字符串，无 DOM）

```ts
/** 所有文案由调用方注入：组件用 i18n + narrator + label 组装，测试用桩对象。 */
export interface CardText {
  title: string; // 「出生证明」/「人生卡片」
  footer: string; // 「这是模拟生成的记录，不是真实的人。」
  labels: Record<CardLabelKey, string>;
  settlement(value: string): string;
  familyResources(value: string): string;
  education(value: string): string;
  cause(value: string | null): string;
  decision(value: string): string;
  option(value: string): string;
  fact(fact: SimEventFact): string;
  currency(value: string): string;
  money(minor: number, currency: string): string;
  nickname(value: string): string;
  moreDecisions(count: number): string;
}

/** 返回完整的 <svg> 字符串（viewBox 0 0 1080 1350），不含任何外部引用。 */
export function renderCardSvg(
  model: BirthCardModel | LifeCardModel,
  text: CardText,
  flagSvg: string | null,
): string;
```

硬性要求：

- `viewBox="0 0 1080 1350"`，竖版；背景、标题、字段行、页脚都用 SVG 基本元素。
- **不出现任何外部引用**：不写 `<image href="http…">`、不写 `url(http…)`、不写 `@font-face`、不引用外部字体或图片（`xmlns="http://www.w3.org/2000/svg"` 是命名空间，允许）。
- 字体只用系统字体栈（不打包字体文件、不加载 webfont）：`font-family="system-ui, -apple-system, 'Segoe UI', 'Noto Sans CJK SC', 'PingFang SC', 'Microsoft YaHei', sans-serif"`。
- 旗帜：`flagSvg` 为**已内联的旗帜 SVG 源码**（见第 3 条），渲染时嵌进 `<g>` 并等比缩放到固定框；`null` 时画一个中性描边方框，不猜国旗。
- 所有文本按语言用一个 `locale` 已解析好（每个语言渲染一次），SVG 里不出现 `{{…}}`。
- 转义：所有用户可见文本（含昵称、决定文字）必须先做 XML 转义（`& < > " '`），否则昵称里的 `<` 会破坏 SVG。

### 3. 旗帜内联（唯一允许的素材来源）

- 主方案：在 `apps/web/src/game/flags.ts` 新增 `flagSvgFor(file: string): string | null`，用 Vite 的 `?raw` 静态导入 `public/flags/*.svg`（7 个文件，最大 12 KB，总量约 17 KB）并建成只读映射；构建期内联，运行时不发请求。
- 备用方案（仅当 `?raw` 从 `public/` 导入在本仓库的 Vite 版本上构建失败时）：模块内一次性 `fetch(flagUrlFor(...))` 并缓存文本，**点击生成之后不得再发请求**。两个方案都**不得**把旗帜文件复制到 `src/assets/`（会绕过 `FLAG_SOURCES.md` 的登记路径）。
- 不新增、不替换、不重绘任何旗帜文件。

### 4. PNG 生成与下载（`apps/web/src/game/card-image.ts`）

```ts
export async function svgToPngBlob(svg: string, width: number, height: number): Promise<Blob>;
export function downloadPng(blob: Blob, filename: string): void;
```

- `svgToPngBlob`：`data:image/svg+xml;charset=utf-8,` + `encodeURIComponent(svg)` → `new Image()` → `await img.decode()` → 画到 `<canvas width=height=1080/1350>` → `canvas.toBlob(cb, 'image/png')`；任一步失败都 `reject`（不使用 `alert`）。
- `downloadPng`：照 `downloadSaveBackup` 的结构（Blob + `URL.createObjectURL` + `<a download>` + `finally revokeObjectURL`）。
- 文件名固定、不用系统时间：`lifesim-birth-certificate.png`、`lifesim-life-card.png`。
- 不读写任何网络资源；`canvas` 不得跨域污染（旗帜已内联，所以不会）。

### 5. 界面（`CardPanel.tsx` + `PlayPage`/`SummaryCard`）

- 出生证明入口：`PlayPage` 侧栏 `.side-controls` 增加按钮 `card.openBirth`（「出生证明」/ "Birth certificate"），点开后在 `.game-main` 顶部渲染 `<CardPanel kind="birth">`（再次点击折叠）。
- 人生卡片：结局时在 `SummaryCard` 下方渲染 `<CardPanel kind="life">`（默认展开）。
- 面板内容：`<img class="card-preview" src={dataUrl} alt={title}>`（同一个 SVG 字符串同时用于预览与下载，避免两套渲染漂移）+ 「保存为图片」按钮（`card.download`）+ 昵称输入（仅出生证明面板：`<input type="text" maxLength={CARD_NICKNAME_MAX = 24}>`，label `card.nicknameLabel`，按钮 `card.saveNickname`）。
- 昵称存 `lifesim.prefs.v1` 的 `card.nickname`（`string | null`，默认 `null`），读取时与既有键合并、写回时保留其他键；localStorage 不可用时本会话内生效，不抛错。昵称**不**进入 `GameSaveData`、不进入 `snapshot`、不进入 `facts`。
- 可访问性：预览图 `alt` 用卡片标题；下载按钮有明确文案；键盘可达；不新开窗口。
- 手机：面板宽度 100%，预览图 `max-width: 100%`，页面不横向滚动。

### 6. 内容与文案的边界

- 卡片上出现的每个字段都必须能追溯到 `CardSource`：日期来自 `birth.birthDate`/`summary.deathDate`，地点与政体来自真实数据解析，决定与经历来自 `facts`，余额与币制来自 `summary`。**不得**在卡片里写任何硬编码的国家名、城市名或事件描述。
- 中英两版都完整（`locales.test.ts` 的 `checkLocaleParity` 必须通过）；`card.*` 键先加 zh-Hans。
- 页脚固定声明这是模拟记录，不是对真实个人的描述，也不是预测（与 `about.notPrediction` 同义但独立键）。

## 验收测试

单元（`apps/web/src/game/cards.test.ts`、`apps/web/src/game/card-svg.test.ts`）：

1. **字段与事实一致**：用 `request = { seed: 'card-0', region: 'JP', year: 1978, birthDate: '1978-05-04' }` 建局并 `finish()`；断言 `buildBirthCard` 的 `birthDate`、`packId`、`birthPlaceId`、`polityIdAtBirth`、`settlement`、`familyResources` 与 `session.birth` 及 `summary` 对应字段逐一相等；`flagFile` 等于 `flagFileFor(polityIdAtBirth, birthDate)`。
2. **政体取出生时而非现在**：用 `region: 'RU', year: 1970` 建局（出生时是苏联），推进到 2000 年后再建人生卡片：`polityIdAtBirth` 仍是 `polity:ussr`，而 `residencePolityId`（去世时居住地政体）可以是俄罗斯联邦；两者不相等时断言卡片同时显示两者。
3. **人生卡片字段**：`ageAtDeath`、`deathDate`、`causeOfDeath`、`education`、`yearsEmployed`、`finalBalanceMinor`、`currency`、`factCount` 与 `session.summary` 完全相等；`decisions` 与 `summary.decisions` 的元素逐条相等（不排序、不改写）。
4. **主要经历选择**（用事实夹具断言，不依赖真实人生）：`facts` 依次含 `education.admitted`（两次）、`career.hired`、`identity.polity-change`、`education.tertiary-completed`、`life.death`、`finance.settlement` → `highlights` 恰好是 4 条：早的那条 `education.admitted`、`career.hired`、`identity.polity-change`、`education.tertiary-completed`，且按时间升序。
5. **不出现未发生的内容**：`highlights` 与 `decisions` 的每个元素都能在 `session.facts` 里找到同 `id` 的事实；卡片模型里没有任何字面量国家名/城市名（用 `JSON.stringify(model)` 断言不含 `'日本'`、`'Japan'`、`'东京'`、`'Tokyo'`）。
6. **只读**：对同一会话连续调用 `buildBirthCard`/`buildLifeCard` 三次，`canonicalJson(session.facts)` 与 `canonicalJson(session.simulation.snapshot())` 与调用前相同；`session.clock` 不变。
7. **wrapText**：`wrapText('', 10, 3) === []`；`wrapText('あ'.repeat(25), 10, 3)` 得到 3 行且末行以 `…` 结尾；英文 `wrapText('born in a small town by the sea', 12, 2)` 不拆开单词（每行都是完整单词序列）；恰好在第 `maxLines` 行结束时不加省略号。
8. **SVG 无外部引用**：对两种卡片的两种语言渲染结果断言：以 `<svg` 开头、含 `viewBox="0 0 1080 1350"`、不含 `url(http`、不含 `xlink:href="http`、不含 `<image href="http`、不含 `@font-face`、不含 `{{`；`flagSvg = null` 时仍能渲染且不含 `<image`。
9. **转义**：昵称 `R&D <b>` 渲染后 SVG 里出现 `R&amp;D &lt;b&gt;`，不出现裸 `<b>`。
10. **双语**：同一个模型用 `zh-Hans` 与 `en` 两套 `CardText` 渲染，两份 SVG 不相同且都非空；`locales.test.ts` 的 `checkLocaleParity` 通过（`card.*` 键中英齐全、占位符一致）。
11. **旗帜内联**：`flagSvgFor('jp-japan.svg')` 返回以 `<svg` 或 `<?xml` 开头、含 `</svg>` 的字符串；未登记文件返回 `null`；`flagSvgFor` 覆盖 `FLAG_SOURCES.md` 表里的全部 7 个文件（写一个遍历断言）。

端到端（`apps/web/e2e/cards.spec.ts`，沿用 `freezeSeed` + `startLife('日本', '1978')` 夹具）：

12. **出生证明下载**：点「出生证明」→ `.card-preview` 可见且 `alt` 含「出生证明」；点「保存为图片」→ `page.waitForEvent('download')`，`suggestedFilename()` 为 `lifesim-birth-certificate.png`，`download.failure()` 为 `null`，读前 8 字节等于 PNG magic（`89 50 4E 47 0D 0A 1A 0A`），字节数 > 1000。
13. **人生卡片下载**：跑完一局（沿用 `smoke.spec.ts` 的到结局循环）→ `SummaryCard` 下方出现 `.card-preview` 且文本含「享年」或 `享年` 数字 → 下载 `lifesim-life-card.png`，同样是 PNG 且非空。

17. **手机布局**：`setViewportSize({ width: 320, height: 700 })` 下打开卡片面板，`document.documentElement.scrollWidth - clientWidth <= 0`。
18. **无回归**：`smoke/display/flags/licenses/appearance` 五个既有 spec 原样通过。
