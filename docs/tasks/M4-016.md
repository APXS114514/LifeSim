## 目标

把 M4-006 里的「派生指标」提前：角色卡显示健康、幸福、知识、人际、经济五个 0—100 指标与收入，随状态变化；提供「这些是什么」说明。M4-006 以后只负责三栏布局并复用本任务的函数。

## 背景（只写执行者必须知道的事实）

- GDD 决定 11：健康、幸福、知识、人际、经济等表层指标由底层状态**派生**，不能独立增减，也不写进模拟状态。本任务的函数因此是只读纯函数：**不改变任何规则、不参与任何抽样**。把它接进事件处理器会改变黄金指纹——那是违规的（见「验收测试」第 6 条）。
- 现有可派生字段（2026-10-21 在 `main` 上核对）：快照里的 `actors[].education`（`completed` / `enrolledIn`）、`employment`（`status` / `wageLevel`）、`health.conditions`（`treated`）、`traits.aptitude`、`finance.accountId`；`householdAccounts[].balanceMinor`（可为负＝负债）；`relationships[].bonds`（双向 `trust` / `intimacy` / `conflict`；M3-002 已推送 `c8e22f4`，快照里已经有关系图）。M3-043 的细状态尚未合并，**不得**引用它。
- 年度收支事实：`finance.settlement` 的 `details` 为 `{ incomeSource: 'wage' | 'pension' | 'none', incomeMinor, costMinor, balanceMinor, currency }`（`packages/systems/src/finance.ts`）。M3-011 落地后 NPC 也会产生同类事实，**必须**用 `fact.actorIds` 是否含主角来过滤，不能只依赖「现在只有主角有结算事实」这个临时状态。
- 金额显示：`formatRealMoney(minor, currencyLabel, locale)`（`@lifesim/real-world`）与 `session.currencyName(currencyLabel, locale)` 已在 `SummaryCard` 使用；币制来自 `snapshot.world`（`MacroStateSchema`，形如 `{ code: 'JPY', version: 1 }`，显示标签是 `"JPY-1"`）。
- 教育程度已经有中英枚举标签 `enums.level`（`session.label('level', value, locale)`：无学历/小学/中学/大学），**直接复用**，不要另写一套。
- 测试环境现状：`vitest.config.ts` 的 `environment` 是 `node`，仓库**没有** jsdom 与 Testing Library，React 面板无法在单元测试里渲染。因此：面板用 Playwright E2E 验收，纯函数用 vitest 验收；**不要为了面板单测新增依赖**（新增依赖需要维护者批准）。
- 界面层现状：`PlayPage` 的左栏是 `.game-side` 里的角色卡；本任务在角色卡下方追加一个面板 section，M4-006 做三栏布局时再移动位置。

## 已定的约束（骨架原文，不得改动）

1. 指标是**纯函数**：输入快照（与必要的事实），输出数值与说明；不写进模拟状态、不影响任何规则（GDD 决定 11）。规格沿用 M4-006 第 1 条。
2. M3-043 合并前，只用现有字段派生（学历、就业、疾病、余额与负债、关系 bonds）；合并后改用细状态，接口不变。
3. 说明文字披露派生方式与 D 级性质；金额沿用当时币制与本地格式，不换算成美元。
4. 中英齐全；手机布局不横向滚动。

## 实现要求

### 1. 派生指标函数（`packages/systems/src/indicators.ts`）

导出（名字与形状固定，M4-006 会按此复用）：

```ts
export const INDICATOR_KEYS = [
  'health',
  'happiness',
  'knowledge',
  'relationships',
  'economy',
] as const;
export type IndicatorKey = (typeof INDICATOR_KEYS)[number];
/** 五个指标，各为 0—1 的比值（M4-006 第 1 条的接口口径）。 */
export type IndicatorValues = Record<IndicatorKey, number>;
/** 0—1 比值 → 0—100 的界面整数（四舍五入，先夹取到 [0, 1]）。 */
export function indicatorPercent(value: number): number;
export function deriveIndicators(
  snapshot: SimulationSnapshot,
  facts: readonly SimEventFact[],
): IndicatorValues;
/** 最近一次（按 sequence 最大）属于主角的年度结算事实；没有时返回 null（界面显示「—」，不要显示 0）。 */
export interface DerivedIncome {
  incomeMinor: number;
  incomeSource: 'wage' | 'pension' | 'none';
  at: ISODate;
}
export function deriveIncome(
  snapshot: SimulationSnapshot,
  facts: readonly SimEventFact[],
): DerivedIncome | null;
```

计算口径（照抄；`clamp01(x) = min(1, max(0, x))`，所有除法都用浮点，不要整数化）：

```text
p        = snapshot.actors.find(a => a.id === snapshot.activeCharacterId)；找不到 → 抛错（与 summarizeLife 一致）
age      = ageOn(p.birthDate, snapshot.at)
account  = snapshot.householdAccounts.find(a => a.id === p.finance.accountId)   // 可为 undefined
income   = deriveIncome(...)?.incomeMinor ?? 0                                   // 只统计 actorIds 含 p.id 的 finance.settlement
scale    = max(1, |income|)

health        = clamp01(1 - min(1, 0.30·untreated + 0.12·treated) - 0.25·clamp01((age - 50) / 50))
economy       = clamp01(0.5 + 0.5·balance / (|balance| + scale))，balance = account?.balanceMinor ?? 0
knowledge     = clamp01(BASE[p.education.completed] + (p.education.enrolledIn === null ? 0 : 0.15) + 0.20·p.traits.aptitude)
                  BASE = { none: 0.10, primary: 0.30, secondary: 0.50, tertiary: 0.75 }
relationships = 主角参与且 until === null 的关系上「主角自己的 bond」质量的平均；没有有效关系 → 0
                  quality = (trust + intimacy + (1 - conflict)) / 3
delta         = clamp(0.05·(正面条数 - 负面条数), -0.15, +0.15)
                  窗口：addDays(snapshot.at, -730) <= fact.at <= snapshot.at，且 fact.actorIds 含 p.id
                  正面：career.hired、education.admitted、education.secondary-completed、education.tertiary-completed
                  负面：health.illness-onset、career.job-lost、education.admission-failed、
                        finance.settlement 且 outcomeCode === 'in-debt'
happiness     = clamp01(0.30·health + 0.25·economy + 0.25·relationships + 0.20·knowledge + delta)
```

- 全部计算是输入的函数：不用 `Math.random`、`Date.now`、`new Date()`，不读环境；不修改传入的 `snapshot` / `facts`（不得排序或改写原数组）。
- 死亡角色照常返回数值（显示最终状态），不要抛错、不要返回 `null`。
- 指标基线是 **D 级设计假设**（0.30/0.12/0.25、0.5、0.15、0.20、基准表、0.30/0.25/0.25/0.20 与 ±0.15）：在代码注释里写明「设计假设，非统计值」，界面说明文字也要披露。
- 这些常数提到模块顶层的具名常量（例如 `HEALTH_ILLNESS_WEIGHT`），测试引用常量而不是重复数字。

### 2. 属性测试（fast-check，同一文件）

1. 范围：任意合法夹具 + 任意数值改动 → 五个值都在 `[0,1]`，`indicatorPercent` 的每个结果都是 `[0,100]` 的整数。`numRuns: 200`。
2. 健康单调：把某个 `treated` 条件改成未治疗（或新增一个未治疗条件）→ health **不升**；反向改成已治疗 → **不降**。`numRuns: 200`。
3. 经济单调：余额减少（负债增加）→ economy **不升**。`numRuns: 200`。
4. 知识单调：`education.completed` 按 `none < primary < secondary < tertiary` 提升 → knowledge **不降**（提升时保持 `enrolledIn === null` 且 `employment.status = 'not-in-labor-force'`，否则快照不合法）。`numRuns: 100`。
5. 关系单调：提高某条关系主角侧 `trust` / `intimacy` → relationships **不降**；提高 `conflict` → **不升**。`numRuns: 200`。
6. 纯函数：同一输入调用两次结果完全相同，且调用前后的 `snapshot` / `facts` 规范 JSON 不变。`numRuns: 50`。

属性回调一律写成带花括号的函数体，不要返回断言结果。
