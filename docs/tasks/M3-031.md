# M3-031：政体 / 地点历史名称显示层与长名称布局

| 项       | 内容                                                                                                                    |
| -------- | ----------------------------------------------------------------------------------------------------------------------- |
| 风险     | 中（`real-world` 显示层 + 界面；不改模拟、存档、契约或国家包数据）                                                      |
| 前置依赖 | M3-001（政体更替作用于在世角色）。在 M3-001 之前只能显示出生时的政体，无法正确显示 1991 年后的变化                      |
| 涉及模块 | `packages/real-world`、`apps/web`                                                                                       |
| 预计改动 | 新增 1 个显示层文件 + 1 个界面组件 + 测试；修改 `narrator.ts`、`PlayPage`、`SummaryCard`、`CharacterCreationPage`、i18n |

## 目标

让「出生地 / 政治实体 / 国籍 / 现居地」在界面上分开显示，并按**日期**解析历史名称：苏联时期显示苏联，1991-12-26 之后显示俄罗斯联邦；列宁格勒在 1991-09-06 前显示列宁格勒、之后显示圣彼得堡。所有解析通过可复用函数完成，不写死「苏联 → 俄罗斯」这一条分支。

## 背景

- 现有能力：`packages/country-packs/src/resolve.ts` 已提供 `assignmentAt`、`politicalEntityAt`、`adminUnitAt`、`placeNameAt`（按日期半开区间解析）；`PoliticalEntity` 自带 `names` 与 `validFrom/validTo`。
- 现有缺陷：`real-world/src/narrator.ts` 在创建时用**出生日期**冻结全部地点名称；`PlayPage` 的政体也取自出生时的 `session.birth.politicalEntityId`。所以 1991 年后仍会把列宁格勒/苏联显示成出生时的名称。
- 数据结构已分离（GDD §5）：`CharacterState` 有 `birthPlaceId`、`currentResidenceId`、`politicalEntityId`、`citizenshipIds`；`BirthContext` 有出生时的政体与地点。**本任务不新增字段。**
- 加盟共和国扩展：显示层只认 `polityId` + 日期 + 名称，未来在数据层新增政治实体与 `placeAssignments` 即可出现「乌克兰」「哈萨克斯坦」等，不需要改显示层的分支逻辑。数据扩展另立任务（受 Q6/Q11 约束）。
- 长名称：中文「俄罗斯（含苏联时期）」、英文「Russia (incl. Soviet era)」、政体全名「朝鲜民主主义人民共和国」等不能把卡片/列表挤坏。

## 实现要求

### 1. `display.ts`（纯函数，无 DOM、无时间）

    export interface PlaceRef { placeId: string; date: ISODate; }
    export interface PoliticalRef { polityId: string; date: ISODate; }

    export function placeLabel(pack: CountryPack, placeId: string, date: ISODate, locale: Locale): string;
    export function polityLabel(pack: CountryPack, polityId: string, locale: Locale): string;
    export function polityAtPlace(pack: CountryPack, placeId: string, date: ISODate): PoliticalEntity;
    export function placeWithPolity(pack: CountryPack, placeId: string, date: ISODate, locale: Locale): {
      place: string; polity: string; combined: string;
    };
    /** 出生地（按出生日期）与现居地（按当前日期）分开；国籍按角色状态。 */
    export function describeCharacterLocations(
      pack: CountryPack,
      actor: { birthPlaceId: string; birthDate: ISODate; currentResidenceId: string; politicalEntityId: string; citizenshipIds: readonly string[] },
      today: ISODate,
      locale: Locale,
    ): {
      birth: { place: string; polity: string };
      residence: { place: string; polity: string };
      politicalEntity: string;
      citizenship: string[];
    };

- 全部通过 `placeNameAt / politicalEntityAt / polity.names` 解析；遇到未知 ID 抛错（不要静默回退到现代名称）。
- 不缓存「苏联 → 俄罗斯」之类映射；缓存只允许按（packId, placeId, date, locale）做纯记忆化。

### 2. 叙事按事实日期解析

- `createRealNarrator` 保留现有的币制/金额逻辑；新增：
  - `enums.polity`：所有政治实体的 `id → name[locale]`；
  - 渲染一条事实时，若 `details` 含 `place`、`fromPlaceId`、`toPlaceId``，用 `fact.at` 解析地点名并覆盖该 ID 的枚举；
  - 缓存键必须包含地点 ID 与解析后的名称，避免用出生日期冻结。
- 现有出生事实的渲染结果保持不变（出生地的解析日期 = 出生日期）。

### 3. 界面显示

- 角色卡：
  - 第一行：地区短名（`pack.names`，现有）；
  - 「出生」：`placeWithPolity(pack, birthPlaceId, birthDate)`；
  - 「现居」：`placeWithPolity(pack, currentResidenceId, currentDate)`；
  - 「政治归属」：`polityLabel(actor.politicalEntityId)`；「国籍」：`citizenshipIds` 映射后的名称（多个用「、」/「, 」连接）。
  - 若出生地与现居地相同且政体相同，合并为一行，避免重复。
- 出生设置：地区列表保留短名（随机/中国大陆/日本/…），不显示历史政体全名；旗帜任务在 M3-032 接入。
- 时间线：叙事使用上面的日期感知渲染；地点/政体名称不得出现「苏联 → 俄罗斯」硬编码文本。
- 长名称布局：新增 `PlacePolityLabel`：
  - 主行地名、次行政体名（或反之），最多两行；
  - `min-width: 0`、`overflow-wrap: anywhere`、`line-height: 1.3`；
  - 卡片/列表/详情共用同一个组件与 CSS 类；不得只在某一页临时加样式；
  - 时间线事实文本同样允许断词，不产生横向滚动。
- 双语：新增「出生 / 现居 / 政治归属 / 国籍 / 苏联 / …」等界面标签加入 zh-Hans 与 en；名称本身来自国家包数据。

## 验收测试

1. `display.test.ts`：
   - RU 角色：`polityAtPlace(pack, 'place:ru-moscow', '1980-01-01')` 的 id 为 `polity:ussr`、名称为「苏联」/「Soviet Union」；`'1992-01-01'` 为 `polity:ru-russian-federation`、名称为「俄罗斯联邦」/「Russian Federation」。
   - `placeNameAt`：`place:ru-saint-petersburg` 在 `1991-09-05` 为「列宁格勒」，`1991-09-06` 为「圣彼得堡」。
   - 用一个测试夹具包（虚构第三个政治实体）证明 `polityLabel` 按 ID 解析，不依赖国家代码或固定分支。
   - 未知 polityId/placeId 抛错。
2. 叙事：RU 1980 出生事实在 zh/en 下包含「苏联」/「Soviet Union」；构造一条 `at: '1992-01-01'`、`details: { from: 'polity:ussr', to: 'polity:ru-russian-federation' }` 的夹具事实，渲染为对应名称；列宁格勒相关事实按事实日期切换。
3. 界面（Testing Library 或 E2E）：RU 1980 出生角色在 1992 年推进后，角色卡显示出生地「莫斯科，苏联」、现居「莫斯科，俄罗斯联邦」与国籍「俄罗斯联邦」；1978 年时两者都是苏联。
4. 长名称：在 320px 与 390px 视口下，用「俄罗斯（含苏联时期）」「朝鲜民主主义人民共和国」等名称渲染角色卡/列表，断言无横向溢出、无文字重叠（截图或 scrollWidth 断言）。
5. 现有 14 项 E2E 全部通过；事实数量、存档与模拟结果不变。
