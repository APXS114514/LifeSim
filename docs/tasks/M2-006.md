## 目标

创建 `@lifesim/data-registry`：接收一组统计序列，按（指标、地理、年、年龄）精确查数。缺失时返回明确的「缺失」结果，**绝不返回 0**。回退规则不在本任务（见 M2-007）。

## 背景（只需知道这些）

- 统计序列格式：M2-001 的 `StatSeriesSchema`（`packages/content-schema/src/series.ts`）。
- 依赖方向已在 `scripts/check-boundaries.mjs` 登记：`@lifesim/data-registry` 只能依赖 `@lifesim/content-schema`。
- 包的结构照抄 `packages/narrative`：`package.json`（`exports` 指向 `./src/index.ts`、`typecheck` 脚本）、`tsconfig.json`。
- 断点（`Breakpoint`）在本任务只定义 schema、由构造函数接收并保存，**不参与查询**（M2-007 使用）。

## 实现要求

### 包

- `package.json`：`"name": "@lifesim/data-registry"`，`private: true`，`type: module`，`license: MIT`，`sideEffects: false`，`exports: { ".": "./src/index.ts" }`，`scripts.typecheck: "tsc -p tsconfig.json"`。
- 依赖：`pnpm --filter @lifesim/data-registry add '@lifesim/content-schema@workspace:*' zod@<与 content-schema 相同的精确版本>`。

### `breakpoint.ts`

```ts
export const BreakpointSchema = z.strictObject({
  id: z.string().min(1),
  /** 断点适用的地理单位。 */
  geographyIds: z.array(EntityIdSchema).min(1),
  /** 断点日期：该日期所在年份前后属于不同口径。 */
  date: ISODateSchema,
  /** 只影响这些指标；不同指标的口径断点不同（例如币制改革不影响出生数）。 */
  indicators: z.array(IndicatorSchema).min(1),
  reason: z.string().min(1),
  sourceIds: z.array(SourceIdSchema).min(1),
});
export type Breakpoint = z.infer<typeof BreakpointSchema>;
```

### `registry.ts`

```ts
export interface LookupQuery {
  indicator: Indicator;
  geographyId: string;
  year: number;
  /** 单岁年龄；ageBasis 为 'none' 的指标必须省略或为 null。 */
  age?: number | null;
}

export type LookupMethod =
  | 'exact'
  | 'fallback-neighbor-year'
  | 'fallback-parent-geography'
  | 'hold-first-observed'
  | 'scenario-hold-last';

export type LookupResult =
  | {
      status: 'found';
      value: number;
      method: LookupMethod;
      seriesId: string;
      /** 实际取值的年份与地理单位（回退时与查询不同）。 */
      sourceYear: number;
      sourceGeographyId: string;
      projected: boolean;
      evidence: EvidenceMeta;
    }
  | { status: 'missing'; reason: string };

export interface RegistryOptions {
  breakpoints?: readonly Breakpoint[];
  /** 地理单位 → 上级地理单位（M2-007 使用）。 */
  parents?: Readonly<Record<string, string>>;
}

export class DataRegistry {
  constructor(series: readonly unknown[], options?: RegistryOptions);
  lookup(query: LookupQuery): LookupResult;
  get series(): readonly StatSeries[];
  get breakpoints(): readonly Breakpoint[];
}
```

构造函数：

1. 每个序列用 `StatSeriesSchema.parse` 校验；失败时抛出的错误消息要包含序列下标（以及能取到的 `id`）。
2. 同一（`indicator`, `geographyId`）出现两个序列时抛 `Error`，消息包含两个序列的 `id`。
3. 每个断点用 `BreakpointSchema.parse` 校验。
4. 建立索引（`Map`），使单次查询不需要遍历全部点。

`lookup`（本任务只实现精确查询）：

| 情况                                                 | 结果                                                                                                                                       |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 指标为 `'none'` 年龄口径，但 `query.age` 是数字      | 抛 `TypeError`                                                                                                                             |
| 指标为 `'single-year'`，但 `query.age` 缺省或为 null | 抛 `TypeError`                                                                                                                             |
| 没有该（指标、地理）的序列                           | `{ status: 'missing', reason: 'no <indicator> series for <geographyId>' }`                                                                 |
| 序列里没有该（年、岁）的点                           | `missing`，reason 包含年份（与年龄）                                                                                                       |
| 点存在但 `value` 为 null                             | `missing`，reason 等于该点的 `missingReason`                                                                                               |
| 点存在且有值                                         | `found`，`method: 'exact'`，`sourceYear` = 查询年，`sourceGeographyId` = 查询地理，`projected` = 点的标记，`evidence` = 序列证据的**副本** |

`index.ts` 导出 `registry.ts` 与 `breakpoint.ts` 的全部内容。

## 验收测试（必须新增，写在 `registry.test.ts`）

在测试文件中定义夹具序列（注释标明「测试夹具，数值虚构」）：`test/CN/births`（1950、1951、2024，2024 为预测）、`test/CN/qx`（2000 年 age 0—2），以及一个含缺失点的 `test/JP/births`（1950 有值，1951 为 null、`missingReason: 'fixture gap'`）。

1. 精确命中：births 1951 返回 `found`、`method: 'exact'`、值正确；2024 返回 `projected: true`。
2. qx 2000 age 1 命中；age 3 返回 `missing`。
3. 缺失点返回 `missing` 且 reason 为 `'fixture gap'`——**并断言结果里没有 `value: 0`**。
4. 未登记的地理返回 `missing`。
5. 年龄口径用错时抛 `TypeError`（两种情况）。
6. 重复（指标、地理）的序列在构造时抛错；不合法的序列在构造时抛错且消息含下标。
7. 修改返回的 `evidence` 不影响后续查询结果（证明返回的是副本）。
