## 目标

加入政治实体、行政单位、地点、地点归属的 schema，以及「某个日期哪条记录有效」的纯函数。**只加契约、工具函数与测试，不写任何国家的数据。**

## 背景（只需知道这些）

- GDD §5：物理地点（`placeId`，永不改变）、行政归属（随时期变化）、政治实体（随时期变化）要分开存。例如列宁格勒 1991 年改名圣彼得堡，地点 ID 不变，只是名称换了；同一个地点在 1991-12-26 之前属于苏联，之后属于俄罗斯联邦。
- 有效期一律是**半开区间**：`validFrom` 当天有效，`validTo` 当天**不再**有效；`null` 表示不设限。
- 「其他城镇地区」「其他农村地区」是人口池地点（GDD §4.3），不是真实城市。

## 实现要求

### Schema（字段、取值与规则不得改变）

```ts
export const LocalizedNameSchema = z.strictObject({
  'zh-Hans': z.string().min(1),
  en: z.string().min(1),
});
export type LocalizedName = z.infer<typeof LocalizedNameSchema>;

const validity = { validFrom: ISODateSchema.nullable(), validTo: ISODateSchema.nullable() };

export const PoliticalEntitySchema = z.strictObject({
  id: EntityIdSchema,
  names: LocalizedNameSchema,
  ...validity,
  sourceIds: z.array(SourceIdSchema).min(1),
});

export const ADMIN_LEVELS = ['country', 'province', 'municipality', 'unspecified'] as const;
export const AdminUnitSchema = z.strictObject({
  id: EntityIdSchema,
  names: LocalizedNameSchema,
  level: z.enum(ADMIN_LEVELS),
  ...validity,
  sourceIds: z.array(SourceIdSchema).min(1),
});

export const PLACE_KINDS = ['city', 'other-urban', 'other-rural'] as const;
export const PlaceNameSchema = z.strictObject({ ...validity, names: LocalizedNameSchema });
export const PlaceSchema = z.strictObject({
  id: EntityIdSchema,
  kind: z.enum(PLACE_KINDS),
  settlement: z.enum(['urban', 'rural']),
  names: z.array(PlaceNameSchema).min(1),
  sourceIds: z.array(SourceIdSchema).min(1),
});

export const PlaceAssignmentSchema = z.strictObject({
  placeId: EntityIdSchema,
  adminUnitId: EntityIdSchema,
  politicalEntityId: EntityIdSchema,
  ...validity,
  sourceIds: z.array(SourceIdSchema).min(1),
});
```

为每个 schema 导出 `z.infer` 类型（`PoliticalEntity`、`AdminUnit`、`Place`、`PlaceName`、`PlaceAssignment`）。附加规则：

| #   | 规则                                                                                                        | 适用                                            |
| --- | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 1   | `validFrom` 与 `validTo` 都非 null 时，`validFrom < validTo`                                                | 带有效期的四个 schema（`PlaceNameSchema` 也算） |
| 2   | `kind === 'other-rural'` ⇔ `settlement === 'rural'`；`city`、`other-urban` 的 `settlement` 必须是 `'urban'` | `PlaceSchema`                                   |
| 3   | `names` 中各时段互不重叠（用下面的 `findOverlaps`）                                                         | `PlaceSchema`                                   |

### 工具函数（同一文件导出）

```ts
export interface Validity {
  validFrom: ISODate | null;
  validTo: ISODate | null;
}

/** validFrom ≤ date < validTo（null 表示不设限）。 */
export function isValidOn(record: Validity, date: ISODate): boolean;

/** 当天唯一有效的记录；没有返回 null；多于一条抛 Error（数据重叠）。 */
export function resolveOn<T extends Validity>(records: readonly T[], date: ISODate): T | null;

/** 有效期相互重叠的记录下标对 [i, j]（i < j），按 i、j 升序。 */
export function findOverlaps(records: readonly Validity[]): [number, number][];

/** [from, to) 内没有任何记录覆盖的区间，按时间升序；to 为 null 表示一直到无穷。 */
export function findGaps(
  records: readonly Validity[],
  from: ISODate,
  to: ISODate | null,
): { from: ISODate; to: ISODate | null }[];
```

示例（必须作为测试用例）：

| 调用                                                                        | 结果                                         |
| --------------------------------------------------------------------------- | -------------------------------------------- |
| `isValidOn({ validFrom: '1991-12-26', validTo: null }, '1991-12-25')`       | `false`                                      |
| `isValidOn({ validFrom: '1991-12-26', validTo: null }, '1991-12-26')`       | `true`                                       |
| `isValidOn({ validFrom: null, validTo: '1991-12-26' }, '1991-12-26')`       | `false`                                      |
| `findOverlaps([{null,'2000-01-01'}, {'1999-06-01', null}])`                 | `[[0, 1]]`                                   |
| `findOverlaps([{null,'2000-01-01'}, {'2000-01-01', null}])`                 | `[]`（首尾相接不算重叠）                     |
| `findGaps([{null,'1991-09-06'}, {'1991-09-07', null}], '1950-01-01', null)` | `[{ from: '1991-09-06', to: '1991-09-07' }]` |
| `findGaps([{'1960-01-01', null}], '1950-01-01', null)`                      | `[{ from: '1950-01-01', to: '1960-01-01' }]` |
| `findGaps([], '1950-01-01', null)`                                          | `[{ from: '1950-01-01', to: null }]`         |
| `resolveOn` 在两条记录同时有效的日期                                        | 抛 Error                                     |

## 验收测试（必须新增，写在 `geography.test.ts`）

1. 上表每一行一个断言。
2. 每个 schema 至少一个合法样例通过、一个违反附加规则的样例被拒绝。
3. `PlaceSchema`：名称时段重叠被拒绝；`kind: 'other-rural'` 配 `settlement: 'urban'` 被拒绝。
4. fast-check 性质测试：随机生成首尾相接、互不重叠的有效期序列，`findOverlaps` 返回 `[]`，`findGaps(…, 最早起点, null)` 返回 `[]`，且序列内任意日期 `resolveOn` 恰好返回一条。

测试里的地点、实体都用明显虚构的 ID（如 `place:test-a`），并注释为测试夹具。
