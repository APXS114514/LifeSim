# M3-015：疾病状态机与医疗决策

> 2026-10-22 P2 规格刷新：按 `main` `8742255` 的代码与已采纳 ADR 重写。当前 `SYSTEMS_VERSION = 0.10.0`、`SNAPSHOT_SCHEMA_VERSION = 2`。本文件只更新规格，不实施；旧稿把「五国共用 1980 年治疗可得」与 `treated` 布尔字段当作既定设计，本稿把前者降为**待替换的现状**（真实地区目前仍是 `REAL_RULES.treatmentAvailableFrom = 1980`），后者改为状态机字段。

## 目标

把「一条慢性病 + 治疗/不治疗」升级为**疾病持续状态机**：发病 → 诊断 → 治疗 → 康复或长期影响；疾病影响就业、收入、家庭支出与关系；医疗可及性随国家与年代变化；死亡风险仍只在 `health.check` 里抽一次，不重复计数。

本任务不改变 M3-016 的死亡风险校准与 0.5—3.0 限幅数值；只提供疾病状态与「是否治疗」的输入。

## 交付拆分（建议，按道 K / 道 R 分工）

- **M3-015a（契约与规则数据，建议道 K）**：`HealthConditionSchema` 新字段、`HealthQueries.careAccess` 接口、国家包 `health.careAccess` schema、`SNAPSHOT_SCHEMA_VERSION` 提升、旧快照非破坏性测试。判定：`pnpm verify` 通过；不改变现有抽样时黄金不变。A 段先加字段与接口，`treated` 暂保留并由不变量强制与 `treatmentStartedOn` 一致；删除 `treated` 与更新读取方放在 B 段，避免一次同时改契约与规则。
- **M3-015b（规则与验收，道 R）**：状态机、诊断/治疗/康复事件、费用、就业/指标读取方、叙事、黄金更新。判定见「验收测试」。
- 若合并交付，报告必须分列契约与规则的高风险点，并由维护者审查。

## 背景（现状与已定约束）

### 1. 代码现状（2026-10-22，`main` `8742255`）

- `HealthConditionSchema` 只有 `id`、`onset`、`treated: boolean`、`factId`；`HealthStateSchema` 只有 `conditions[]`（`packages/content-schema/src/character-state.ts`）。
- `packages/systems/src/health.ts` 只有一条疾病路径：`health.check` 在无病时抽 `illnessOnsetP`，发病即 `id: 'chronic'`、`treated: false`，并立即排 `choice.treatment`；治疗是二选一，可得性只看 `year >= region.rules.treatmentAvailableFrom`（真实地区目前共用 `REAL_RULES.treatmentAvailableFrom = 1980` 这一个常数，见 `packages/real-world/src/region-model.ts`；不是按国家的数据）。本任务要把它替换为按国家/年份的 `careAccess`；合成地区可以继续用该常数做 D 级默认，真实地区不得继续五国共用 1980。费用是一次性 `treatmentCostMinor` 加上 `finance.settle` 里按 `treatmentAnnualCostShare` 计的年度费用。
- `RegionModel.illnessOnsetP` 目前只看年龄（约 35 岁起线性上升，D 级），没有国家/年代/性别差异；本任务不重写发病率基线，只把它作为 D 级输入。
- 死亡与死因在 `health.check` 的**同一次**检查里确定：先抽 `scaleAnnualProbability(mortalityQ(...), multiplier)`，再抽 `offsetDays` 与 `byIllness`；疾病只改乘数，不另抽死亡。这是 GDD §8.3 与 ADR-0007 §7 的红线。
- 读取 `treated` 的地方：`shared.ts` 的 `untreatedIllness`/`hasIllness`；`finance.ts` 的年度治疗费；`career.ts` 的求职/失业惩罚；`indicators.ts` 的健康指标；`life-events.ts` / `life-events-catalog.ts` 的 `daily-routine.sick-leave`；测试夹具。**改字段必须一次性更新这些读取方**，否则会出现「状态机说已康复、财务还在收费」。
- `npc.ts` 让 NPC 复用共享 `health.check` 处理器，但 `npcContext` 丢弃 `choice.treatment`（不为 NPC 结算收支）。新增的诊断/结局事件也必须明确 NPC 是否排程，否则会排出一个无法处理的治疗决定。
- 学制不是本任务的核心；但付款方判断要用 `isIndependent` / `isIndependentForSettlement` 与 `RegionRules.minimumWorkingAge`，不得写死成年年龄。
- 年度重点 `FOCUS_EFFECTS` 只有 `onset` 与健康相关（`health` 0.85、`work` 1.1、`leisure` 0.95），没有「治疗」「诊断」「康复」键；见下文口径。
- 性能基线（G1）：约 **842 事件/局、341—342 事实/局、p50 ≈ 5.9 ms**；每事实预算 `p50 ≤ 5.5 × (事实数 / 167)`。见 [V0.1_PLAN](../V0.1_PLAN.md) §4 与 [G1-PERF-PROFILE](../audits/G1-PERF-PROFILE.md)。

### 2. 已定的约束

- **GDD §8.3**：疾病是持续状态（发生、症状、诊断、治疗、康复或慢性影响），能影响现金流和就业；医疗条件因时代/地区而异；死亡风险与生命表统一校准，疾病只改乘数，绝不单独再抽一次死亡。
- **ADR-0007 §7**：死亡乘数链先乘后限幅，建议下限 0.5、上限 3.0（维护者已确认）；死因与死亡在同一次检查里确定；本任务不改变这些数值，也不新增死亡抽样。
- **ADR-0010 A1**：角色有 `sex`，但其他规则默认不按性别区分概率。疾病发病率在现实中确有性别差异，但**没有可再分发的五国历史序列**；本任务默认不按性别区分，若以后用可核验数据区分，必须单独审查。
- **数据**：疾病发病率没有可再分发的五国历史序列（WDI 没有；IHME GBD 是 CC BY-NC-SA，与本项目 MIT 公开构建冲突，**禁止引入**）。本任务必须使用明确的 D 级年代化假设表，并在 ADR-0007 增补中登记；不得伪装成统计。
- **M3-042 / M3-041 边界**：通用事件原型不得发出 `health.*` 事实，也不得新增/修改 `health.conditions`；年度重点只乘 `onset`，不乘诊断、治疗、康复或死亡风险。
- **M3-016**：死亡风险统一模型与校准归 M3-016；本任务只保证「状态 → 乘数」的接口稳定，不自行改 `RegionEffects.mortality` 的数值或容差。

## 与现有机制的接口

### 1. 年度重点乘数：哪些乘、哪些不乘

| 项                                 | 是否乘年度重点 | 说明                                                                   |
| ---------------------------------- | -------------- | ---------------------------------------------------------------------- |
| `illnessOnsetP` 发病               | **乘 `onset`** | `health.check` 已调用 `focusProbability(..., 'onset')`；不得重复乘     |
| 诊断概率/诊断可得性                | **不乘**       | `FOCUS_EFFECTS` 没有诊断键；诊断由医疗可及性与年代决定                 |
| 治疗决定（去/不去）                | **不乘**       | 治疗是选项与负担能力，不是年度重点概率                                 |
| 康复/慢性化                        | **不乘**       | 由病情、治疗与医疗质量决定，不由年度重点决定                           |
| 死亡风险                           | **不乘**       | 只通过疾病状态改变乘数；`FOCUS_EFFECTS` 没有死亡键                     |
| `stress` / `ties`                  | 本任务不写     | `focus.complete` 已经一次性写入；不得在健康事件里重复写                |
| `education` / `hiring` / `jobLoss` | 不用于本任务   | 分别归教育/职业；疾病对就业的惩罚走 `RegionEffects.illness*`，不乘重点 |

新增「治疗依从性」「复查概率」等新概率时，必须：① 使用已有键并写明映射；或 ② 明确不乘并在披露中说明。新增 `FOCUS_EFFECTS` 键属于 M3-041 的设计变更，需先改表、披露与测试，执行 Agent 不得自行加键。

### 2. M3-042 通用人生事件：避免重复、`when` 如何读新字段

- 原型运行器与纯函数约束见 `life-events.ts`：`eligible`、`variant.when`、`topicAvailable` 不抽随机数、不写状态。
- 现有读取疾病的地方只有 `daily-routine.sick-leave` 的 `untreatedIllness`（以及测试夹具）。改成新字段后必须定义**唯一的纯函数谓词**（放在 `shared.ts` 或 `life-events.ts`，只读）：
  - `hasActiveCondition(actor)`：存在 `stage !== 'recovered'` 的疾病；
  - `hasActiveUntreatedCondition(actor)`：存在 `stage ∈ {onset, diagnosed}` 或 `stage === 'chronic' && treatmentStartedOn === null` 的疾病。
- `daily-routine.sick-leave` 用 `hasActiveUntreatedCondition`，与现在「未治疗的慢性病才请病假」的语义一致。**不得**让原型发出 `health.*` 事实、不得 push/patch `health.conditions`、不得改 `stage`。健康事实只由 `health.ts` 产生，避免「原型请病假」和「健康事件发病」各记一次。
- `minor-mishap` 明确**不**创建疾病、不改 `health.conditions`（M3-042 的既有决定；若未来要表达受伤，需要新的细状态与单独审查）。
- 任何对 `when` 的修改都会改变事实；必须列出原型 id、旧/新谓词、黄金差异、披露行，并经维护者批准。v1 默认只把谓词从 `treated` 换成 stage，不新增原型。

### 3. 细状态（`stress` / `ties` / `skills`）

- 本任务**不写** `wellbeing.stress`、`social.ties`、`skills`。疾病对幸福的影响已经由 `indicators.ts` 从 `health.conditions` 派生；若要在确诊/慢性化时额外写压力，属于新的写入者，需在 ADR-0010 B 范围内单独批准，本任务不做。
- 疾病的唯一权威状态是 `health.conditions[]`；可见健康指标仍是纯函数派生（M4-016），不得把指标写回状态。

### 4. 学制与独立性

- 学制不是本任务的核心；但治疗/诊断的付款方与「是否成年」必须用 `isIndependent(actor, age, region)`、`isIndependentForSettlement` 与 `RegionRules.minimumWorkingAge`，不得写死 18 岁。
- 儿童与在读学生的治疗费由家庭承担（见下），不因上学/未成年而失去治疗机会。

### 5. 「未独立时由家里承担」的金钱规则

- 现状：`health.ts` 的治疗选项用 `account(actor).balanceMinor >= cost` 判断可负担，并从**本人账户**扣款。对儿童/学生来说，这会把医疗费变成孩子的债务，进而通过 `isPoor` 抬高其发病率与死亡率——与 M3-012c 的学费规则、M3-042 的日常花费规则都不一致。
- 本任务要求：治疗费付款方与学费一致——
  1. 有自己收入（`employed` / `retired`）时用本人账户；
  2. 否则用在世父母账户，按 `state.relationships` 里亲子关系顺序平均分摊，余数给第一位；
  3. 没有在世父母时才用本人账户。
- 为避免在 `education.ts` 与 `health.ts` 各写一份，允许把 `tuitionPayers` / `chargeTuition` 的通用部分抽到 `shared.ts`（例如 `familyPayers(state, actor)`），并保持学费行为不变。抽取必须带等价测试；不得顺手改学费规则。
- 已知缺口：没有在世父母的未独立患者如果必须自付，账户可能为负。本任务按 M3-012c 的同一口径处理（自付、可为负），并在报告中记为已知缺口；是否改为「制度/亲属吸收」是维护者决定（见「需要维护者决定的问题」6）。

### 6. 每事件成本（G1 预算）

| 项             | 预算                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------- |
| 新增事件       | **≤ 8 个/局**（每次发病：诊断 1 + 治疗决定 1 + 结局 1；年度 `health.check` 已有，不另加年度事件） |
| 新增事实       | **≤ 6 条/局**（发病、诊断、治疗/拒绝、康复/慢性化；年度结算的 details 扩展不算新事实）            |
| 相对事实数变化 | 预计 **< 2%**；若 > 10%，按 V0.1_PLAN §4 重测并更新阈值                                           |
| 实测           | 实施后给出 `pnpm bench --lives 1000` 的 p50/p95 与 `processedKeys.length`，与改前对照             |

如果实现成「每年为每个慢性病患者排一条复查/治疗决定」，事件数会随患病年数线性增长，超出预算；必须用「发病 → 诊断 → 治疗 → 结局」的有限链条，慢性化后的年度费用由 `finance.settle` 承担，不另排事件。

**跨字段规则**：

1. `diagnosedOn !== null ⇔ stage !== 'onset'`。
2. `treatmentStartedOn !== null ⇒ stage ∈ {treated, recovered, chronic}`。
3. `stage === 'treated' ⇒ treatmentStartedOn !== null`；`stage === 'recovered' ⇒ treatmentStartedOn !== null`（v1 的 D 级假设：康复只经由治疗；自然康复不建模）。
4. `stage === 'chronic'` **允许** `treatmentStartedOn === null`（未治疗的长期病），也允许已治疗；这是与旧稿「treatmentStartedOn ⇔ treated/recovered/chronic」不同的地方——否则未治疗慢性病无法表达。
5. `onset <= diagnosedOn <= treatmentStartedOn`（非空时）；日期都不得早于出生。
6. `stage ∈ {recovered, chronic}` 是终态；`onset` / `diagnosed` / `treated` 可以继续流转。
7. v1 最多一条活动疾病；新增第二条活动疾病需要新的发病率数据/ADR，不得在同一阶段静默放开。
8. `severity` 0—1；治疗可以降低，慢性化可以保留；具体增量是 D 级假设，登记在 ADR-0007 增补。

**版本与兼容**：

- 删除 `treated`、新增必填字段会让旧快照无法通过 `HealthConditionSchema`。按 Q9：旧存档保留原文、允许导出、提示不兼容，**不写迁移器、不静默把旧 `treated` 映射成 `stage`**。
- `SNAPSHOT_SCHEMA_VERSION` 提升由道 K 执行；若与 M3-013/017 合并，统一升一次（见「需要维护者决定的问题」7）。
- `SYSTEMS_VERSION` 提升一次；黄金指纹、CLI 投影、bench 工作量指纹变化逐条解释。
- 旧事实的 `evidence.modelVersion` 保留当时数据版本；不得用新数据改写旧事实。

## 实现要求

1. **契约与读取方**：按上表改 `HealthConditionSchema`；把 `shared.ts` 的 `hasIllness`/`untreatedIllness` 改成 `hasActiveCondition`/`hasActiveUntreatedCondition`；一次性更新 `health.ts`、`finance.ts`、`career.ts`、`indicators.ts`、`life-events-catalog.ts`、`narrative.ts` 与测试夹具。不得保留两份「是否治疗」的判断。
2. **发病**：`health.check` 的发病抽签与死亡抽签顺序**不变**；发病后写 `stage: 'onset'`、`severity: 0.5`、`onsetFactId`/`lastFactId`，并排 `health.diagnosis`（不要在同一天排治疗决定；先诊断）。不得在死亡抽签之前插入新随机数；严重度默认确定性，不抽随机。
3. **诊断**：`health.diagnosis` 在发病后下一次年度健康检查时处理（或按 D 级固定延迟排程）。概率/可得性读 `careAccess(year)`：`diagnosisAvailable` 为假时保持 `onset` 并排下一年复查（最多 N 年，D 级）；为真时按 `quality` 与 D 级概率抽一次（事件自己的随机流）。诊断成功：`stage: 'diagnosed'`、`diagnosedOn`、发 `health.illness-diagnosed`，并排治疗决定。诊断只给主角排；NPC 不排（见第 8 条）。
4. **治疗决定**：只有在 `stage === 'diagnosed'` 时排 `choice.treatment`；选项 `treat` / `forgo`。`treat` 的资格 = `careAccess(year).treatmentAvailable` 且付款方负担得起；不可用时 `ineligibleReason: 'not-yet-available' | 'unaffordable'`；未诊断时治疗选项 `eligible: false`、原因 `not-diagnosed`（防御性；正常排程不会出现）。`forgo` 始终可用。
5. **治疗与费用**：`treat` 时用第 5 节的付款方规则扣费（整数最小单位），写 `treatmentStartedOn`、`stage: 'treated'`、`lastFactId`，发 `health.treatment-started`（details 含 `costMinor`、`currency`、`paidBy`）。年度费用只在 `finance.settle` 对 `treatmentStartedOn !== null && stage !== 'recovered'` 的疾病收取；`recovered` 后不再收。`forgo` 发 `health.treatment-declined`，不改 `stage`（保持 `diagnosed`），并排下一年复查（最多 N 年）。
6. **康复/慢性化**：治疗后在下一年（或 D 级固定延迟）排 `health.outcome`；按 `severity`、`careAccess.quality` 与 D 级阈值确定性决定 `recovered` 或 `chronic`，发 `health.illness-recovered` / `health.illness-chronic`。终态不再流转；慢性化后年度费用由 `finance.settle` 承担，不再每年排治疗决定。
7. **死亡风险**：`health.check` 仍是唯一的死亡抽签点。乘数：`recovered` → 1；`treatmentStartedOn !== null` → `effects.mortality.treatedIllness`；否则 → `effects.mortality.untreatedIllness`。不新增严重度乘数（留给 M3-016）；不改变 0.5—3.0 限幅；不新增死亡抽样。死因归属仍用同一次检查里的 `byIllness`。
8. **NPC**：NPC 复用 `health.check` 发病与死亡，但不排 `health.diagnosis`、`choice.treatment`、`health.outcome`（`npcContext.schedule` 明确丢弃；或在 `health.ts` 里按 `tier` 门控）。NPC 的疾病保持 `onset` 或按 D 级确定性地转 `chronic`（不治疗），死亡乘数按未治疗处理；不为 NPC 造治疗费用。
9. **M3-042 谓词**：按第 2 节把 `daily-routine.sick-leave` 的谓词换成 `hasActiveUntreatedCondition`；列出黄金差异。不得新增原型或让原型写 `health.conditions`。
10. **叙事与双语**：新增 `health.illness-diagnosed`、`health.illness-recovered`、`health.illness-chronic` 的 zh-Hans/en 模板；`health.treatment-started`/`health.treatment-declined` 增加 `condition`、`stage`、`reason` 等参数与 `enums`；所有新增事实双语渲染无残留 `{{`。
11. **版本、黄金与性能**：提升 `SYSTEMS_VERSION`；逐条列出黄金/CLI 投影差异（发病到诊断的延迟、治疗费付款方、慢性化年度费用、M3-042 谓词）；`pnpm bench --lives 1000` 实测事件数与 p50，超预算先改设计。
12. **确定性**：诊断/结果事件的随机流以各自事件键派生；不得在 `health.check` 的死亡抽签前插入新抽样；同一 seed 两次运行逐字节相同。

## 验收测试

### A. 方向性（配对种子）

1. **年度重点**：同一批 200 个固定种子，在相同种子下分别 preset `health` 与 `work`；断言 `health` 的 `health.illness-onset` 数低于 `work`（方向性），且诊断/治疗/死亡流程不被重点直接改变。
2. **慢性病对就业**：同一批种子，用夹具让一半角色在相同年龄患未治疗慢性病、另一半健康（或同一 seed 的两臂）；断言患病臂的 `career.job-lost` 比例更高，报告两侧人数与比例。配对指同一 seed 的两臂，不得只比较两组不同种子。
3. **医疗可及性年代**：同一国家、同一年龄、同一种子，分别跑 1950 与 2000 出生/发病；断言 1950 年的治疗不可得或诊断质量更低（至少 2 个国家），并报告实际 `careAccess` 值。
4. **负向对照**：`family` / `leisure` 重点不应改变 `health.illness-onset` 的方向性（或只通过 `onset` 键改变；按 `FOCUS_EFFECTS` 报告）。

### B. 回归（具体种子）

固定种子清单（实施时若某个种子不触发目标事件，必须在测试文件里替换为另一个**固定**种子并在报告说明；不得运行时随机搜索）：

| 种子        | 目标                                                               |
| ----------- | ------------------------------------------------------------------ |
| `CN-1970-a` | 发病 → 诊断 → 治疗的状态与日期顺序；`diagnosedOn` 在治疗之前       |
| `JP-1978-e` | 治疗可得性随年份；不可得时 `ineligibleReason: 'not-yet-available'` |
| `KR-2005-a` | 儿童/学生治疗费用由在世父母承担；本人账户不为负（有父母时）        |
| `RU-1952-d` | 未治疗慢性病不产生年度治疗费；死亡乘数按未治疗处理                 |
| `KP-1955-e` | 康复后不再产生该病的年度费用；`stage: 'recovered'` 为终态          |
| `JP-2000-y` | NPC 不排诊断/治疗/结局；NPC 疾病不破坏不变量                       |

- **状态机回归**：断言 `onset <= diagnosedOn <= treatmentStartedOn`；未诊断时治疗选项不可用（`not-diagnosed`）；`recovered` 后 `finance.settlement` 不再含该病费用；`chronic` 可以未治疗。
- **死亡唯一抽签**：用 `mortalityQ = 0` 的地区夹具，断言发病后不产生 `life.death`；用 `mortalityQ = 1` 的夹具，断言死亡只由 `health.check` 产生，疾病事件本身不排 `life.death`。
- **快照**：同 seed 两次运行逐字节相同；往返一致；旧快照（`treated` 字段）按 Q9 非破坏性拒绝，不静默映射。
- **不变量**：`HealthConditionSchema` 正反例（日期顺序、终态、stage 与日期一致）；fast-check 随机生成状态无违规。

### C. 性能（事件数预算）

- 新增事件 **≤ 8/局**、新增事实 **≤ 6/局**；用 `processedKeys.length` 与事实计数对照改前。
- `pnpm bench --lives 1000`：p50 满足每事实预算 `5.5 × (事实数 / 167)`；报告 p50/p95/p99、事实数、快照字节与工作量指纹。
- 若事实数变化 > 10%，按 V0.1_PLAN §4 重测并更新阈值；不得为性能删状态阶段或降低治疗可得性。

### D. 契约、确定性与双语

- fast-check：随机生成 `HealthCondition`，断言跨字段规则；随机生成 `stage` 与日期，断言终态/顺序。
- 五国 × 出生年 1950/1970/1990/2020 × 固定 seed：完整人生可跑完；无日期倒流、无死者新增行为、无不变量违规。
- 双语：新增事实与 `enums` 在 zh-Hans/en 键集合一致、占位符一致、无残留 `{{`。
- GBD/IHME 不得出现在依赖、数据或测试夹具里（用 grep 检查）。

## 完成定义

- 疾病是持续状态，诊断、治疗、康复/慢性化可追溯；医疗条件随国家与年代变化；治疗费付款方与学费/日常花费口径一致。
- 死亡风险仍只在 `health.check` 抽一次；疾病只改乘数，且不改变 ADR-0007 §7 的限幅。
- 发病率、疾病种类、严重度进展、诊断/治疗可得性全部能追溯到 ADR-0007 增补（或新 ADR），B 级数据与 D 级假设可区分。
- 验收 A—D 全过；黄金指纹、CLI 投影、性能与事件数与改前对照均已解释；没有删除/弱化测试。
- 报告列出：实际使用的固定种子、各阶段事件数、治疗费付款方实测、待维护者决定的问题。

## 可能的阻塞（遇到就停止并报告）

1. **ADR-0007 增补未采纳**（`HealthQueries.careAccess`、D 级发病率/严重度/诊断阈值）：停下来报告，不要自行设计接口或数值。
2. **需要 GBD/IHME 数据**：许可是 CC BY-NC-SA，与本项目 MIT 公开构建冲突；报告，不引入。
3. **快照版本提升未获批准**：按 Q9 保留原文并提示不兼容；不要写迁移器或把 `treated` 静默映射成 `stage`。
4. **治疗费付款方抽取破坏学费行为**：先加等价测试；不等价就停止，不要顺手改 M3-012c。
5. **事件数超出预算**：先检查是否每年为慢性病排复查/治疗决定；不要删阶段或降低治疗可得性。
6. **NPC 事件无法处理**：如果诊断/结局事件被排给 NPC 而 `npc.ts` 没有丢弃，先修门控；不要让 NPC 进入没有处理器的状态。

## 需要维护者决定的问题

1. **疾病种类粒度**：v1 只做一个通用 `condition:chronic`，还是按病种（呼吸/心血管/……）拆分？拆病种需要分病种发病率与严重度数据；没有可再分发来源时只能是 D 级假设。本稿默认一个通用病种。
2. **`careAccess` 的归属与数据**：按年可及性是**规则数据**放国家包 `health` 小节，还是作为 `StatSeries` 指标？本稿按 ADR-0007 增补采用规则数据；需要维护者确认接口与数据来源责任。
3. **`treated` 是否保留为派生布尔**：删除（单一来源，所有读取方改）还是保留（兼容读取方，但可能漂移）？本稿默认删除；若保留，必须在不变量里强制 `treated ⇔ treatmentStartedOn !== null`。
4. **严重度进展是否随机**：本稿默认确定性（不抽随机，避免移动既有死亡抽签）；若要随机，必须在独立事件流里抽，并说明对黄金的影响。
5. **疾病是否写 `stress`**：本稿不写；若确诊/慢性化应影响幸福，是否允许健康事件写 `wellbeing.stress`？这需要 ADR-0010 B 的写入者批准。
6. **无在世父母的未独立患者**：治疗费自付（可为负，与学费一致）还是由制度/亲属吸收（新规则）？本稿沿用学费口径，记为已知缺口。
7. **契约与快照版本排期**：M3-013/015/017 是否合并为一次 `SNAPSHOT_SCHEMA_VERSION` 提升？本稿只声明需要提升，不替维护者排期。
8. **治疗成本公式**：继续用现有 `treatmentCostMinor`，还是用「人均卫生支出 × 自付比例 × D 级系数」构造 C 级成本？后者需要方法与容差，写进 ADR-0007 增补；本稿默认不改现有公式。
9. **诊断延迟与复查上限 N**：本稿用 D 级固定延迟（例如 1 年）与复查上限（例如 3 年）；具体值需要维护者确认还是由任务细化决定？
10. **NPC 的疾病进展**：NPC 不治疗、直接按确定性转慢性，是否符合「NPC 是独立的人」？若要 NPC 也有治疗决策，需要 NPC 收支（M3-014/M3-018）先落地。
