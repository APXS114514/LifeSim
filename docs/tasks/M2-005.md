## 目标

为后续的数据转换脚本提供三个经过测试的小工具：解析 CSV、读取可能是 gzip 压缩的文本文件、计算文件的 SHA-256。**不写任何具体数据源的逻辑。**

## 背景（只需知道这些）

- 联合国 WPP 的 CSV 文件里，地名本身可能带逗号（例如 `"China, Hong Kong SAR"`），所以不能用 `split(',')`，必须按 RFC 4180 解析带引号的字段。
- 原始文件可能是 `.csv.gz`。数据脚本运行在 Node 里，可以使用 `node:` 模块；不引入任何 npm 依赖。
- 根目录的 vitest 与 `tsconfig.json` 已经包含 `data/scripts/**`（测试写成 `.test.ts`，源码写成带 JSDoc 类型的 `.mjs`）。

## 实现要求

### `csv.mjs`

```js
/** 把 CSV 文本解析为行，每行是字段字符串数组。 */
export function parseCsv(text);              // => string[][]

/** 以第一行为表头，返回对象数组；字段数与表头不一致时抛错。 */
export function readCsvRecords(text);        // => Record<string, string>[]
```

规则：

1. 分隔符是逗号；字段可以用双引号包裹；引号字段内的 `""` 表示一个 `"`；引号字段内可以有逗号和换行。
2. 行尾可以是 `\n` 或 `\r\n`；文件末尾的换行不产生空行；文件开头的 UTF-8 BOM（`﻿`）去掉。
3. 引号没有闭合时抛出 `Error`，消息包含起始行号（从 1 开始）。
4. `readCsvRecords`：表头字段去掉首尾空格；某行字段数与表头不同时抛出 `Error`，消息包含行号与期望 / 实际字段数；完全空白的行跳过。
5. 不做类型转换：所有值都是字符串。

### `files.mjs`

```js
/** 读取文本文件；路径以 .gz 结尾时先用 gunzip 解压。按 UTF-8 解码。 */
export function readTextFile(path);          // => string

/** 文件内容的 SHA-256，小写十六进制。 */
export function sha256File(path);            // => string
```

使用 `node:fs`、`node:zlib`、`node:crypto`，同步 API 即可。

## 验收测试（必须新增）

`csv.test.ts`：

1. `'a,b\n1,2\n'` → `[['a','b'],['1','2']]`。
2. `'"China, Hong Kong SAR",344\n'` → `[['China, Hong Kong SAR','344']]`。
3. `'"say ""hi""",x\n'` → `[['say "hi"','x']]`。
4. 引号字段内的换行：`'"line1\nline2",x\n'` → `[['line1\nline2','x']]`。
5. CRLF 行尾、开头的 BOM、没有末尾换行，三种情况各一个断言。
6. 引号未闭合抛错且消息含行号。
7. `readCsvRecords('LocID,Location\n156,China\n')` → `[{ LocID: '156', Location: 'China' }]`；字段数不一致时抛错且消息含行号。

`files.test.ts`（在 `os.tmpdir()` 下的临时目录里写文件，测试结束删除）：

1. 普通文本文件与同内容的 `.gz` 文件，`readTextFile` 结果相同。
2. `sha256File` 对内容 `abc` 返回 `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`。
