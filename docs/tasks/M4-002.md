## 目标

让存档在版本变化时安全：校验格式、版本、大小、校验和与 request/snapshot/facts 的对应关系；损坏存档被安全拒绝且不影响正常游戏；M3-lite 的 localStorage 存档按 Q9 已确认的**非破坏性策略**处理（保留原始内容、可导出、提示不兼容；迁移视情况另做）。

## 背景

- GDD §11.4 与 `packages/save/src/envelope.ts` 已有：大小上限、UTF-8、危险键、schema、SHA-256、日志不变量。M4 要把它们接到 IndexedDB 与界面。
- M3 提升了 `SYSTEMS_VERSION` 与可能的 `SNAPSHOT_SCHEMA_VERSION`：旧存档恢复会被内核拒绝。Q9 已确认：保留原始内容、允许导出备份、提示不兼容；M3-000 已实现最小保护。
- 现状：`loadGame()` 遇到任何异常都 `clearGame()` 后返回 null——这会把用户的存档静默删掉，M4 必须改成「拒绝读取但保留数据，并提示」。

## 实现要求

1. **分类**：读取失败必须返回可区分的原因：`too-large`、`not-json`、`forbidden-key`、`bad-envelope`、`unsupported-version`、`checksum-mismatch`、`bad-payload`、`incompatible-engine`、`incompatible-rules`、`missing-data`。
2. **不删数据**：校验失败时**不删除**存档；界面提示「存档无法读取，已保留，可导出后反馈」并提供导出原始字节的入口（导出功能在 M4-003，若有依赖则先提供复制文本）。
3. **localStorage 迁移**：
   - 读取旧键 `lifesim.save.v1`；
   - 若旧存档的 `systemsVersion` 与当前不一致：保留原始内容并提示「旧版本存档不可继续」，**不得**静默删除或改写版本号；玩家可以导出后清除；
   - 一致时迁移进 IndexedDB，迁移成功后保留旧键一个版本周期（不立即删除），再次成功读取后清理。
4. **版本元数据**：记录 `engineVersion`、`systemsVersion`、`dataPackVersions`；不匹配时拒绝，错误提示里说明原因与建议。
5. **大小与配额**：超限时提示用户导出并清理；不得静默丢弃最旧存档。
6. **测试**：不得依赖真实浏览器行为（用 fake-indexeddb 或 Playwright）。

## 验收测试

1. 每种失败分类各一个夹具，断言返回具体原因且存档仍存在（读后仍可列出）。
2. 旧 localStorage 存档：版本不一致 → 提示且不迁移、不删除；版本一致 → 迁移成功、快照一致、旧键保留。
3. 篡改 checksum → `checksum-mismatch`；篡改事实 → `bad-payload`；超大数据 → `too-large`。
4. 正常存档读取不受影响（回归）。
5. 双语提示：zh/en 都有文案，占位符一致（`apps/web/src/i18n/locales.test.ts` 覆盖）。
