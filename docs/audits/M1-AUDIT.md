## 1. 审计范围与方法

逐项阅读 `packages/simulation-core`、`packages/systems`、`packages/synthetic-world`、`apps/cli` 的源码与测试，对照 GDD 的确定性、原子结算、因果日志与死亡终止要求，检查：

模拟确定性 · 状态所有权 · 事件调度 · 快照恢复 · 数值计算 · 因果日志 · 模块依赖 · 测试覆盖 · 性能 · 对 M2—M5 的可扩展性。

每一项都以可重复的命令或测试为证据，不以「看起来没问题」为结论。

## 2. 逐项结论

| 方面         | 结论                                                                                                                                                                       | 证据                                                                                                  |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 确定性       | 通过。随机流由「根种子 + 事件幂等键」派生，与执行顺序无关；风险换算用只依赖四则运算的 `expDet` / `lnDet`；没有读系统时钟或 `Math.random` 的路径（lint 拦截）。             | `random.test.ts` 黄金值；`det-math.test.ts`；`engine.test.ts`「determinism」；`life.test.ts` 黄金指纹 |
| 状态所有权   | 通过（审计后加强）。权威状态只在 `Simulation` 内部；处理器拿草稿，`state` 访问器返回拷贝；**提交的事实现在被冻结**，调用方无法改写日志。                                   | `engine.test.ts`「freezes committed facts」                                                           |
| 事件调度     | 通过。全序（日期、优先级、幂等键）与插入顺序无关；重复键幂等；已处理键再次安排视为循环；同日连锁、每日事件数、单事件后续数都有上限。                                       | `scheduler.test.ts`（新增性质测试）；`engine.test.ts`「atomic settlement」                            |
| 原子结算     | 通过。草稿上处理，事实 / 角色 / 账户 schema、时间与生死约束、系统不变量全部通过后才提交；失败时状态与队列不变，错误带种子、事件键与日期。                                  | `engine.test.ts` 七种陷阱                                                                             |
| 决策         | 通过（审计后加强）。**`options()` 现在被强制为纯函数**：在只读拷贝上运行，抽随机数、追加事实、安排事件都会报 `impure-decision-options`，保证暂停时展示的选项与结算时一致。 | `engine.test.ts`「rejects decision options that draw random numbers」                                 |
| 快照恢复     | 通过。快照经 JSON 往返、存档文件编码解码后恢复，继续推进与不中断逐字节相同；版本、随机算法、数据包版本不匹配时拒绝恢复。                                                   | `engine.test.ts`、`life.test.ts`、`cli.test.ts`                                                       |
| 推进方式等价 | 通过。快进、逐年、每次一个事件三种方式的事实与快照逐字节相同。                                                                                                             | 同上（fast-check 随机种子 × 出生日期）                                                                |
| 数值计算     | 通过。金额是安全整数，重定值用 BigInt；概率在 [0,1]；生命表 q 经风险乘数调整，不另外叠加死亡抽样；110 岁 q = 1 保证终止。                                                  | `money.test.ts`、`life.test.ts`「synthetic region data」                                              |
| 因果日志     | 通过。序号连续、日期不倒流、原因只指向更早的事实；死于疾病的死亡事实引用发病事实；年度结算不漏（检查本身有反向测试）。                                                     | `checkJournalInvariants`；`life.test.ts`                                                              |
| 死亡终止     | 通过。主角死亡后清空队列，之后推进不产生事实；已故者的事件作废。                                                                                                           | `engine.test.ts`「death ends the run」                                                                |
| 模块依赖     | 通过。8 个包无环；领域包不依赖界面库、不导入 `node:`；网页应用不能依赖合成数据；相对导入写明扩展名。                                                                       | `pnpm check:boundaries`                                                                               |
| 双语叙事     | 通过（审计后加强）。固定的 200 局抽样必须**覆盖每一个模板**，每条事实都能中英渲染，且不存在没有模板的事实。                                                                | `cli.test.ts`「reaches every template」                                                               |

## 3. 审计中修复的问题（均在 M1 范围内，行为不变）

修复后黄金指纹不变，说明没有改变任何人生结果。

| #   | 问题                                                                                                                                            | 风险                               | 修复                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------- |
| 1   | `DecisionSpec.options()` 规定为纯函数，但没有强制。若选项读随机数或修改状态，暂停时给玩家看的选项可能与结算时不同，玩家选择也可能被判为不可选。 | 高：轻量模型编写新决策时很容易违反 | 选项在只读拷贝上运行，随机数 / `emit` / `schedule` 一律抛 `impure-decision-options` |
| 2   | 日志里的事实对象在提交后仍可被调用方修改（GDD §7 要求事实不可变）。                                                                             | 中：界面或存档代码可能无意改写历史 | 提交时冻结事实及其数组与 `details`                                                  |
| 3   | 出生时折算宏观状态没有按锚点的 `regionIds` 过滤，与锚点调度的规则不一致。                                                                       | 低：M2 多地区数据后会出错          | 与调度使用同一条件                                                                  |

同时补齐测试缺口：事件队列顺序与插入顺序无关的性质测试、`cloneJson` 拒绝非 JSON 值、人生原则执行器的同分与不可选规则、模板全覆盖。

## 5. 已知限制（不阻碍验收，已登记到后续里程碑）

- 只有合成地区（D 类），结果不代表任何真实统计（M2 起接入真实数据）。
- 只有主角，没有 NPC、家庭与关系；`systems` 的出生事件、账户与决策键假定单一主角（M3）。
- 生活费按出生时的城乡计算，尚无迁居（M3）；治疗从下一次年度健康检查起生效；从未工作的人按最高学历领养老金（ADR-0003 的简化）。
- `RegionModel` 的形状面向合成公式；接入真实数据时（M3）预计需要重塑，届时写 ADR。
- 每个事件深拷贝全部状态并校验全部角色；加入 NPC 后需重新测量（ADR-0004）。
- 已处理事件的键集合随一生增长并写入快照（约数百个），用于循环检测；NPC 增多后需评估体积。
- 跨浏览器逐位一致只在 Node / V8 上实测过（M5 三浏览器）。
