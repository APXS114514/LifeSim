## 1. 产品总览与核心体验

**一句话**：以可溯源的历史统计与可解释的概率模型作为现实约束，让玩家在真实历史时间线中体验一个人的完整一生；个人选择、NPC 自主性与家庭因果不断改变个人命运，但不改写已经发生的宏观历史。

**体验支柱**：真实历史中有限自主权；长时间尺度的因果延续；NPC 是独立的人；玩家界面简单而后台机制可追溯；离线完整可玩、AI 可选而非必需；尊重文化差异与统计不确定性。

**单局核心循环**：选出生设置→生成符合年代/地区的家庭和人物→从世界数据获得机会约束→时间推进触发人生事件→玩家或原则策略选择→结算人物、关系、家庭经济及社会影响→记录不可变的人生事实→直至角色死亡→生成生平报告与家族截至此刻的状态→新开一局或回顾存档。**主角死亡即本局人生结束，不接管后代。**

**玩家自由与限制**：能选择或放弃机会、设定长期价值原则、协商影响亲友、迁居和改变职业；不能指定自己必中学校/治愈疾病、使 NPC 必定服从，或阻止苏联解体等真实历史锚点。

## 3. v0.1 范围与明确排除

### 3.1 v0.1 必须可玩（MUST）

五国均可按出生年份与国家生成角色，也可在首发五地按当年出生人数权重随机国家；支持地区级/代表城市的出生环境差异；1950—2026任选出生年；现代及未来的完整一生；逐年、自动、快进；由规则处理学习、工作、经济、关系、健康、疾病、迁移、死亡；少量有实质后果的历史特色事件；双语时间线、决策卡片、人物/家庭/统计细节面板；生平报告；本地自动存档、备份导入导出、离线游玩；MIT 公共仓库、来源/许可证清单、质量检查与已知限制。

**国家特色最低示例（非穷尽承诺）**：中国大陆在特定历史背景下的教育和职业制度变迁、符合特定身份条件的赴台湾特殊历史路径；日本的高速增长/泡沫破裂与就业后果；朝鲜的制度化生活条件和极低频、受严格时空资格约束的脱北相关事件；韩国的经济高速发展与1997年危机；苏联时期俄罗斯地区至1991年解体后的制度过渡与职业财务影响。事件表现应尊重历史与当事人处境，不能戏谑化艰难经历。跨国目的地可以通过只支持迁入的轻量地区包运行，不必立即作为可出生地区开放。

### 3.2 非首发（NOT IN v0.1）

账号、服务器端云同步、多人或排行榜、死亡后可玩家族继承、运行时必选 LLM、RimeFox 接口实际接入、AI 生成后代展望、全世界国家、全城市全区地图、详细证券市场/企业经营/法庭或医院经营、大规模 NPC 社会全量逐人模拟、所有史料全量复刻、实时新闻改变历史、改写历史的平行时空。保留结构契约与注释，但首版不实现假界面按钮。

### 3.3 内容量作为初始预算而非保真承诺

候选建议：30—50个**通用事件原型**，每国3—5个带条件与后果的历史特色原型，核心家庭链约20—30个可组合关系原型；职业约15—25类；每国2—4个重点地区，总计约15—25个代表性城市。**这些仅是开发起点，必须通过完整人生试玩和事件重复率数据决定是否扩容；所有五国都必须拥有完整基础人生玩法。**

## 4. 世界、时间和历史模型

### 4.1 时间粒度与确定性

内部保存 ISO 风格的日历日期和绝对排序；普通人口及生活结算可以采用年或月的规范步长，重大历史事件按准确日期或月份插入。`advanceTo(targetDate)`、`advanceOneYear()` 与自动模式必须最终调用同一规范推进器。快进只省略视觉停顿/合并展示，不省略应发生的状态变化。每次推进有事件队列、优先级、处理预算及可取消/暂停机制。

出生年份范围仅规定**出生选择**，不得错误用2026作为死亡截止。2026年以后使用透明标记的预测世界包；超过权威预测覆盖区间之后进入情景假设包，不能称之为真实发生的历史。默认不设置固定的2100或其他结束年份；极端高龄/日期在计算边界保护下合理处理。

### 4.2 历史锚点与个人后果

`HistoricalAnchor` 包含稳定ID、起止日期、适用地区及政治实体、史实来源、不可更改的宏观状态变更与可选人物影响模型。宏观锚点固定；角色可选择迁移、职业、避险和家庭行动，这些只影响个体状态。政体变化与迁居是不同事件，不能因1991年的政治实体更替自动搬动莫斯科居民。

### 4.3 随机出生约定

手动指定国家时，国家维度没有抽样；选择随机国家时，**仅在五个首发出生地区内**，按选定出生年份的出生人数 `B(country, year)` 加权：`P = B_i / Σ(B_j)`。绝不能宣传为全球人口随机模拟。若玩家未指定出生年，实施默认值为在1950—2026离散年份上等概率抽取，并明确提示“随机年份等概率；国家按该年五地出生人数加权”；该默认值可作为以后无破坏性 UI 设置扩展。地区出生数据足够时按地区当年出生数加权；缺失时采取可解释回退；设置“其他城镇/农村地区”人口池，避免把全部人口挤到代表性大城市。

## 5. 可插拔国家、地区与数据包

国家包清单包含：`manifest`（稳定ID、schemaVersion、兼容引擎范围、许可清单）、`geography`、`population`、`economy`、`education`、`health`、`familyLaw`、`politicalHistory`、`events`、`narratives`、`sources`。包必须通过 schema 校验和兼容性测试，能被模块化注册；无相关数据时不能伪造值。

地理系统至少分离 `placeId`（物理地点稳定ID）、`adminUnitId`（按时段变化）、`politicalEntityId`（按时段变化）、`birthPlaceId`（不可变）、`currentResidenceId`、`citizenshipIds`。同一地点可在不同年份隶属不同实体；区划合并/拆分用历史映射表，不能覆盖出生时原始地址文字与 ID。地区数值优先来自本地同年可信源，否则回退到上级统计＋有解释的地区修正。

迁移引擎记录申请/决定/实际搬迁/身份审批/家庭变化/就业资格重认定等不同阶段；不能把国籍变更与地理迁移等同。特殊跨境事件仅模拟历史条件下的选择、风险与生活后果，不将其制作为现实行动指南。

## 6. 角色、NPC、人生原则与关系

### 6.1 主角状态

`Character` 至少保存 id、出生日期和出生地点、当前地理与政治归属、存活状态、家庭/国籍身份、教育资格、技能、职业与就业状态、个人财产与责任、健康疾病、人格及人生原则、知识范围、社交关系、主要经历索引。健康/幸福/经济/知识/关系等表层指标由细状态的明确函数派生，不能与底层值独立增减；所有数值变化有来源事实与事件ID。

### 6.2 人生原则与代理决策

角色自主权的核心是“价值权重＋现实资格＋不确定结果”。代理优先排除违法时代条件/不符合资格的行动，再基于家庭、财富、健康、知识、冒险、稳定等偏好估计行动得分和风险；普通行为自动决策，重大不可逆事项按用户设置的介入阈值暂停。风险较高的选项不意味着必然成功；提供简短的可解释决策理由。NPC 使用自己的策略和部分信息，不能访问玩家未公开的隐私或未来随机结果。

### 6.3 三层 NPC

Tier1 核心家庭/密友运行连续的教育、工作、健康、关系和重大事件；Tier2 一般同事邻居运行压缩事件摘要；Tier3 尚未实例化人口以统计分布表示，不逐人计算。人物层级可以提升但此前已确定的经历不能被重抽。关系图应当区分双向主观感受与客观法定/生物/共同居住事实，支持多次婚姻、收养、监护、亲子、不婚、不育。玩家可以劝说、资助、反对，NPC 最终独立选择。

### 6.4 死亡与后代

主角死亡后停止主角的时间推进，生成完整人生结算与截至死亡时的后代状态。后代继续活在社会中的模拟可能性属于后台状态历史，不是新的可控玩家角色。将来的 BYOK AI 后代展望必须标为“假设／非正史”，独立保存，不影响主存档的权威事实；首版不得显示伪可用的 AI 按钮。

## 7. 事件生成、结算和因果追溯

事件结构至少有：稳定ID/版本、发生日期、适用地域和时代、前置条件、独立触发风险或机会模型、相关角色ID、事件因果父ID、给玩家的选项、影响的底层状态字段、后续事件候选、双语叙事模板ID、来源与置信标识。

规范处理顺序：

1. 根据规范时间步长解析世界与历史锚点；
2. 校验人物和家庭状态、年龄资格、政策、地点等前提；
3. 用经过校准的概率模型与可复现随机流产生事件；
4. 用玩家决策或人生原则选行动；
5. 原子结算资金、关系、健康、身份及状态更新，做不变量检查；
6. 将原因、抽样结果、后果、版本写入事实事件日志；
7. 以语言无关的事实快照供 UI 生成中文/英文叙事；
8. 后续事件通过可追溯依赖关联，不能因为叙事文案改变而重抽结果。

不能出现死亡父亲次年失业、未成年人退休、未登记婚姻却无条件离婚、跨年度事件倒序、无限递归事件链。采取事件幂等键（如事件ID＋实体ID＋时间周期）与单次步长触发上限，循环依赖需检测并失败报告。

## 8. 历史经济、教育职业、健康医疗与家庭

### 8.1 家庭经济

个人收入与财产、家庭共同财务、所在地区/时代宏观经济分离。记录币种及币制版本、名义金额、债务、现金流、实物供应条件和购买力衡量。使用整数最小货币单位或十进制定点金额，禁止直接用 JS 浮点累加货币。PPP 只用于可比购买力指标，不替代实际汇率；苏联/俄罗斯货币重定值与经济制度变化必须作为有日期的转换规则。欠缺历史数据时以可信度 C/D 标记估算，不编造可精确到分的价格。

### 8.2 教育与职业

教育阶段使用统一内部类别，但年份与国家规则决定招生资格、考试、费用、升学及职业资格；学历、知识、技能、工作经验、法律执业资格分开存储。职业机会由人物能力、行业地区需求、年代、制度与关系影响；支持就业、升学、职业培训、转行、失业、自由职业、退休。不得把现代互联网职业放到1950年；不得把外国医学资格自动等同本地执业资格。

### 8.3 健康、疾病、医疗与死亡

以“当前日历年份×当前居住地区×当前年龄×可用人口统计组”的生命表风险作基准，用疾病、医疗可及性、伤害、生活方式等对风险进行**校准调整**；绝不把已包含所有死因的生命表概率再与独立疾病死亡风险简单相加。疾病是一条持续状态（发生、症状、诊断、治疗、康复或慢性影响），能影响现金流和就业；医疗条件因时代/地区而异。年度死亡概率为 q 时，风险强度可定义为 `H = -ln(1-q)`，再通过校准后的个体风险映射为 `P = 1 - exp(-H_i)`。是否死亡与死因归属要保持一致，不再重复抽签。婴儿期保留更细粒度结算接口。

### 8.4 婚恋与家庭

法律婚姻、情感关系、共同居住、亲生亲属、收养与抚养责任分离。双方各有信任、亲密、价值观与冲突状态；玩家可协商不能控制 NPC。生育率不能直接当作个人受孕概率；生育、收养与婚姻政策按历史日期与地区包适用。角色有不婚不育等合理路径，不把婚育当作单一成功指标；严肃历史伤害与暴力事件须有内容分级、严肃处理和可读提示。

## 9. 证据、估算、版本与科学性边界

### 9.1 数据分级

A：原始或直接官方统计（仍核实口径与偏差）；B：权威机构模型估计/预测；C：本游戏明示来源及方法的间接估计；D：为可玩性引入的游戏设计假设。**等级并非“置信概率百分比”**；数据质量、预测不确定性、适用地域/时期与授权状态应为独立元信息。

### 9.2 回退规则

同地区同年合适统计→可比邻近年份与制度变化校验→可比上级地区及城乡条件→明确声明的模型假设。苏联解体、教育制度改革、货币重定值、行政区划变化等**制度断点前后不得盲目线性插值**。所有数据通过 `DataRegistry` 获取，必须带来源标识及 schema 版本；缺失值是 `null`，不得默默写成 0。

### 9.3 校准方法

按国家/年份/年龄/城乡等分层抽样，不可只按五国人口加权后忽略小人口国家。对可获得基准的出生分布、年龄别死亡/生存曲线、教育完成率、职业就业结构、家庭和婚育做结果检验。根据来源置信范围、样本量与指标分别建立容差；不能一刀切“全部误差<5%”。对未检验或缺数据的指标在报告中标“未验证”。校准只说明总体分布相近，**不能自动证明个体决策影响的因果效应科学准确**。

### 9.4 资源许可与可再分发

MIT 只覆盖本团队有权授权的原创代码；复制/修改 MIT 代码须保留版权与许可。外部人口数据、地图、照片、翻译、字体、图标、史料可能有独立许可。`data/SOURCES.md`、`THIRD_PARTY_NOTICES.md`、`assets/LICENSES.md` 记录来源、版本、链接、归属、许可证、再分发许可、修改说明与核验日期；数据包未通过许可审计不得合入公开构建。联合国资料可用于研究，但不能在没有核验其具体条款前自动宣布全部 MIT。世界银行多数开放数据以 CC BY 4.0 授权，但需逐数据集核查；Natural Earth 自有数据说明为公有领域，仍需区分第三方派生内容。

## 10. UI、交互与双语设计

桌面主布局：左侧约20%角色摘要，中间约55%可滚动人生时间线，右侧约25%上下文人物/历史/统计面板。手机单列时间线，顶部可折叠状态，底部控制条或抽屉显示关系/决策/详情；所有关键操作支持点击、触摸与键盘，不依赖悬停。

事件展示分普通折叠摘要、重大历史或人生事件、需要玩家介入的决策卡片；通过虚拟列表和分页读取千条以上人生记录。长快进时展示进度及可取消，内部仍按同一引擎结算。主角可能不知道远地 NPC 的私人事实；内部事实日志与玩家已知事实（可见时间线）要区分。

首发所有核心 UI、游戏事件、选项、历史依据说明、出生及死亡报告、错误提示均有 `zh-Hans` 与 `en` 资源。存档只保存语言无关的结构化事实和模板版本；切语言只重绘叙事，不重抽事件。人名、历史地名、时代政体名称按有效年份和语言映射；可在 `i18n/locales` 扩展其他语言。日期、金额和单位遵循用户语言格式，但币种及其实际金额不因界面语言变化。

## 11. 技术架构 v1.0（建议方案）

### 11.1 技术栈

TypeScript（严格模式）、React、Vite、轻量 UI 状态库（例如 Zustand）、专用 Web Worker 模拟引擎、IndexedDB（例如 Dexie）、PWA Service Worker 静态资源缓存、i18next/ICU 格式化、Vitest＋性质测试、Playwright、ESLint/Prettier 或同等级方案、GitHub Actions CI、静态托管。依赖选择需在首个 ADR 中固定实际版本并检查许可证，避免将技术建议解释为不可替换产品需求。

离线意味着**首次访问后所需静态包与五国数据包已成功缓存**；不承诺从未打开过网站的设备能无网首次加载。Service Worker 更新须避免旧页面/新数据包混用。浏览器 IndexedDB 默认并非绝对不丢，提供 `navigator.storage.persist()`（用户许可/浏览器条件允许）、明确备份提示和导出文件。

### 11.2 分层架构

```text
UI (React)  ──> GameController ──> Worker RPC
                                      │
                                SimulationCore
                         ┌────────────┼────────────┐
                         │            │            │
                   WorldResolver  EventEngine  ActorSystems
                         │            │            │
                   DataRegistry  PolicyEngine  Character/NPC
                         └────────────┼────────────┘
                                  Snapshot + Journal
                                         │
                          SaveRepository (IndexedDB)
                                         │
                          optional FutureCloudAdapter

LocalizationRenderer <── immutable event facts
Future optional BYOK NarrativeProvider <── validated read-only facts
```

UI 不应持有整个世界对象；通过选择器读取角色摘要、事件页与关系详情。权威世界状态在 Worker 中，发送稳定版本的结构化 RPC 请求与精简响应；存档层位于可测试的抽象接口之下，不直接耦合 React。

### 11.4 核心接口草案（非最终可运行实现）

```ts

type EntityId = string;

interface EvidenceMeta {
  grade: EvidenceGrade;
  sourceIds: string[];
  modelVersion: string;

  yearRange: [number, number];
  methodId?: string;

interface CountryPackManifest {

interface SimEventFact {
  id: EntityId;
  type: string;

  actorIds: EntityId[];
  causeEventIds: EntityId[];
  outcomeCode: string;
  templateId: string;
  evidenceIds: string[];
  eventVersion: number;
}
interface SimulationSnapshot {
  schemaVersion: number;
  engineVersion: string;
  dataPackVersions: Record<string,string>;
  at: ISODate;
  rootSeed: string;
  rngState: unknown;
  schedulerState: unknown;
  activeCharacterId: EntityId;
  actors: unknown;
  relationships: unknown;
  householdAccounts: unknown;

}
interface AdvanceRequest {

  maxWorkUnits: number;
}
```

**接口补充约束**：金额为定点/最小单位；历史 ID 永不复用；事件事实日志只追加或经有审计记录的迁移转换；导入必须校验内容大小/校验和/schema/兼容性并防止路径或对象污染攻击；`rngState` 不能只保留 rootSeed 而漏掉已消费随机流。建议随机流由根种子、子系统、实体 ID、时段、事件稳定 ID 派生，避免无关 NPC 的执行顺序改变结果。

## 13. 版本路线图、依赖与退出条件

### M0：冻结规范与仓库地基（前置）

交付：将 GDD 和质量标准加入仓库；初始化 TS/React/Vite monorepo 或简化包结构；创建 MIT 与第三方来源说明、ADR、CI、测试框架、i18n 双语空白资源；为各核心模块定义 TypeScript 接口。退出条件：静态页面可构建、lint/typecheck/unit/CI 可运行；不声明实际游戏已经可玩。

### M1：可复现的单人人生模拟内核

交付：标准日历推进、人物底层状态、随机种子与独立随机流、事件队列、人生原则执行器、事件日志、死亡终止及 CLI/headless 跑完整人生的 smoke tests。退出条件：同输入完全复现；不同速度等价；没有死亡后行为/日期倒流/无限循环；可以用极简规则从出生走到死亡。

### M2：五国数据包与证据登记

交付：五地出生数据与地区骨架、1950—2026地区/年代适配、固定历史锚点、出生选择器、关键人口生命表基线与未来情景占位、数据 A/B/C/D 元信息、来源和许可报告。退出条件：五地任何出生年均能实例化；苏联—俄罗斯历史映射正确；禁止未获许可数据进入公共产物；缺失数据不会默默等于零。

### M3：人生系统与程序化内容集成

交付：家庭经济现金流、教育和职业路径、健康/医疗/死亡、Tier1/2 NPC 及关系图、影响协商、婚恋育儿、基本迁移、事件因果和双语叙事、各国历史特色事件。退出条件：五地基础完整人生可通关；关键事件相互产生有意义的后果；所有事件通过状态不变量检查；死亡原因无重复风险抽样。

### M4：公开可玩体验与安全存档

交付：桌面三栏/手机单栏人生时间线、面板、决策卡、时间控制、进度暂停、虚拟化、zh-Hans/en 全覆盖、本地存档自动/手动导入导出、PWA 离线缓存和死亡报告。退出条件：桌面与手机端从角色创建到人生报告全流程可玩；断网后的已缓存游戏可用；多语言状态完全一致；存档往返与恢复一致。

### M5：统计校准、性能与公开 Alpha

交付：批量模拟与误差报告、问题分级、长人生压力、存档回归、双语/无障碍审查、三浏览器兼容、第三方资产许可核验、`KNOWN_LIMITATIONS.md`、版本标签与静态部署。退出条件：全部 P0 与关键路径 P1 清零；校准指标满足事先声明的逐指标标准或明确缩小可验证功能并披露；发布候选通过发布门禁并留存日志。

**依赖顺序**：M1 是 M2、M3 与 M4 权威逻辑的前提；M2 的国家数据样本可与 M1 并行准备；M4 的 UI 外壳可提前开发，但不得另写一套假规则；M5 的测试和校准基础必须从 M0/M1 开始，并非最后才补。

## 14. 自动化质量门槛与发布规则

### 14.1 P0 / P1 / P2 / P3

**P0 绝对阻断**：无法从五地任一完成基础人生；大量角色或存档数据丢失、不可恢复；相同 seed+输入结果不一致；快进和逐年计算不一致；死者继续触发个人活动；重大历史事件错误时间地区；无限事件递归/浏览器冻结；有已知高风险安全漏洞；使用未获适用许可的数据/资产；核心双语内容缺失无法游玩。

**P1 阻断关键路径**：核心 NPC/家庭/账目出现严重矛盾；主要统计群体系统性明显失真且无合理披露/校准；首发国家核心教育职业无法运行；主流设备常态无响应。P2/P3 允许经过记录和风险评估后作为 Alpha 限制发布。

### 14.2 可执行测试

单元测试（金额、日期、资格、风险计算）；属性测试（年龄非负、金额负债守恒、有向亲子关系无自环、死者无新增行为、日期单调）；确定性/快进等价；事件幂等/循环抑制；NPC 升级保留事实；历史政体迁移与法律边界；跨语言相同事件序列；存档中途恢复和导入导出与版本迁移；Playwright 端到端桌面移动端；断网已缓存首次后运行；国家包 schema 和许可证检查。

建议规模（需根据真实速度再定）：每个提交100—500局轻量回归、夜间约10,000局、候选发布50,000—100,000局分层模拟；罕见严重事件需定向构造，不能仅靠随机总样本。统计校准按指标制定容忍度并留可重现报告与随机种子。

### 14.3 暂定工程性能预算

在事先固定的桌面/中档手机测试环境记录 P50/P95/P99：普通界面交互 P75/常用响应目标≤200ms；暂停指令 P95≤250ms；纯计算、无逐帧展示的80年模拟，桌面预算≤5秒、中档手机预算≤15秒。**这些是建议的可测目标，非已实测承诺**；先用 M1/M3 基准记录真实吞吐量、活跃NPC、事件密度和存档大小，再作 ADR 基线修订。即使总模拟耗时较长，主线程不能冻结，取消按钮必须有效。

### 14.4 发布前必须留档

`qa/release-candidate-report.json`（测试数量、失败用例、机器/浏览器、性能分布、统计误差）、`docs/KNOWN_LIMITATIONS.md`、`data/LICENSE_AUDIT.md`、翻译覆盖率报告、可重建 git commit、`CHANGELOG.md`、导入导出往返样本与自动备份提示。每次发布使用固定数据包版本和可追溯的生产构建。

## 15. 十大风险与缓解手段

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 需求蔓延 | 永远无法发布 | 本文冻结23项，MUST/后续严格隔离 |
| 历史数据不足 | 不可信精确数值 | A/B/C/D证据分级，地区回退，不确定性展示 |
| 统计总量看似对而个体因果错 | 误导玩家 | 将总体校准与因果模型验证分开，标明假设 |
| 历史货币与区划断点 | 金钱身份错乱 | 生效区间、币制版本与事件迁移用例 |
| 过深 NPC 计算 | 卡顿和存档膨胀 | 分层、惰性实例化、事件摘要、Worker |
| 快进影响游戏结果 | 信任崩溃 | 规范时间推进器、随机流与差分测试 |
| 健康风险重复计数 | 死亡率畸高 | 生命表基线与疾病统一风险校准 |
| 本地浏览器清理 | 存档丢失 | 备份导入导出、持久化提示、校验与恢复 |
| 中英动态叙事不一致 | 情节逻辑错误 | 结构化事实+双语模板、占位符完整性CI |
| 许可、版权与敏感史实 | 发布/信誉风险 | 源头审计、许可隔离、严肃事件审校与限制披露 |

## 16. 为用户和社区提供的透明信息

游戏页面及 README 应明确：本游戏为历史统计启发的交互式模拟，不是个体命运的科学预测；历史事件与个人虚构结果是不同层级；数据标记 A/B/C/D；未来年份使用预测或游戏假设；朝鲜及较早/省级统计有资料局限；五地随机出生不代表全球出生抽样；本地存档可能受浏览器存储清理影响；默认无服务器无模型 API；不得把用户未选择的文本或 Key 发至外部服务。

## 17. 工程启动后的首个可验收垂直切片

为了防止 Agent 一口气铺开所有模块，首个真正可玩的切片建议仅使用**一个国家示例包＋少量真实有据数据与明确标注假设**，跑通一个从出生至死亡的角色；具有简单教育→工作→家庭经济→健康→死亡因果链；有至少一个需要玩家作决定的事件、一个独立 NPC、一条历史锚点和一份可保存双语人生记录。它是开发中间里程碑，不等于公开的五国 v0.1 已完成。通过后才扩展其他国家包与系统。
