# 质量门禁

> **规范来源是 [GDD.md](GDD.md) §14**（P0—P3 定义、可执行测试、性能预算、发布留档）。本文把它映射到实际的命令和 CI 任务，并记录每个里程碑要新增的门禁。

## 缺陷分级

P0 与 P1 的定义以 GDD §14.1 为准：存在任何 P0，或者存在影响关键路径的 P1，就不发布。P2/P3 可以在 `docs/KNOWN_LIMITATIONS.md` 记录风险后作为 Alpha 限制发布。

## 当前自动化（M0、M1 起生效）

| 门禁           | 命令                        | CI 任务         | 保证什么                                                                                       |
| -------------- | --------------------------- | --------------- | ---------------------------------------------------------------------------------------------- |
| 格式           | `pnpm format:check`         | checks          | Prettier 格式一致（GDD 与任务原文除外）                                                        |
| 静态检查       | `pnpm lint`                 | checks          | ESLint 与 typescript-eslint 类型感知规则；领域包禁用非确定性 API、浏览器全局对象与网络         |
| 依赖边界       | `pnpm check:boundaries`     | checks          | 包依赖方向、源码导入与声明一致、无环                                                           |
| 依赖许可证     | `pnpm check:licenses`       | checks          | 生产依赖只用白名单许可证；`THIRD_PARTY_NOTICES.md` 与依赖同步                                  |
| 类型           | `pnpm typecheck`            | checks          | 所有工作区包通过 TypeScript 严格模式（含 `exactOptionalPropertyTypes`）                        |
| 单元与性质测试 | `pnpm test`                 | checks          | 见下方「M1 确定性与人生不变量」，以及 schema、存档往返与篡改检测、双语文本一致性               |
| 构建           | `pnpm build`                | checks          | 生产构建成功                                                                                   |
| headless 人生  | `pnpm life`                 | checks          | 用合成地区在 Node 里跑完一个完整人生（含一次重大决定）并打印双语生平                           |
| 性能基准       | `pnpm bench --lives 500`    | checks          | 固定种子的批量人生；报告随 CI 产物上传（`bench-report.json`），工作量指纹可复现                |
| 提交信息       | `pnpm check:commits <范围>` | commit-messages | 新提交中没有 AI 工具的自动署名（AGENTS.md「Git 提交规则」）                                    |
| 端到端冒烟     | `pnpm test:e2e`             | e2e             | 桌面与手机视口（Chromium）：页面渲染、语言切换不丢状态、年份越界提示、无横向滚动、无控制台错误 |

`pnpm verify` 依次运行格式、lint、依赖边界、许可证、类型、单元测试与构建，与 CI 的 checks 任务的主体一致。

## 按里程碑新增的门禁

| 里程碑 | 新增                                                                                                                        |
| ------ | --------------------------------------------------------------------------------------------------------------------------- |
| M1     | **已生效**（见上）                                                                                                          |
| M2     | 国家包 schema 与许可清单检查；1950、1970、1991、1997、2026 等边界年份，以及各地区币制断点（见 DATA_POLICY）；数据覆盖率矩阵 |
| M3     | 资产负债守恒、亲子关系无自环等性质测试；死亡风险不重复抽样；五地出生到死亡的端到端因果测试                                  |
| M4     | 存档中途恢复、导入导出与版本迁移；断网后已缓存版本可玩；中英切换后结构化结局不变；手机竖屏全流程                            |
| M5     | 分层批量模拟与逐指标校准报告；Chromium / Firefox / WebKit 三浏览器；长人生压力；`qa/release-candidate-report.json`          |

批量模拟的规模以 GDD §14.2 为起点（每次提交 100—500 局、每晚约 1 万局、发布候选 5—10 万局）。M1 实测：开发机（Apple M5）上合成人生中位数约 1.7 ms/局，CI 每次提交跑 500 局基准；M3 加入 NPC 后重新测量，再写 ADR 定下规模。

## 性能预算的解释

GDD §14.3 写的是「普通界面交互 P75/常用响应目标 ≤200ms」，前后文又要求记录 P50/P95/P99，口径不统一。执行时按以下理解，需要调整时写 ADR：

- 所有指标都记录 P50、P75、P95、P99；
- 普通界面交互以 **P75 ≤ 200 ms** 判定；暂停指令以 **P95 ≤ 250 ms** 判定；
- 无逐帧展示的 80 年模拟：桌面 ≤ 5 秒，中档手机 ≤ 15 秒，在固定的测试环境中测量；
- 这些是待测目标，不是已经测得的承诺。无论总耗时多长，主线程都不能冻结，取消按钮必须有效。
