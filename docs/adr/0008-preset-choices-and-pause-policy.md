# 0008：预设选择与暂停策略（年度重点与介入策略的内核支持）

- 状态：**已采纳**（维护者 2026-10-21 采纳；D3 选 A：两档「只在重大决定暂停 / 所有决定都暂停」）
- 日期：2026-10-21
- 关联：GDD 决定 02、03，§6.2；ADR-0004（确定性内核）；V0.1_PLAN 的 D3、D14；任务 M3-037（A：本 ADR 的实现）、M3-041（年度重点）

## 背景

- 维护者已批准 D14：每年可以设定「今年的重点」，它在当年有界地影响各系统的概率。玩家需要**提前**为下一年设定重点，而不是每年被打断一次。
- D3（待答复）：玩家可以选择只在重大决定暂停，或在所有决定都暂停。
- 内核现状：选择只能通过两种方式记录——创建时传入的 `decisions`，或对**队首**待决事项调用 `decide()`；暂停只针对 `major` 决定；已记录却不合格的选择会抛 `invalid-decision`。没有办法为一个**尚未到来**的决策事件预先记录选择，也没有办法让玩家在普通决定上暂停。

## 决定

### 1. 预设选择

- 新增 `Simulation.preset(decisionKey, optionId | null)`：为一个**尚未处理**的决策事件预先记录选项；`null` 清除。键是事件幂等键（`type|entityId|period`），`type` 必须是已注册的决策事件；已处理的键拒绝（`invalid-decision`）。事件发生前可以随时修改。
- 预设存在快照的 `schedulerState.presets`（**可选字段，缺省为空**），按键排序。
- 结算顺序：**玩家对待决事项的直接选择 > 预设 > 人生原则执行器**。
- 预设是「软」的：结算时若预设选项不合格（预设时无法预知未来状态，例如失业后「工作」重点不可用），**不报错**，改由人生原则选择；`decision.made` 的 `details` 记录 `decidedBy: 'principles'` 与 `presetIgnored: <选项>`。玩家用 `decide()` 直接作出的选择仍然是「硬」的，不合格就报错（现行为不变）。
- `decision.made` 的 `decidedBy` 增加 `'preset'`；叙事枚举补中英文案。
- **确定性**：结果只取决于事件被处理时存在的预设值；预设与直接选择一起构成动作序列并随快照保存。同一种子 + 同一组选择与预设 → 逐字节相同的事实；逐年、快进、单事件三种推进在预设相同时结果相同。

### 2. 暂停策略

- `AdvanceRequest` 增加可选字段 `pauseOn: 'major' | 'all'`，缺省 `'major'`（即现行为）。`stopAtMajorDecision: false` 仍表示从不暂停（直接结局、CLI）。
- `'all'`：在任何**没有直接选择也没有预设**的决策事件前暂停。
- `DecisionSpec` 增加可选 `background: true`：这类决定**永不暂停**，只由预设或人生原则决定（年度重点就是这一类，靠界面的重点选择器提前预设，不会每年打断）。
- `pendingDecision()` 接受同样的暂停策略参数，与 `advanceTo` 的判断一致。
- **D3 已决定为 A**：两档 `major` / `all`。（未采用的 B「重大决定 + 健康相关」三档与 C「按类别逐项开关」需要给 `DecisionSpec` 增加类别字段，日后需要时另行修订本 ADR。）

### 3. 版本与兼容

- 两项都是**可选扩展**，缺省时行为与现在逐字节相同：黄金指纹、基准工作量指纹、全部现有测试不变。
- 因此**不提升** `ENGINE_VERSION` 与 `SNAPSHOT_SCHEMA_VERSION`：旧快照没有 `presets` 字段，按空处理，可以照常恢复。若维护者认为语义扩展也应提升版本，则按 Q9 的非破坏性方式拒绝旧存档。
- `Choice.decidedBy` 的类型扩为 `'player' | 'preset' | 'principles'`，属于内核公共类型的改动。

## 理由与取舍

- **为什么不用「每年暂停一次」实现年度重点**：每年打断会让自动播放失去意义；1in8b 与 1injp 都是「随时可改、到点生效」的选择器。
- **为什么预设是软的**：未来的合格性在预设时无法确定；硬预设会让一局人生因为玩家几年前的设定而报错中断。软预设加上 `presetIgnored` 记录，既不中断也可追溯。
- **为什么暂停策略不进快照**：暂停与否不改变任何结果（结果只取决于选择与预设），它是界面偏好；放进快照会让同一局人生因为界面设置不同而产生不同的快照。
- **代价**：内核多一个公开方法与一个快照字段；`pendingDecision` 的语义多一个参数。

## 验收（M3-037A）

1. fast-check：随机种子 + 随机预设集合，两次运行事实逐字节相同；逐年与快进在相同预设下逐字节相同。
2. 预设生效：预设的选项被采用，`decidedBy: 'preset'`；预设不合格时由人生原则选择且记录 `presetIgnored`，不抛错。
3. 已处理的键不能预设；未注册的事件类型不能预设。
4. `pauseOn: 'all'` 在普通决定前暂停、在 `background` 决定前不暂停；缺省值下全部现有测试与指纹不变。
5. 快照往返保留预设；没有 `presets` 字段的旧快照可以恢复。

## 何时重新评估

- 维护者答复 D3 选择 B 或 C 时（需要决定类别字段）；
- 需要「中途修改人生原则」时（另立 ADR：修改原则也要成为动作序列的一部分）；
- Worker（M4-004）上线后，预设与暂停策略经 RPC 传递时。

## 实施记录（M3-037A，2026-10-21）

- `simulation-core`：`AdvanceRequest.pauseOn`、`PausePolicy`、`DecisionSpec.background`、`Choice.decidedBy` 增加 `'preset'`、`Simulation.preset()`、`pendingDecision(pauseOn)`；`decide()` 接受按 `all` 判定的待决事项；预设在事件提交、作废或主角死亡时移除；快照只在有预设时写 `schedulerState.presets`。
- 测试：toy world 增加 background 的年度重点（`work` 16 岁起可选）与 10 岁的普通决定；新增 6 项测试覆盖本 ADR 验收 1—5（含 fast-check：相同预设下逐年与快进逐字节相同）。
- 缺省行为不变：黄金指纹、基准工作量指纹 `3f03ad12…`、平均快照字节数（14,734）与全部既有测试不变。
