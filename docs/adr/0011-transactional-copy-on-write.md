# 0011：事务草稿按需复制

- 状态：已采纳（用户在本次 Alpha 推进会话中明确批准实施并验证）；尚未启用新实现
- 日期：2026-10-21
- 关联：ADR-0004、M3-043、M3-042、V0.1_PLAN G1

## 证据与问题

同一台 AMD EPYC 9V74 云主机（5 vCPU、Node 24.21.0），空闲时顺序运行各 1,000 局：已发布 7a3d6ff 的 p50 为 9.388 ms，角色契约扩展后为 11.116 ms；两者均超过 G1 的 5.5 ms。两组均为 89,825 条事实、平均死亡年龄 76.4。

角色版本的 Node CPU profile 显示，递归 JSON 复制约占 24%，结构相等比较约占 20%（包括事件事务、只读状态与基准快照；是采样比例，不是精确计时）。每个事件目前先深拷贝全部角色、账户、关系，再遍历比较以跳过未修改对象的 schema 校验。M3-042 增加大量未发生或只改少数字段的事件，将放大该成本。

## 提议的边界

1. 内核继续独占权威状态。公开 `simulation.state`、`snapshot()` 和恢复入口保持独立的普通 JSON；快照格式、随机流、事实 ID、事件键和调度顺序完全不变。
2. 事件处理器获得事务草稿。使用内核私有、无依赖的 Proxy 实现，读取共享已提交分支，首次写入时只复制该分支与祖先；数组的 push、splice、索引、length，属性删除及整个分支替换都纳入事务。
3. 本事件新建对象允许在处理器内部继续通过本地引用修改（出生初始化需要此语义）。提交时将新建或修改的数据验证并转成普通 JSON；禁止 Proxy 或外部可变引用进入权威状态。事务关闭后撤销草稿代理，处理器保留的草稿不能修改已提交状态。
4. 未修改分支按引用识别，省去整树 `jsonEqual`；修改的角色与账户仍执行原 schema，关系有变化仍整体校验。所有系统不变量逐事件执行，校验错误仍抛原错误码。
5. 处理器或校验失败时丢弃草稿、事实和后续排程，时钟、队列、预设、随机结果及权威状态均保持原事务边界；不得部分提交。
6. `DecisionSpec.options()` 的丢弃式深拷贝及纯函数检查先保持现状，避免把本次优化扩大到决策语义。开发中若这部分仍占主要成本，再另行提交可审查的等价优化。

不新增依赖，不引入 Worker，不减少原型、概率、年龄窗口、测试次数或不变量，也不改性能阈值。

## 必须通过的验证

- 原全部测试与已批准黄金不变；合成完整人生事实逐字节一致，快照结构和值一致。
- 独立的事务测试覆盖嵌套写入、数组修改、删除、分支替换、插入后继续修改本地对象、未修改分支、事务关闭和失败回滚。
- 非 JSON 值、非法 schema、关系环、处理器失败继续被拒绝；保留外部引用不能在提交后修改状态。
- 与现有深拷贝事务对照运行相同动作，比较事实和快照；逐年、单事件、快进与恢复继续等价。
- 同机空闲时比较 1,000 局的 p50、p95、快照字节和工作量指纹；报告 G1 真实结果，不把云机器与其他机型的绝对耗时视为等价。

## 风险与取舍

代理实现需要完整处理数组、别名和生命周期，比当前深拷贝复杂；减少分配和比较可能被代理开销抵消。先在隔离分支验证，若不能保持行为或没有收益，则保留当前实现并报告。该提议不承诺已经达到 5.5 ms，也不改变现有公开状态的归属。
