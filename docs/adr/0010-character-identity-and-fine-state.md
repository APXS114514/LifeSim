# 0010：角色身份与细状态（性别、姓名、细状态）

- 状态：**提议**（A 部分的产品方向已由维护者 2026-10-21 决定，技术方案待审；B 部分待 M3-042 细化后补完）
- 日期：2026-10-21
- 关联：GDD 决定 11、§6.1、§10（「人名、历史地名、时代政体名称按有效年份和语言映射」「存档只保存语言无关的结构化事实」）；M3_OPEN_QUESTIONS Q1 / V0.1_PLAN D4；ADR-0004（确定性内核）、ADR-0005（数据架构）、ADR-0007（数据驱动规则）；任务 M3-043（实现）、M3-045（姓名表）、M3-047（分性别生命表与出生性别比）、M4-022（界面）

## 背景

- **维护者决定（2026-10-21，Q1 / D4）**：角色有性别——主角出生时按 WPP 出生性别比抽样，父母按角色确定；死亡率改用分性别生命表；允许玩家在出生设置里指定性别。姓名写进角色状态，与 M3-043 的细状态扩展合并为**一次**角色契约变更。
- 现状：`CharacterState` 没有性别与姓名；`StatSeries.sex` 只允许 `'both'`；WPP 转换脚本只保留合计生命表（`data/scripts/wpp2024/qx.mjs`，`Sex === 'Total'`）；`RegionModel.mortalityQ(year, age)` 不分性别；叙事用关系称谓（M3-011），没有人名。
- 中日韩俄的名字大多区分性别：俄罗斯的姓随性别变形（Иванов / Иванова），父称由父亲的名派生；日本的名字强烈区分性别。所以姓名必须建立在性别之上。
- 婚后改姓在日本是法律上的夫妻同姓（实际多为妻子改姓），在俄罗斯常见；中国大陆、韩国、朝鲜婚后不改姓。姓名会随人生变化，属于状态而不是出生时的纯函数。

## 决定

### A1 性别

1. `CharacterState` 增加必填字段 `sex: 'female' | 'male'`。含义是 **WPP 统计口径的出生性别**；v0.1 不模拟性别认同，出生后不改变。界面标签「性别」，「这是什么」说明写明口径。
2. **主角**：在 `life.birth` 的出生随机流**末尾**（现有全部抽样之后）抽一次，`P(female) = 100 / (100 + SRB)`，SRB 为出生年的 WPP「出生性别比（每 100 名女婴对应的男婴数）」（B 级）。玩家指定性别时**照常抽这一次**、再用指定值覆盖，使抽样位置与是否指定无关（与 `selectBirth` 的「指定项也照常抽样」一致）。
   - 请求：`createLifeSimulation({ sex? })`、`RealLifeRequest.sex?: 'female' | 'male'`；出生设置界面提供「随机（按出生性别比）/ 女 / 男」。
   - 出生事实 `life.birth` 的 `details` 增加 `sex`（叙事可写「是个女孩/男孩」）。
3. **父母**：`family.ts` 按角色确定（母亲 `female`、父亲 `male`），不抽样。以后创建的子女按 SRB 抽样，配偶按各自任务的规则确定。
4. **死亡率按性别**：`RegionModel.mortalityQ(year, age, sex)`。真实地区取 WPP 分性别单岁生命表（M3-047）；合成地区两性共用同一张 D 级表（不改变合成世界的含义，只改变签名）。
5. **其他规则不按性别区分**，除非对应任务给出可核验的依据并单独审查（征兵、婚育、职业隔离等）；不得用刻板印象设定按性别不同的概率。

### A2 姓名

1. `CharacterState` 增加必填字段 `name`，存**语言无关的结构**（各语言写法在姓名表里，存档不存显示字符串）：

   ```ts
   NameRef = { table: string; id: string }          // 例：{ table: 'jp-given-female', id: 'hanako' }
   PersonName = {
     scheme: 'zh' | 'ja' | 'ko' | 'ru';              // 命名习俗：显示顺序、是否有父称、婚后姓氏规则
     family: NameRef | null;                         // 姓（ru 方案的表条目含阴性与阳性两种形式）
     given: NameRef | null;                          // 名
     patronymic: NameRef | null;                     // 只在 ru 方案；引用「名」表条目，按性别派生词形
   }
   ```

   `family` / `given` 为 `null` 只表示该地区与年代的姓名表有缺口（见第 6 条），界面显示「姓名待接入」；规则不得依赖姓名。

2. **姓名表**放在国家包（`packages/country-packs/data/<PACK>/names*.json`），契约为新的 `NameTableSchema`（content-schema）。每个条目：稳定 `id`、适用性别（`female` / `male` / `any`）、出生年代窗口、城乡权重（可选）、频率权重及其证据等级、各语言写法（原文、`zh-Hans`、`en`）、来源 ID。表的版本并入国家包的 `dataVersion`，从而进入快照的 `dataPackVersions`；条目**只增不删**，删除或改 ID 必须升版本。合成地区使用明确虚构的音节名（D 级）。
3. **生成**：出生当天为每个新角色安排一个 `identity.name` 事件（每个角色一个事件、以实体 ID 为键的独立随机流），在 `life.birth` 之后处理；按命名方案、**该角色自己的出生年**、城乡、性别，从表里按权重抽取。**不改变出生事件已有的任何抽样**。该事件**不发出事实**（命名不是时间线事件；出生事实的叙事在渲染时按 `name` 查表）。
4. **家族规则**（命名方案决定，D 级习俗假设逐条写进 M3-045）：
   - 主角随父姓（`zh`、`ja`、`ko`）；`ru` 的姓按性别取阴性或阳性形式。
   - 母亲的姓：`zh`、`ko` 保留自己的姓（独立抽取）；`ja` 与父亲同姓（法律上的夫妻同姓）；`ru` 取父亲的姓的阴性形式（常见做法，D 级假设）。
   - `ru` 父称：主角的父称由父亲的名派生；父母自己的父称来自为其各抽一个「父亲的名」（不实例化祖辈角色）。
   - 改名只通过事实（M3-017 结婚改姓、日后的玩家改名决定），不在本 ADR 实现。
5. **叙事与显示**：模板继续用关系称谓（M3-011）；身份卡、出生登记、终章、家人面板等由显示层按 `name` 查表渲染。事实的 `details` **不写**姓名字符串。
6. **内容边界**：只用调研并登记过的名字；按年代窗口抽取，避免时代错位；不使用政治人物与名人的全名；朝鲜部分按资料核实与领导人姓名相关的命名限制并写入排除规则；不从姓名推断民族；没有许可的名单不得入仓。某个地区或年代凑不齐有依据的名单时，该处显示「姓名待接入」，**不编造**。

### B 细状态（M3-043 原有范围，待补）

GDD 决定 11 要求可见指标由后台细状态派生。候选字段（M3-043 骨架）：压力、社交联系、技能与兴趣、近期重大经历的记忆。具体字段、取值范围、由谁修改、如何派生为指标，等 M3-042 细化确定事件需要什么之后补进本节。约束不变：只加 M3-042 与 M4-016 真正需要的最小字段；出生时确定性初始化，需要随机数时追加在出生随机流末尾；指标不入库。

## 理由与取舍

- **性别抽样放在出生随机流末尾**：现有抽样位置不变，主角其余的出生结果（地区、城乡、家境、父母）在加入性别前后完全相同；「指定也照常抽样」让指定与否不影响后续随机数。
- **现在就用分性别生命表**：俄罗斯男女期望寿命在 1990—2000 年代相差超过 10 岁（WPP 可核验），显示性别却用合计死亡率会误导玩家。
- **姓名存进状态而不是现算**：婚后改姓、日后的玩家改名、配偶与子女的姓名，都需要「随事实变化的状态」；所有显示位置读同一字段，不会因为各处调用不同版本的生成函数而不一致。
- **存表引用而不是字符串**：符合 GDD §10 的语言无关存档；切换语言只换写法，不重抽名字。
- **命名用独立事件**：随机流按实体隔离，加入或调整姓名不扰动任何其他结果。
- **合并为一次角色契约变更**：快照版本与存档失效只发生一次；数据契约（`series.ts`）的变化不影响存档，可以先行。
- **未采用**：只在界面上给姓名配「显示用性别」（会在模型之外造出第二个事实来源）；不分性别的名字（俄罗斯与日本做不自然）；由种子现算姓名（婚后改姓与改名无法表达）。

## 待维护者确认

1. 母亲姓氏的习俗假设：日本与父亲同姓、俄罗斯取父姓阴性形式（D 级，常见做法）、中国大陆与韩国、朝鲜保留自己的姓。
2. 朝鲜人名的中文写法：朝鲜不使用汉字，中文媒体按惯例给出汉字写法；建议只收录有公开惯用汉字写法的姓与名，否则中文界面显示谚文原文加音译。
3. 若 B 部分迟迟定不下来，是否允许 A 部分先实施（代价：快照版本与存档失效多发生一次）。
4. 出生登记页是否允许玩家改名（会成为一种玩家选择，需要另立决定事件与存档语义）。建议 v0.1 先不做。

## 何时重新评估

- 需要表达性别认同或非二元选项时：属于产品决定，另立 ADR（GDD 未规定）。
- 某地区或年代的姓名数据无法取得许可：保持「姓名待接入」，并重新评估数据来源。
- M3-017（婚恋）落地时：复核婚后改姓规则与 `name` 的变更事实。
