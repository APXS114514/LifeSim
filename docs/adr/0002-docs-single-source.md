# 0002：设计文档以 GDD 为唯一来源

- 状态：已采纳
- 日期：2026-10-20

## 背景

设计交付包里除了 GDD，还有 `ARCHITECTURE_技术架构.md`、`ROADMAP_v0.1_开发路线.md`、`QA_GATE_验收与发布门禁.md` 三份附属文件。逐行核对后发现，它们都是从 GDD 原样摘出的章节，连标题编号也保留着 GDD 的编号（例如从「## 4.」开始）。把三份副本放进仓库，迟早会和 GDD 出现分歧。

## 决定

- `docs/GDD.md` 保持交付原文，是唯一的规范来源；`docs/AGENT_PROMPTS.md` 同样保持原文。两者都不参与 Prettier 格式化。
- `docs/ARCHITECTURE.md`、`docs/QA_GATE.md`、`docs/ROADMAP.md`、`docs/DATA_POLICY.md`、`docs/RELEASE_CHECKLIST.md` **不复制 GDD 原文**，只引用 GDD 章节，并补充实现层面的信息：实际的包与命令、当前状态、自动化对应关系、待核实事项。
- 对 GDD 的澄清或工程默认值写成 ADR，不直接修改 GDD；改变 23 项产品决定需要发起公开提案并发布新版本的 GDD。
- 原始交付包（含 `.docx` 排版版与三份摘录）原样存档在仓库之外，不进入版本库。

## 理由与取舍

单一来源可以避免出现「改了 GDD 却忘了改摘录」的情况。代价是读附属文档时需要跳转到 GDD 对应的章节。

## 何时重新评估

GDD 发布新版本时，检查各附属文档引用的章节号是否仍然正确。
