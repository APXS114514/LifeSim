## Q1 角色性别与分性别生命表

- **现状**：GDD 未规定角色是否有性别；M2 只转换了男女合计生命表（ADR-0005 §3），AGENT_HANDOFF §7 已把「角色是否有性别」列为待维护者决定的产品问题。
- **为什么现在要决定**：M3-002 的关系契约要区分配偶、父母、子女；M3-016 生育需要性别语义；M3-022…025 的征兵、产假、职业隔离等事件都与性别相关。事后补字段会重写已有关联状态。
- **保守方案（若不决定）**：M3 先不做性别，婚育只在「双方同意、具备生育条件」的抽象层面建模；事件文本避免性别代词。M3-016 因此推迟或只做收养。
- **需要维护者回答**：① 角色是否有性别？② 若有，是否补 WPP 分性别生命表（新数据任务）？③ 是否允许玩家选择？

## Q2 家庭账户与婚后财务的状态归属

- **现状**：`SimulationSnapshot.householdAccounts` 是账户数组，主角一个账户；`CharacterState.finance` 只是指针。
- **为什么现在要决定**：结婚、育儿、赡养、丧偶都涉及「钱是谁的」。GDD §8.1 要求个人收入/财产与家庭共同财务分离，但没有定义账户粒度。
- **可选方案**：
  - A. 每人一个账户 + 家庭层汇总记录（推荐，改动小，不破坏现有不变量）。
  - B. 家庭共同账户 + 成员份额（更接近真实家庭，但重写结算与币制换算）。
- **影响**：M3-013 的结算、M3-016 的育儿费用、M3-017 的丧偶财产。

## Q3 RegionModel 扩展方式

- **现状**：`packages/systems/src/region.ts` 的 `RegionModel` 是 M1 为合成公式设计的接口（概率表 + 学制 + 效应系数）。M3-lite 用 D 级常数实现。AGENT_HANDOFF §9 明确「M3 接入真实数据时预计要重塑（届时写 ADR）」。
- **为什么现在要决定**：教育/职业/价格/医疗需要新的查询维度（职业类别、年代、地区、家庭背景），直接往接口里加 20 个方法会让 systems 与数据包耦合。
- **可选方案**：
  - A. 扩展现有接口 + 新增 `RegionTables` 数据对象（中等改动，systems 仍只依赖接口）。
  - B. 新增 `@lifesim/life-model` 包承接真实规则，systems 保留合成地区（改动大，新增包）。
- **需要的产物**：ADR-0007（数据驱动的 M3 人生规则）。ADR 属于高风险文档，执行者只能起草，由维护者确认。

## Q4 新增统计指标与来源许可

- **现状**：`data/sources.json` 已登记 WPP 2024 与 WDI 城镇比例；WDI 的 CC BY 4.0 已核验。
- **待确认**：教育（入学/完成率）、劳动力（参与率、就业结构）、CPI、卫生支出能否继续使用 WDI 同一来源 ID；ILO 工资数据是否引入（许可与可得性未核验）。
- **影响**：M3-004…006 的 `data/sources.json`、`LICENSE_AUDIT.md` 与转换脚本。没有确认就不能产出数据。

## Q5 工资与收入数据

- **现状**：工资是 ADR-0006 的 D 级假设（1.04^年 增长）。
- **待确认**：① 是否有可再分发的五国工资序列？② 若没有，是否接受「人均 GDP（WDI，CC BY 4.0）+ CPI」的 C 级推算，并在 ADR 里写明规则？
- **影响**：M3-013 的收入与购买力；M3-011 的教育费用。

## Q6 迁移范围

- GDD §3.1 要求「跨国目的地可以通过只支持迁入的轻量地区包运行」。M2 明确把「只支持迁入的目的地轻量地区包」推迟到 M3（INDEX「明确推迟」表）。
- **待确认**：v0.1 是否只做「五国内部迁居 + 五国之间的迁移（用现有国家包）」，不新建目的地包？还是必须支持第三国？
- **影响**：M3-019 与 M3-020 的范围与数据量。

## Q7 生育率 → 个人受孕概率

- GDD §8.4 明确「生育率不能直接当作个人受孕概率」。
- **待确认**：采用哪种换算（分年龄生育率 ASFR → 年度概率，并按婚姻/健康/意愿调整），以及是否引入 WPP 的 ASFR 数据（WPP 2024 含 ASFR，许可同 WPP）。
- **影响**：M3-017 的规则与数据任务。

## Q8 死亡风险校准与限幅

- GDD §8.3：生命表 q 已含全部死因，只能做乘数调整；`P = 1 - exp(-H·m)`。
- **待确认**：① 乘数链上限（例如 3.0）与下限（0.5）是否固定；② 是否要求「按国家/年份/年龄带的模型死亡率与生命表偏差 ≤ 声明容差」作为验收；③ 死因权重表的证据等级（D 级是否可以接受）。
- **影响**：M3-015 的验收测试。

## Q9 旧存档兼容

- M3-001 起 `SYSTEMS_VERSION` 会提升，旧快照恢复会被拒绝（这是设计意图）。M3-lite 的 localStorage 存档会失效。
- **待确认**：① 是否接受「旧存档直接拒绝并提示新开一局」；② 还是要求 M4-002 提供「只读回放/导出旧事实」的兼容路径。
- **影响**：M4-002 的验收；M3-001 的提交说明。

## Q10 敏感历史内容

- 朝鲜相关事件、饥荒、政治暴力、脱北在 GDD §3.1 有明确要求（「极低频、受严格时空资格约束」「不能戏谑化」）。
- **待确认**：① 内容分级与提示形式；② 哪些事件需要维护者逐条审校后才可入库；③ 是否允许在事件中出现真实人名（默认不允许，只用制度与统计）。
- **影响**：M3-025、M4-009。

## Q11 代表性城市与省级区划

- GDD §3.1/§3.3 要求每国 2–4 个重点地区、总计 15–25 个代表性城市；M2 只有「其他城镇/其他农村」人口池。
- **待确认**：① 城市人口权重的数据来源与许可（WPP 只有国家层；需要各国普查数据）；② 是否接受先用 D 级权重（明确标注）直到拿到可再分发数据。
- **影响**：M3-019 的出生与迁居权重、五国事件的城市资格。

## 维护者答复（2026-10-20）

1. **Q2 = 方案 A**：每个角色独立账户；另建家庭层的共同收支与责任记录。必须明确个人财产与家庭共同经济责任的边界；家庭汇总不得重复计算个人资产；成员之间的资金转移需要平衡记录。财产共有与继承规则留给相应家庭系统任务。
2. **Q3 = 原则方案 A**：保留 `RegionModel` 的核心职责，通过独立的 `RegionTables` 或数据查询适配层引入国家、年份、地区与职业维度；不一次性向原接口加大量方法，也不新增平行模拟引擎。ADR-0007 草案必须给出具体接口、兼容性与测试方案；**重大公共契约修改仍需维护者确认后才实施**。
3. **Q4**：允许扩展 WDI 数据来源，但**不能默认所有指标沿用已经核验的单个指标来源 ID**。每项新增指标必须核实官方来源、单位、时间覆盖、适用地域、具体许可与可再分发条件；只有核验通过的数据才可进入国家包。ILO 工资数据暂列候选，许可未核实时不得复制或再分发。
4. **Q5**：优先使用可靠、有适用许可的真实工资或收入统计。**不能**简单把人均 GDP 当作平均工资，也不能认为 CPI 能自动完成这种换算。只有存在可信校准基准、明确模型方法与误差验证时，间接收入估计才可标为 C 级；缺乏充分依据时使用明确登记的 D 级设计假设并保留替换能力。不得伪造五国历史工资数值。
5. **Q9 = 非破坏性**：旧存档不能恢复时保留原始内容，允许导出备份并提示不兼容；不要求在 M3 强行迁移。已由 [M3-000](tasks/M3-000.md) 与后续 M4-002 落实。
6. **Q12**：允许研究并移植 1injp 中真正由 MIT 授权的原创代码，但必须保留版权与许可证声明，并在必要时更新 `THIRD_PARTY_NOTICES.md`。不能复制许可未核实的第三方数据或素材。
7. **Q13**：默认不新增工作区包。确有充分架构理由时，先给出 ADR 或等效审查材料。
8. **Q10**（2026-10-20 追加）：允许朝鲜经济锚点与南→北迁移进入设计/实现；提示方式记录为「X」，但 X 尚无定义，实现事件前需补充具体的提示形式。
9. **Q1 / Q6 / Q7**：本轮回复中的「X / Y / Z」没有对应任务文件中的任何选项，按占位符处理，仍为未决；相关任务暂不启动。（Q1 已由第 10 条决定。）
10. **Q1 = C**（2026-10-21）：角色有性别——主角出生时按 WPP 出生性别比抽样，父母按角色确定；使用 WPP 分性别生命表；允许玩家在出生设置里指定性别。姓名写进角色状态（不在界面现算），与 M3-043 的细状态扩展合并为一次契约变更。方案见 [ADR-0010](adr/0010-character-identity-and-fine-state.md)，数据见 [M3-047](tasks/M3-047.md)、[M3-045](tasks/M3-045.md)。
