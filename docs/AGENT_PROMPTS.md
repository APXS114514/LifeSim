# Codex / Claude Code 分阶段实施提示词

> 适配：新建仓库或已有空白项目。所有阶段均须先阅读 `GDD_v1.0_完整设计与技术规范.md`（可改名为 `docs/GDD.md`），严禁擅自恢复已撤回的“死后接管后代”机制。  
> 模式：每一阶段都是可单独复制的 Agent 任务。先运行阶段 0，验收后再运行阶段 1……阶段 5。**不要在一次执行中跳过全部验收门槛。**  
> 说明：下面的“停下”指 Agent **在当前任务完成到约定边界后给出交付报告**，不是让 Agent 在后台异步开发。

## Agent 总规则（各阶段始终有效）

```text
你是负责 TypeScript 游戏模拟系统的高级工程师和质量负责人。
把仓库中的 docs/GDD.md 视为冻结的23项产品决策。代码必须尊重历史固定、角色个人可变、五地区、1950—2026可出生、主角死亡即结束、双语、离线不强制AI、MIT原创代码以及严格的数据许可审计。
先阅读 AGENTS.md、docs/GDD.md、docs/ARCHITECTURE.md（如有）、README.md、package.json、现有测试、git status -sb 和最近提交。不要 reset、rebase、force push、覆盖或删除用户未提交修改。不要把现有工程随意重建。没有文件时才按GDD创建最小项目。
遵守清晰的分层架构。每一项状态变化必须可追踪，随机和快进必须可复现。不得以占位随机数假装史实；数据不足时使用明确标注的估计与 D 类游戏假设。
禁止将真实 API Key、个人敏感数据、未经授权的数据集和素材提交到 Git。v0.1 无网络AI与账户依赖，禁止添加隐蔽遥测。任何第三方依赖应记录许可。
每次交付都提供：改动文件摘要、架构决策及原因、执行过的测试与真实输出、没有通过的项目、剩余风险、如何复现、下一阶段的前提条件。不要声称未运行的测试已通过。确保 TypeScript 严格模式、代码可读、注释和命名清晰。
如果你发现 GDD 真正互相矛盾，先采用不会丢失事实、不降低质量且不扩大首发范围的保守实现，在 docs/adr 中记录。不要额外向用户抛出新的大范围需求问卷。
```

## 阶段 0：仓库建立与设计基线

**目标**：将设计文档变成可维护、可构建、可测试的项目仓库；本阶段不写大量游戏逻辑。

```text
任务：执行《GDD v1.0》的阶段 M0。
先执行总规则中的只读审查，确认现有仓库状态；若当前目录并非空仓库，保留原有结构与未提交工作，选择最小侵入改造。
建立 React + Vite + TypeScript 严格模式，以及适度的 packages/modules 结构，保持 simulation-core 与 UI 无循环依赖。设置 lint、format、typecheck、build、test、基础 Playwright、GitHub Actions。创建开发文档：docs/GDD.md、ARCHITECTURE.md、DATA_POLICY.md、QA_GATE.md、docs/adr/0001-*、RELEASE_CHECKLIST.md；仓库协作材料 LICENSE(MIT，仅当授权者信息正确)、README、CONTRIBUTING、CODE_OF_CONDUCT、SECURITY、THIRD_PARTY_NOTICES。
建立 country-pack manifest、event-fact、character-state、save-repository、data-evidence、narrative-provider 的类型契约及 schema 检查器，不实现不必要的具体规则。
准备 zh-Hans 与 en 文本资源壳、干净的角色创建页草图和一个 Vitest 示例；禁止虚构“已完成五国人生模拟”。
验收：npm ci / typecheck / lint / test / build / Playwright smoke 可复现运行，CI 能自动检测。文档链接、许可证边界和类型文件可浏览。输出阶段完成报告；不要自动开始 M1。
```

## 阶段 1：确定性人生模拟内核（M1）

**目标**：在无 UI、无真实数据包环境下实现一个可运行、可测试的规范模拟器。

```text
任务：实现 GDD M1 可复现模拟内核，保留 M0 的接口和全部现有工作。
实现：世界日期与时段推进、历史锚点调度、角色状态和稳定 ID、人生原则规则引擎、带资格条件和幂等键的事件系统、原子状态变更、单调事件日志、死亡终止、随机种子与独立随机流、快进/逐年/自动共用 advanceTo 内核、分批计算及取消检查、纯 Node/headless 测试入口。
先用一个人工明确标记为 D 类的合成地区数据包，不伪称真实历史统计。至少实现教育→就业→家庭财务→健康→死亡的最小因果链，并支持玩家干预一次重大选择。
关键测试：相同初始状态+seed+动作序列产生字节层面稳定的标准化事实事件序列；逐年与快进等价；死亡后不再参与事件；事件因果引用有效；不会产生日期倒流、无限事件递归、负年龄、状态漏结算。引入存档快照对象，但不急于做完整界面。
验收：一条完整合成人生在 headless CLI 中运行成功；测试具备失败时输出 seed/事件ID/日期的能力；性能基准能复现。报告已经通过和未通过的测试；不要自动进入 M2。
```

## 阶段 2：五国历史统计包与来源治理（M2）

**目标**：建立真实国家/历史骨架，来源合法且可审计；把统计与规则分开。

```text
任务：完成 GDD M2 国家数据包与来源治理。
逐一注册中国大陆、日本、朝鲜、韩国、俄罗斯五个支持出生的地区。定义 Russian SFSR/USSR 到 Russia Federation 的历史政治归属，不用现代国家名改写过去。实现地区稳定 placeId、按年份生效的行政归属、部分代表性城市、城乡类别、迁入目的地轻量地区包。
建立 DataRegistry、按值/指标记录 evidence A/B/C/D、来源URL、许可证、数据版本、年份与地理范围、方法ID、不确定性及缺失值处理。优先使用许可合适的官方统计。禁止使用来源不明的百分比冒充历史事实；无法确定时明确用受约束的 C/D 估算，并在样例中标注。不在完成逐项许可证审查前把受限数据库复制进 public 构建。
实现固定重大历史锚点的几个有来源示例以及五地出生年范围的角色实例化；随机出生在选定年份按五地当年出生人数加权；无出生年时的随机年份采用在 GDD 中标注的暂定等概率规则；地区缺失时要有“其他城镇/农村”人口池。实现 2026 年后明确标记的预测世界和预测末端以后的情景规则接口。
关键测试：1950、1970、1991、1997、2026 的边界案例、1960年前统计缺失、货币制度与行政变迁日期、国家包可独立装载和 schema 校验、许可清单与来源字段非空或理由可解释。输出数据覆盖率矩阵及真正的数据缺口，不将数据空缺视为零。不要自动进入 M3。
```

## 阶段 3：把系统做成一生，而不是孤立面板（M3）

**目标**：让五地都拥有基本完整生活循环与历史差异。

```text
任务：完成 GDD M3 人生系统集成。
按照统一事件引擎实现：家庭收支与定点金额、历史货币版本及基本供应限制；教育制度、学习技能、职业资格、就业/失业/转行/退休；生命表基线和校准后的死亡风险、病程与治疗；分层 NPC（核心亲属/普通人物/统计人口）与关系图；影响协商、婚育、收养、育儿、家庭冲突；国内及跨国迁移；多个有实质结算后果的五国特殊事件。
NPC 的事实不可因升级层级而重抽；亲属有独立人生原则和知识边界，不能被玩家直接下命令。严格禁止高层事件抽样与底层死亡抽样重复计算风险。按国家/年检验职业、学校、法律与政治实体资格。主角死后结束本局并可总结后代截至该时刻的真实状态，绝不接管。
事件原型数量可参考 GDD 的内容预算，但不要只堆大量不会联动的随机文本。选每个系统的代表性情景编写端到端因果测试。首要验收：五国均能从出生运行到死亡，至少有若干社会经济与家庭事件相互影响，输出结构化人生传记和可核验事件日志；每个国家最少有独特历史规则/事件。报告未完成内容，不要自动进入 M4。
```

## 阶段 4：双语玩家界面、离线与可靠存档（M4）

**目标**：玩家能在桌面和手机独立游玩全部核心流程。

```text
任务：完成 GDD M4 网页应用与存档。
桌面采用左角色摘要/中间人生时间线/右侧上下文详情；手机采用单栏阅读＋可展开信息面板；实现出生选择、日期控制、快速推进与暂停、重大决策卡片、历史事实与角色认知的显示边界、叙事折叠和历史回溯、死亡生平报告。时间线必须虚拟化，用户切换语言不重模拟。
完成 zh-Hans 与 en 的核心事件/界面/错误/存档/报告文本，使用语言无关的事实事件ID和双语完整句子模板；校验所有占位符与历史地区名称。不得调用任何在线模型进行运行时翻译。
通过 SaveRepository 封装 IndexedDB 和可选 Dexie，实现自动存档、事务性快照/事件日志、导入导出（含校验和与 schema）、损坏文件拒绝、导入大小限制、版本迁移示例、空储存空间处理与人工备份提示；不能只存 React state。PWA 缓存必要静态包，测试用户至少联网访问并缓存过一次后的离线运行。浏览器被清空数据无法保证恢复，需说明限制。
关键 E2E：五地出生、重大决策、家庭和职业变化、死亡报告、中文切英文后结构化结局不变、重载继续、导出导入、手机竖屏操作、断网已缓存可玩、模拟期间随时暂停或取消。出具截图与测试输出，不要自动进入 M5。
```

## 阶段 5：公开 Alpha 发布门禁（M5）

**目标**：用可重现证据证明“可以发布”，而不是口头声称完成。

```text
任务：完成 GDD M5 统计校准、稳定性、安全许可与公开 Alpha 发布候选。
先审查现有 git、测试、源码与历史文档，不进行破坏性重构。建立 headless batch-run，按国家、年代、年龄、城乡类别分层抽样；重点对出生分布、生命表相关生存曲线、可获得基准的教育/职业/婚育统计进行逐指标误差报告。报告必须分别标明原始数据、估计、游戏规则、不可验证处，不能用全球汇总掩盖小人口国家问题。
执行确定性、快进等价、极端 NPC 关系、死亡后状态、恢复快照、随机事件自引用、资产负债守恒、双语一致性、移动端操作、断网、长人生压力和多浏览器兼容回归。基准性能记录测试硬件/浏览器、NPC数、事件密度、P50/P95，并与 GDD 建议预算比较，必要时写 ADR 解释调整。
审计原始代码/派生数据/地图/图片/字体及 RimeFox 复用情况的许可证；不放入未经允许的公开数据包；扫描潜在真实密钥/隐私；生成 THIRD_PARTY_NOTICES、数据来源与许可清单。列出所有 P0、影响核心流程 P1：存在即停止发布。可保留 P2/P3，但在 KNOWN_LIMITATIONS 中注明。
最后生成 RELEASE_CHECKLIST、发布测试 JSON、可重复的 npm/pnpm 命令、构建和部署记录、Git tag 建议。若没有真实通过全部门禁，不得虚构“发布成功”，只提交发布候选与剩余阻碍。不要扩大 v0.1 范围或实现云同步/AI。
```

## 未来增强任务（明确在 v0.1 之后；当前禁止启动）

```text
任务候选：在不更改主角死亡终止规则的前提下增加可选 BYOK AI“后代可能未来”展望。先审计 MIT 许可的 RimeFox 模型请求、响应、Provider 抽象；提取去除 Chrome 扩展 API 的通用适配层，保留原版权与许可；对不同供应商 CORS/鉴权和 Key 安全设计作单独威胁建模。
玩家主动配置 API 才启用；出站前显示将发送哪些虚构世界事实；仅发送用户明确允许的上下文；AI 输出限制为非正史叙事，经过时间/人物/事实一致性校验；不回写核心存档事实；支持清除、导出及重新生成。永远不成为运行完整一生的必要前置。
```

## 共同完成定义（Definition of Done）

单个阶段完成不等于全项目完成。所有阶段的最终 DoD 必须同时满足：文档与代码一致；审查报告解释做了什么；所有声称通过的测试有真实日志；公开数据及图像许可核对；没有任何隐藏云端/AI依赖；没有将未来 AI 后代展望误当成家族继承；五国1950—2026出生、完整人生双语可离线玩；满足 GDD 发布阻断标准。
