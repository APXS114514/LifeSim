# v0.1 公开 Alpha 推进骨架（第 2 版：体验优先）

- 日期：2026-10-21；起草：Claude Code（首席架构）；**由维护者确认后生效**
- 依据：[GDD](GDD.md) 决定 20、§3、§13 M3—M5、§14；[RELEASE_CHECKLIST](RELEASE_CHECKLIST.md)；[tasks/INDEX.md](tasks/INDEX.md)
- 第 2 版的原因：维护者试玩 M3-034 后认为「做得不错，但和 1in8b、1injp 比太简陋」，要求尽快玩到像样的 0.1。本版把顺序改为**先让一局人生有血有肉，再补数据精度与发布工程**；范围、数据与确定性的红线不变。
- 本文件是**骨架**：只规定顺序、分道、里程碑、门禁、分工与待决事项。骨架任务按 §6 先由执行 Agent 细化、经审查后再实施。

## 1. 为什么现在显得简陋（实测，2026-10-21）

五国各 100 局真实人生（`main` = `5bf0284`）：

| 指标     | 现状                                         | 1in8b / 1injp 的做法                                       |
| -------- | -------------------------------------------- | ---------------------------------------------------------- |
| 每局事实 | 81.8 条，其中 **76% 是年度收支**（默认隐藏） | 每年多条生活事件，按年内进度逐条出现                       |
| 可见事件 | 约 20 条 / 78 年（**每年 0.25 条**）         | 学校、朋友、恋爱、工作、家人、时代事件                     |
| 事件种类 | 24 种                                        | 上百种原型                                                 |
| 玩家选择 | 每局 0.54—0.70 个；30%—47% 的人生一个都没有  | 每年可改「今年的重点」；升学、工作、恋爱、移居、治疗都会问 |
| 状态     | 只有年龄与地区                               | 健康 / 幸福 / 知识 / 人际（0—100）+ 收入                   |
| 情感节点 | 无                                           | 5、15、30、50、70 岁停下来问一个问题；家人生老病死         |
| 对照     | 无                                           | 「同一秒出生的另外四人」、同年出生者生存曲线、人生方格     |
| 节奏     | 最慢每年 2 秒，一生约 3 分钟                 | 可选一生 30 / 60 / 90 分钟，每年 40—60 秒                  |
| 收尾     | 简单总结卡                                   | 出生证明卡、死亡记录卡、前世记录                           |

结论：差距主要在**内容密度、每年的选择、状态与情感节点、界面**，而不在内核。LifeSim 的长处（确定性、真实历史锚点与政体变迁、五国深度、证据分级、双语）要保留；1in8b 的玩法思路可以借鉴，但它**不是开源项目**：只借鉴公开的玩法创意，不复制其代码、文字、图片或音乐（见 [REFERENCE_REUSE](REFERENCE_REUSE.md)）。

## 4. 门禁

| 门禁 | 时机                  | 必须满足                                                                                                      |
| ---- | --------------------- | ------------------------------------------------------------------------------------------------------------- |
| G1   | P1 完成               | §2 的 P1 条件；父母死者无新行为；主角投影指纹不变（M3-011）；p50 满足每事实预算（见下），否则先做内核按需复制 |
| G2   | P2 完成 + M3 剩余完成 | GDD §13 M3 四项退出条件；QA_GATE 的 M3 门禁                                                                   |
| G3   | M4 完成               | 桌面与手机全流程；断网可玩；切换语言结构化结果不变；存档往返一致                                              |
| G4   | M5-008                | RELEASE_CHECKLIST 全部勾选；打 `v0.1.0-alpha.N` 标签（推送标签需人类当次批准）                                |

**G1 的 p50 口径（2026-10-22 修订，维护者授权协调者决定）**：原门槛「p50 ≤ 5.5 ms/局」是在合成人生 **167 条事实/局**
（M3-042 之前）的规模上定的。M3-042 加入 20 个事件原型后每局事实变成 **341—342 条**，绝对耗时随内容增长是合理代价，
因此 G1 改为**每事实预算**判定：

```text
p50 ≤ 5.5 ms × (当前事实数 / 167)        即基准 0.0329 ms / 事实
```

每次内容密度变化超过 10% 时必须用 `pnpm bench --lives 1000` 重测，并把新阈值与实测写进本节。

- 2026-10-22 实测：事实 341—342 条、p50 **5.9 ms**（0.0173 ms/事实，比原始预算省 **47%**）→ **达标**。
- 已做的优化（ADR-0011 按需复制 + 日期解码 + 角色按字段校验 + 决策选项按需复制 + 不变量缓存）见
  [G1-PERF-PROFILE](audits/G1-PERF-PROFILE.md)；事实契约层面的进一步优化（事实校验约占 10%）列为后续项，不再阻塞 G1。

## 6. 分工与交接流程

```text
骨架任务 ─► 执行 Agent 细化成完整任务文件 ─► Claude Code 审查（高风险另需维护者确认）
        ─► 执行 Agent 在新会话按 FLASH_AGENT_PROMPT 实施 ─► 自动化测试
        ─► Claude Code 审查 ─► 维护者验收与逐次推送批准
```

| 角色        | 负责                                                                     |
| ----------- | ------------------------------------------------------------------------ |
| 维护者      | §7 的决定、里程碑验收与试玩、高风险合并、**每一次推送**                  |
| Claude Code | 道 K；骨架与细化任务的审查；代码审查；性能、指纹与试玩数据的根因分析     |
| 执行 Agent  | 骨架细化；道 R、W、D、Q 的实施（一次一个任务、新会话）                   |
| 自动化测试  | 确定性、不变量、来源与许可、存档往返、双语一致、性能与体验度量（M5-001） |

**细化规则**：

1. 按 [INDEX「编写新任务的模板」](tasks/INDEX.md) 写全，每个验收要点落成可执行的测试或命令。
2. **不得改动骨架里「已定的约束」**：风险、依赖、允许修改的包、契约方向、数据与证据规则。认为骨架有误时写进「可能的阻塞」。
3. 只细化纯实现细节；影响公共契约、状态归属、随机流、数据语义或产品范围的选择列为「需要维护者决定」，不选。
4. 细化只提交 `docs/tasks/<ID>.md`，不改代码；审查通过后才实施。
5. **可以复用 1injp 的代码（MIT）**，但必须走 [REFERENCE_REUSE](REFERENCE_REUSE.md) §8 的登记机制（`third_party/ported-code.json` + 许可证原文 + `/*!` 许可注释 + `pnpm notices`），只移植代码、不移植数据与素材；各任务的可移植候选见该文件 §11。1in8b 未开源，不得复制任何内容。

**细化提示词**（把 `{{ID}}` 换成任务编号）：

> 你是 LifeSim 的任务规划助手。只做一件事：把骨架任务 `docs/tasks/{{ID}}.md` 细化成可以直接交给执行 Agent 实施的完整任务文件。先读 `AGENTS.md`、`docs/V0.1_PLAN.md` 第 6 节、该骨架文件，以及骨架「必读」里列出的文件；不要通读 GDD 或其他任务。遵守第 6 节的细化规则：不改「已定的约束」，不替维护者做决定，验收要点全部落成可执行测试。只修改 `docs/tasks/{{ID}}.md`，本地提交（不推送），然后输出：细化后的文件摘要、你认为需要维护者决定的问题、你发现的骨架问题。完成后停止。

## 8. 主要风险

- **内容是关键路径**：P1 的体验取决于 M3-042 通用事件与 M3-041 年度重点。事件概率是 D 级设计假设，必须按年代设资格（1950 年没有智能手机），并在界面披露「设计假设」，不得冒充统计。
- **规则道串行**：其他四条道必须充分并行；规则任务保持一个 PR 大小。
- **性能**：事件密度提高 5—6 倍、父母有自己的事件后，每局成本会明显上升；G1 时超过 5.5 ms/局就由道 K 做内核按需复制。
- **数据缺口**：朝鲜教育、CPI、卫生数据全缺；城市人口数据许可未核验。
- **敏感内容**：朝鲜、赴台湾路径、南→北迁移受 Q10 约束；M3-033 设计稿须先修订史实。
- **包体积**：约 4.2 MB 首包，M4-012 按需加载。
- **CI 只在推送 `main` 时运行**：每个任务单独验证、单独推送；M5-001 增加夜间批量回归与体验度量。
