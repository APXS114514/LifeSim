# 姓名表调研与审校记录（M3-045）

> 关联：[ADR-0010](../adr/0010-character-identity-and-fine-state.md) A2（姓名写进角色状态）、
> [DATA_POLICY](../DATA_POLICY.md)、[GDD](../GDD.md) §9（数据分级与许可）、§10（语言无关存档）。
> 本文件记录：来源与许可核实结论、每张表的取舍、覆盖缺口、内容边界，以及**待维护者抽查**的名单。
> 契约在 `packages/content-schema/src/names.ts`，表在 `packages/country-packs/names/<PACK>/`。

## 1. 结论摘要

- **实际使用的数据来源只有一个**：Wikidata 的姓名（given name）与姓氏条目，许可为 CC0 1.0（可再分发）。
  条目只提供**写法与语言标签**（原文 / 简体中文 / 英文转写）。
- **频率权重、年代分组、性别归属、城乡适用性全部是 D 级设计假设**（`grade: "D"`，`sourceIds` 同时引用 `adr:0010`）。
  没有任何一地的权重来自可核实的频率表：五个候选统计来源在本次核实中都没有拿到「可用于再分发的条款」
  （见 §2）。**因此本任务没有把任何统计排行表的数据写进仓库。**
- **朝鲜只交付姓氏（34 条）**；名字表整体缺席，缺口如实列在 §4。这是 ADR-0010「宁缺毋滥」的直接结果，
  不是遗漏。
- 表结构与选择函数见 `packages/country-packs/src/names.ts`；表指纹由 `NAME_TABLE_FINGERPRINTS` 锁定。
- **名单必须由维护者抽查后才能合并**：§6 是按地区整理的抽查清单（含全部朝鲜姓氏与俄语阴阳性成对条目）。

## 3. 表结构与取舍

- **五地 × 三张表族**：`<pack>-family`（姓）、`<pack>-given`（名），俄罗斯另有 `ru-patronymic`（父称，`kind: "given"`）。
- **年代分组**（出生年闭区间，写成条目里的 `born`）：
  | 组                                                                         | 出生年    | 说明                                         |
  | -------------------------------------------------------------------------- | --------- | -------------------------------------------- |
  | c1                                                                         | 1880—1935 | 战前/清末民初—战间期；父母与祖辈的最早出生年 |
  | c2                                                                         | 1925—1980 | 战后—工业化；与 c1 有 1925—1935 的重叠       |
  | c3                                                                         | 1970—2026 | 1970 年后至今；与 c2 有 1970—1980 的重叠     |
  | 重叠不是错误：真实名字不会在某一年突变，重叠让年代交界处有两个世代的候选。 |
- **姓不按年代分**：中日韩俄的姓本来就不随出生年变化，因此 `family` 用 `born: [[1880, 2026]]` 一条贯穿；
  这是数据事实，不是偷懒（韩日俄的姓有读音/词尾变化，见 `ru` 的阴阳性）。
- **性别**：`given` 表按 `female` / `male` 分条；`family` 表用 `sex: "any"`。
- **`ru` 的姓与父称**：一个条目服务两种性别，`genderedForms` 同时给 `feminine` 与 `masculine`（ADR-0010 A2.1）；
  基础 `forms` 用阳性（引用形式），测试断言 `forms === genderedForms.masculine`。契约层强制：
  `scheme: "ru"` 且 `sex: "any"` 必须带 `genderedForms`，其他情况必须不带。
- **城乡**：契约里有可选字段 `settlement`，**本次没有任何条目使用它**。
  原因：没有拿到可核实的城乡姓名差异来源；用刻板印象编城乡差别违反 ADR-0010 A1.5 与任务的内容边界。
  选择函数仍然按 `settlement` 过滤（测试用夹具验证机制），等有来源时再加条目。
- **权重**：同一世代内按相对常见度给 1—30 的整数权重，全部 `grade: "D"`。权重只用于排序与抽取，
  不声称是人口频率。**没有任何一处把 D 级权重写成 A/B/C 级。**
- **条目 ID**：`<拼音/罗马字>-<f|m>-c<世代>`（如 `xiuying-f-c1`）；姓用姓氏罗马字（`wang`、`sato`、`kim`）。
  ID 只增不删，删条目或改 ID 必须同时升表的 `version`（ADR-0010 A2.2）。
- **表指纹**：`NAME_TABLE_FINGERPRINTS`（`packages/country-packs/src/names.ts`）锁住每张表的 `canonicalJson` 指纹，
  与 `DATA_FINGERPRINTS` 同样属于「数据有意更新并经审查后才能改」的常量。

## 4. 覆盖与缺口表

要求：五个地区 × 1880—2020 每十年 × 两种性别，可选**名字 ≥ 15**、**姓氏 ≥ 30**。
检查点取每个十年的**起点年**（1880、1890、…、2020），并同时检查城乡两种取值（因为契约支持 `settlement`）。

| 地区          | 姓氏条目         | 名字条目                   | 每个检查点的可选名字数 | 结论     |
| ------------- | ---------------- | -------------------------- | ---------------------- | -------- |
| 中国大陆 `cn` | 35               | 96（3 世代 × 2 性别 × 16） | 16                     | 达标     |
| 日本 `jp`     | 35               | 96                         | 16                     | 达标     |
| 韩国 `kr`     | 35               | 96                         | 16                     | 达标     |
| 俄罗斯 `ru`   | 40（阴阳性成对） | 96 + 父称 20               | 16                     | 达标     |
| 朝鲜 `kp`     | 34               | **无表**                   | 0                      | **缺口** |

**缺口表（未达标的组合，精确等于验收测试里断言的那一组）**

| 地区      | 组成部分 | 年代                                | 性别             | 缺口原因                                                                             |
| --------- | -------- | ----------------------------------- | ---------------- | ------------------------------------------------------------------------------------ |
| 朝鲜 `KP` | `given`  | 1880、1890、…、2020（共 15 个十年） | `female`、`male` | 无官方统计，且无法核实个别名字的**惯用汉字写法**；按维护者 2026-10-21 的决定宁缺毋滥 |

缺口在界面上的表现由 M3-043 决定（ADR-0010 A2.1：`given: null` → 显示「姓名待接入」）。

## 5. 内容边界与排除规则

1. **不收录政治人物与名人的全名**：姓与名分别抽取，因此理论上任何组合都可能与某个真人同名；
   我们做的是「不有意收录名人组合」，并在下面把最容易撞车的组合点名列给维护者。
   - 排除的姓氏：`普京 Путин`、`斯大林 Сталин`、`列宁 Ленин`、`梅德韦杰夫 Медведев`、`叶利钦 Ельцин`、`戈尔巴乔夫 Горбачёв`；
     `毛`、`蒋`、`安倍`、`小泉`、`岸田`、`菅`、`麻生`（日本首相姓）。
   - 排除的名：`泽东`、`泽民`、`锦涛`、`近平`、`家宝`、`小平`、`恩来`、`少奇`（中文）；
     `日成`、`正日`、`正恩`（朝鲜/韩国）；`晋三`、`栄作`、`角栄`、`喜朗`（日本）。
   - 朝鲜没有名字表，因此不存在朝鲜领导人姓名组合的风险。
   - **仍需维护者决定的边界**（见 §6 的抽查清单）：俄语 `Королёв`（与 `Сергей` 组合会撞到火箭设计师）
     与 `Романов`（王朝姓），中文 `邓`。这三个都是常见的真实姓，删不删是内容决定，不是数据决定。
2. **朝鲜的命名限制**：本次**没有**取得可核实的「与领导人姓名相关的命名限制」官方文本
   （朝鲜法律与统计数据库无法访问/无公开条款）。因此采用更保守的规则：**不收录任何朝鲜名字**，
   只交付有公开惯用汉字写法的姓（金、李、朴、崔、鄭、…）。若日后接入名字，排除规则至少必须包含：
   领导人及其家属的名字（일성/정일/정은/주애 等）与宣传口号式组合。
3. **不收录带贬义或宗教敏感的名字**：中文的「招娣」类、俄语的宗教/民族专名（如 `Магомед`）、
   日语的旧式差別語联想名都不收录。性别不对应的名字不跨性别复用（如 `美咲` 只出现在 `female`）。
4. **不从姓名推断民族**（ADR-0010 A2.6）：表里不记录民族字段，也不用姓氏反推民族。
5. **不用机器编造冒充有来源的数据**：五个真实地区的写法来自 Wikidata（§2.1）；
   虚构音节姓名只放在 `packages/synthetic-world/src/names.ts`，明确标注 D 级，并由测试校验不与五地真实姓名重合。

## 7. 复核与更新流程

1. 维护者抽查 §6，逐条给出「保留 / 改写法 / 删条目」。
2. 删条目或改 ID 必须同时升该表的 `version`，并更新 `NAME_TABLE_FINGERPRINTS`（高风险常量，需审查）。
3. 新增地区或年代：先按 §2 核实许可、写进 `data/sources.json`（`redistribution: "allowed"` 必须有 `verifiedAt`），
   再补条目；`pnpm check:data` 会拦下未登记或不可再分发的来源。
4. `data/LICENSE_AUDIT.md` 的逐条审计记录由维护者补写（本任务的可改文件清单里没有它）：
   本次新增的来源只有 `wikidata:names`（CC0 1.0，见 §2.1）。
5. 维护者完成抽查前**不得合并**本任务分支。
